# data/.state/

Machine state the workspace services read and write:

- `apps.toml` - The registry of running apps and their ports.
- `oom_priority/` - The memory-pressure shed ledger and agent-pid registry.
- `screen/` - The Screen's rendered `xorg.conf`, `neko.yaml`, `pulse.pa`, its control lease (`control.json`), the display modes added this stack life (`modes.json`), why the stack last ended (`stop_reason`) and the events its watcher appends (`events/screen/events.jsonl`). (The browser's instance records are `data/.apps/browser/instances.json`.)
- `workspace_main_branch_initialized` - First-boot marker for moving the workspace onto a clean `main` branch. (A workspace first booted by an older build has `initial_chat_created` instead, which counts the same.)
- `last-restic-prune` - Backup maintenance timestamp.
- `user_timezone` - The user's IANA timezone, recorded for the client that created the workspace (through the shell's timezone route, or by a command for a client from before that route) and applied by the bootstrap at each boot.
- `profile/account.json` - The workspace profile snapshot: the workspace's account and owner, and the account-keyed settings its apps consume, materialized by a client (the Imbue Studio desktop or the web chrome) and written as that client sent it, by the shell's profile route (or by a command for a client from before that route); nothing in the workspace composes it. Read by `system/libs/workspace_profile/`.
- `update-apply/` - The update flow's state: the armed schedule (`schedule.json`), the per-workspace skipped update target (`skipped-target.json`) and update-row dismissals (`dismissals.json`) the Imbue Studio app keeps here, the run record (`run.json`), the dispatch records (`last-dispatch.json`, `dispatch-attempt.json`, `watchdog.json`), how the last start through the shell's update routes went (`last-start.json`), what a workspace that arms its own updates keeps (the update settings `settings.json`, the version its release channel was last read at `channel-version.json`, the newest version a client last named `client-ceiling.json`, which values of the armed schedule are the workspace's own `schedule-origin.json`, and the version of the checkout as last read `installed-version.json`), the apply's own records (`marker.json`, `emergency.json`, `provision-incomplete.json`, `last-good.json`, `snapshots/`), the dispatcher's log (`dispatcher.log`), and the dispatcher an Imbue Studio app from before the update routes installs (`dispatcher.pyz`). The schedule, the skip and the dismissals are written by the shell's update routes (`system/libs/workspace_update_control/`), or by that older app's own program.
- `backup_setup/` - Where the workspace was asked to back up to, and how its own setup of that stands (`state.json`, which holds no credential), written by the shell's backup routes, the boot's `apply-initial-data` step and the `backup-setup` program (`system/libs/workspace_backup_setup/`).
- `initial_data/` - How the document the workspace was handed when it was created stands (`state.json`: `NONE`, `APPLIED` with when, or `FAILED` with why, and no credential of the document), written by the boot's `apply-initial-data` step (`system/libs/workspace_initial_data/`) and answered by the shell's status route.
- `isolated-instances/` - State for temporarily booted app instances.
