Added `system/scripts/refresh_workspace_view.py`, the shared motion for rebuilding the user's view of the workspace after its interface changes -- above all after `mngr start --restart system-services`, which bounces the system interface underneath whatever the user has open.

Nothing reloaded that view before. The Minds app only intervenes when a workspace looks unreachable for a sustained stretch, and a services restart that comes back quickly never crosses that bar, so the user was left reading the page the previous build had rendered.

The helper fires two channels, because neither reaches every viewer. The in-workspace `reload_system_interface` broadcast reaches every attached browser, including anyone the workspace was shared with over a Cloudflare tunnel. The Minds app's `POST /api/v1/agents/<primary>/refresh` reaches only the desktop app, but it does not go through the workspace server at all, so it still lands while that server is coming back. Both are fire-and-forget and the script always exits 0: the change has already landed on disk, so a viewer that cannot be reached is not a reason to fail a reveal.

The broadcast is explicitly best-effort. It is a live fan-out with no replay, so it reaches whoever is connected at that instant and nobody else; after a services restart that is often nobody, because browsers reconnect on exponential backoff (up to 30s). Waiting for the interface to answer before broadcasting does not fix that -- the server answering is not the same as a browser having reconnected -- so the helper does not wait, and the Minds app channel is what actually covers the common case of a user looking at the workspace in the app.

The Minds app addresses a workspace's window by its *primary* agent id, so the helper resolves that id rather than using the caller's own: a sub-agent (an `/assist` chat, a launch-task worker) has its own id, and a refresh aimed at it names no window at all -- the gateway accepts the call, the app matches it to nothing, and it reads as a success while doing nothing. The lookup selects on the `is_primary` label alone, since the `workspace` label the Minds app once set on its agents is no longer written. A lookup that names nobody skips the app channel and says so, rather than falling back to an id that would quietly do nothing. A partial listing still counts: `mngr ls` exits non-zero when any provider is unreachable, having already printed the agents it did find, and the id is taken from that output.

The system-interface shell HTML is now served `Cache-Control: no-store`. It is assembled per request and names content-hashed assets, so its freshness alone decides which bundle a reloaded page runs -- and a page cannot drop its own HTTP cache, since `location.reload(true)` is a Firefox-only extension. This matters most for tunnel viewers, where an intermediary may cache anything not marked otherwise.
