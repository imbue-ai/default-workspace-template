Added `system/scripts/refresh_workspace_view.py`, the shared motion for rebuilding the user's view of the workspace after its interface changes -- above all after `mngr start --restart system-services`, which bounces the system interface underneath whatever the user has open.

Nothing reloaded that view before. The Minds app only intervenes when a workspace looks unreachable for a sustained stretch, and a services restart that comes back quickly never crosses that bar, so the user was left reading the page the previous build had rendered.

Because callers run it while the services agent is still restarting, the helper first waits (up to 30s) for the system interface to answer again. The broadcast below is a live fan-out with no replay, so one fired at a port that is still down is not retried -- it is lost, and with it the only channel that reaches a shared viewer. The wait lives in the helper rather than in each caller so the three call sites cannot drift on it; a healthy interface answers the first probe, so a reveal that involved no restart pays nothing.

The helper fires two independent channels, because neither reaches every viewer. The in-workspace `reload_system_interface` broadcast reaches every attached browser, including anyone the workspace was shared with over a Cloudflare tunnel. The Minds app's `POST /api/v1/agents/<primary>/refresh` reaches only the desktop app, but drops its HTTP cache and works when the page's WebSocket never came back from the restart. Both are fire-and-forget and the script always exits 0: the change has already landed on disk, so a viewer that cannot be reached is not a reason to fail a reveal.

The primary-agent lookup also gets its own timeout, separate from the two HTTP calls' 10s leash. The lookup is a `mngr ls` subprocess whose cost is an interpreter start plus provider discovery -- mostly page faults, so it tracks how much memory the host has to spare: about 1.5s idle in a workspace container, ~3s under CPU contention, and 35s measured on a host whose swap was ~90% full. On the shared 10s budget a loaded machine timed out and fell back to the calling agent's id, which is the same silently-wrong window the label fix above was meant to stop. It now reuses the 30s ceiling the post-restart health probe already applies. A host thrashing badly enough to blow through 30s will still fall back, and says so on stderr.

The helper resolves the workspace's primary agent id by the `is_primary` label alone. It previously required a `workspace` label alongside it, which the Minds app stopped setting on its agents some time ago -- so the lookup matched nothing in every real workspace and fell through to addressing the *calling* agent's own id. For the chat agent a user talks to, that is the wrong id: the app identifies the window by the primary agent's id, so the refresh named a workspace no window was showing and would have been a silent no-op even had the gateway allowed it through.

The system-interface shell HTML is now served `Cache-Control: no-store`. It is assembled per request and names content-hashed assets, so its freshness alone decides which bundle a reloaded page runs -- and a page cannot drop its own HTTP cache, since `location.reload(true)` is a Firefox-only extension. This matters most for tunnel viewers, where an intermediary may cache anything not marked otherwise.
