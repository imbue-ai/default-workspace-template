A workspace container that docker restarted on its own (an out-of-memory kill of the gVisor sandbox, a docker daemon restart, a VM reboot) came back with nothing in it but sshd until the Imbue Studio desktop app happened to notice: the services agent, supervisord, and every service, the share gateway included, stayed down (the 2026-11-08 world-builder outage). The image now installs `/usr/local/bin/mngr-container-start-hook` (`system/scripts/minds_container_start_hook.sh`), which mngr's container entrypoint runs on every start: on a restart it records a `container_restarted` event in the services agent's `events/host_lifecycle/events.jsonl` (`workspace_bare_scripts/record_container_restart.py`) and relaunches the services agent through the shared start script; on the container's first start it does nothing.

earlyoom's README and configuration record that a cloud workspace's VM now publishes `/mngr-vol/.host-meminfo` too (mngr_vps), so earlyoom sees the cgroup's real headroom under gVisor on AWS, GCP, Azure, Vultr, and OVH as it already did on Imbue Cloud slices.
