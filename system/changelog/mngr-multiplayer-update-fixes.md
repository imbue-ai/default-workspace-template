The desktop-interface contracts doc says the roster, the presence listing, and the heartbeat answer from the profile cache (a stale entry included while the workspace is shared), fetch missing or stale profiles in the background, and push `presence_updated` and `roster_updated` again when that changed a profile; that a person nothing names is called `Guest`; that the first start of a shell that keeps desktop owners gives each ownerless desktop `users.json` assigns to a visitor that visitor's key, once, marked by `visitor_desktops_adopted`; and that an arrival seeds a visitor a fresh desktop when the one `users.json` records for them is gone or no longer theirs.
