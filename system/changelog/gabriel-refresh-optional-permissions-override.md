`system/scripts/refresh_workspace_view.py` no longer requires `LATCHKEY_GATEWAY_PERMISSIONS_OVERRIDE` to reach the Minds app. It now needs only the gateway URL and password, and forwards the override header when the variable is set.

Only a desktop-hosted gateway (a Docker, Lima, or Modal workspace) injects that variable. A VPS-hosted one -- every Vultr, imbue-cloud, AWS, GCP, or Azure workspace created since the single-gateway change -- deliberately omits it, because the extension that forwards Minds API routes back to the desktop substitutes a target JWT of its own. Requiring it therefore skipped the Minds app refresh outright on every remote workspace, reporting `latchkey gateway env not set` even though the gateway and password were both present. That left those workspaces with only the `reload_system_interface` broadcast, which a services restart has usually just disconnected -- so a reveal on a remote workspace often refreshed nothing while still reporting that it had asked for a reload.

Dropping the header entirely would break the other topology: on a desktop-hosted gateway it is the per-agent authorization JWT, and a request without it resolves against a deny-all default. Sending it only when set is the same shape the rest of the template already uses for this variable (`system/libs/bootstrap`, `system/libs/github_sync`, and the `latchkey` skill's git commands).
