- `system/test_python_launch_rules.py` lets a launch of the workspace's own code, or an import-path edit, that has to stay carry a marker in the comment lines above its statement (`# own-process: <reason> -- <why>`, `# import-path: <reason> -- <why>`), with the reason taken from `running-python.md`'s list. A marked site is not counted, and a marked `sys.path` edit may add a directory outside the bare search paths. A marker with an unknown reason, no why, or no site below it fails. Both failure messages now say what the check is for and give the agent leave to restructure the code involved, instead of only saying "import it instead".

- The import-path count also covers `PYTHONPATH=` in tracked shell scripts. A path that is only written to (`.write_text`/`.write_bytes`, as `scaffold_skill.py` writes a new skill's `run.py`) is no longer counted as a launch; it used to be counted in any workspace with exactly one crystallized skill.

- `run_in_background.py --waiter`, for a command that only waits and is safe to start over: it runs in the runner's OOM band (200) instead of the caller's 900, so a lead's wait on its worker is no longer shed with the worker's test runs. If a signal ends it anyway while the caller's agent still has live processes, the runner starts it again, up to three times, and notes each restart in the output.
