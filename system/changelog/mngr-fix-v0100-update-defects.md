- `system/test_python_launch_rules.py` no longer counts launches of the workspace's own code or edits to the import path: each one fails unless a marker in the comment lines above its statement (`# own-process: <reason> -- <why>`, `# import-path: <reason> -- <why>`) names one of the reasons `running-python.md` gives. A marked `sys.path` edit may add a directory outside the bare search paths, except in code the system `python3` runs, where only an `other-tree` edit may. A marker with an unknown reason, no why, or no site below it fails. Both failure messages give the usual fix and the marker format, and give the agent leave to restructure the code involved. Every template site either became an import or carries a marker, and the test's own list of `sys.path` exceptions is gone.

- The import-path check also reads `PYTHONPATH=` in tracked shell scripts. The launch scan no longer flags a path that is only written, read or checked (as `scaffold_skill.py` writes a new skill's `run.py`, which flagged any workspace with exactly one crystallized skill), a console-script name that is an argument rather than the program an argv runs (`supervisorctl status env-converge`), a list or tuple holding another (a route table's row), or a file naming its own path.

- `forward_port` moved from `workspace_bare_scripts` into the new stdlib-only `system/libs/app_registration` library, which is on the bare search paths. `system/scripts/forward_port.py` runs it as before.

- `run_in_background.py --waiter`, for a command that only waits and is safe to start over: it runs in the runner's OOM band (200) instead of the caller's 900, so a lead's wait on its worker is no longer shed with the worker's test runs. If a signal ends it anyway while the caller's agent still has live processes, the runner starts it again, up to three times, and notes each restart in the output.
