New root ratchet `test_prevent_playwright_session_fixtures_in_root_suite_tests` (count 0): a test, or a fixture in a test file or conftest, that the root suite collects may not take pytest-playwright's `page`, `context`, `browser` or another fixture sharing its session Playwright without defining it locally. Those leave an asyncio loop running in the xdist worker, so every later browser test on it errors, as 150+ `module_browser` tests did in one workspace's update. Browser tests use the root conftest's `module_browser`. Paths the root config ignores (the chat and the shell, which run their own sessions) are out of scope.

AGENTS.md now says the `select-tests` gate is the harden worker's to run when a change goes through a flow that ends in one (`update-creation`, `heal-creation`, `crystallize-creation`); otherwise a chat runs tests only through `system/scripts/run_in_background.py`, never in the foreground, and in the foreground verifies the change as a user would. A worker runs its gate as its own guide says.

The root conftest overrides pytest-playwright's session `playwright` fixture to fail with a pointer to `module_browser`, so a root-suite test that asks for `page`, `context` or `browser` errors on its own instead of breaking every later browser test in its worker. The chat and shell suites, which run their own sessions, are unaffected.
