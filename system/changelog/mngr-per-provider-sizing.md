earlyoom now sheds at the workspace's own memory cap on a local docker workspace under runc: a new `publish_cgroup_meminfo` program publishes the container's cgroup limit and headroom into the `--host-meminfo` file earlyoom already reads (the gen-2 slice VM publishes it from outside under gVisor; under runc the container can read its own cgroup). Before, under runc earlyoom watched the whole machine's memory and the cgroup OOM killer struck first.

earlyoom's swap gate is held open (`-s 100,100`): it acts only when memory and swap are both below their thresholds, and under runc the container sees the host's swap, which on a laptop with swap kept earlyoom from ever acting. A workspace container can never swap, and the gen-2 and lima VMs have no swap, so nothing changes elsewhere.
