A bug report from a workspace running a codex agent now carries the codex app-server's own log database, rendered to text as `agent-logs/<agent>/logs_2.sqlite.log`.

Before, the only codex daemon diagnostics in a report were the tail of `app_server.log`, which records what a thread did but not which request or connection asked for it. The database has carried that attribution all along -- codex writes it independently of `RUST_LOG` -- but nothing collected it, because the collector only ever looked at `*.log` files. It is also about a hundred times smaller than the text log for the same span of time, so where the text log's 256 KiB tail could cover as little as a few seconds on a busy daemon, the rendered database covers the whole session.

Only rows written by the app-server's own request layer are read. The database is the harness's entire TRACE stream, and on a live workspace it was measured carrying bearer tokens under two targets and an API key under a third, so this is an allowlist of what to include rather than a denylist of what to drop -- an allowlist can only ever miss something useful, while a denylist misses something secret. As a second line of defence the database is scanned as its own class, separately from the harness log files: a row the allowlist did not anticipate costs the report the database alone and still delivers `app_server.log` and every agent's `stderr.log`, which are the logs most likely to explain the bug.
