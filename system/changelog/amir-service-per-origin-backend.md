Service-per-origin cutover (backend/scripts side): the `/service/<name>/` path-prefix proxy is gone; every registered service now owns a real browser origin (`http://<name>.agent-<hex>.localhost:8421/` locally, `https://<name>--<host>--<user>.<domain>/` on shares), with routing handled by the external forwarder. `forward_port.py` now validates app names as origin hostname labels (lowercase alphanumeric/underscore runs with single hyphens; the reserved `agent-` prefix and `localhost` are rejected with a clear error on both register and remove; underscores stay legal, so `system_interface` keeps its name). The browser program drops its dead `ROOT_PATH=/service/browser` env prefix. `layout.py replace-url` expectations stay service-relative (`service:<name>[/<path>]`): the frontend derives each service's absolute origin from its own host, so the wait-stable check now compares service name + path against the panel's stored origin URL in both the local and shared host shapes.
