forward_port.py now refuses a registration that would create a brand-new pickable entry without an icon, so new apps cannot fall back to the generic letter monogram; existing entries re-register untouched. Icons are registered solely via --icon-file (.svg only) -- the inline --icon markup flag is removed -- and a new --no-icon flag opts out for non-pickable machinery (system_interface, browser, terminal, previews).
A bad icon file fails a new registration but only warns on an existing app's re-registration (the stored icon is kept), so a corrupted icon cannot crash-loop a running app.
