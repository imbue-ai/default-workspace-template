forward_port.py now refuses a registration that would create a brand-new pickable entry without an icon, so new apps cannot fall back to the generic letter monogram; existing entries re-register untouched. Icons are registered solely via --icon-file (.svg only) -- the inline --icon markup flag is removed -- and a new --no-icon flag skips the requirement, keeping the generic letter monogram (it does not hide the entry -- that is --internal's job); the built-in system_interface/browser/terminal registrations and preview instances use it.
A bad icon file fails a new registration but only warns on an existing app's re-registration (the stored icon is kept), so a corrupted icon cannot crash-loop a running app.
