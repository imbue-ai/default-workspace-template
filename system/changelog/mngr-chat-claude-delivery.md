`docs/specs/chat-send-failure-system.md` covers mngr's `submission_unconfirmed`, `agent_not_found` and `not_submitted` send-failure kinds: what the chat's failure notice offers for each, why an unconfirmed send gets Send again and no Force, how the chat takes its composer copy back out once the agent's turn for it arrives, and that the chat app sends a message again once on its own after `agent_not_found` (by discovery) and after `not_submitted` (to the same place), where nothing was delivered, the notice reading both as `unknown`.

mngr is pinned to the mngr-internal commit that adds `not_submitted` and reads Claude's screen for a send it has waited out, so the Dockerfile's dependency and build steps and the create templates' build arguments pass the build the credential it fetches that pin with. Reading the screen the same way for Codex, Antigravity and pi, the agents that still get the unconfirmed notice, comes next.
