`docs/specs/chat-send-failure-system.md` covers mngr's `submission_unconfirmed`, `agent_not_found` and `not_submitted` send-failure kinds. The chat app sends a message once more on its own after each: after `submission_unconfirmed` to the same place, answering a send that then lands `"resent"`, which the page shows as a "Sent again" line under the message that a second copy folds into; after `agent_not_found` by discovery; after `not_submitted` to the same place. The spec says what the failure notice offers when that repeat fails too, why a still-unconfirmed send gets Send again and no Force, how the chat takes its composer copy back out once the agent's turn for it arrives, and which harnesses can return an unconfirmed send at all.

mngr is pinned to the mngr-internal commit that adds `not_submitted` and reads Claude's screen for a send it has waited out, so the Dockerfile's dependency and build steps and the create templates' build arguments pass the build the credential it fetches that pin with. Reading the screen the same way for pi and opencode, whose sends can still come back unconfirmed, comes next.
