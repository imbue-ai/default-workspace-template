A new guard, `agent_block_foreground_sleep.sh`, blocks any command that waits on a foreground `sleep` of 5 seconds or more, on every harness (claude, codex, pi and agy). Agents had been starting their tests in the background and then polling the output on a guessed schedule (`sleep 240; cat <output>`), holding their turn for minutes after the tests had finished, with messages to them queued until the sleep ended. The refusal tells the agent to wait on the event instead: run the command through `run_in_background.py` (or the harness's own background option) and end the turn, or check the state it is waiting for with short sleeps (`until curl -sf <url>; do sleep 1; done`). Sleeps under 5 seconds, a sleep in a list sent to the background with `&` (such as the `mcpc login` sign-in in `connect-external-service`), a sleep inside the command handed to `run_in_background.py`, and a claude call made with `run_in_background` are allowed. `AGENTS.md` gains the same rule as prose, including when a timed wait is legitimate (the user asked to check back later, a retry-after, pacing a rate-limited API) and that it then goes in a background command. The tool-call policy contract records it as P11. The pipe-into-`head`/`tail` guard now finds a stage's command the same way the sleep guard does, so it also sees past a leading `elif` or `{`.
