Bake the Grok Build CLI (`grok` 1.0.62) into the workspace image. `system/scripts/install_grok.sh` downloads xAI's per-arch `.gz` release, checks it against the SHA-256 recorded in the script (xAI publishes none), decompresses it beside `/usr/local/bin/grok`, checks that it reports `grok 1.0.62 (`, and renames it into place, so a running grok is never overwritten and a bad download never replaces a good binary. It does nothing when the installed grok already reports the pinned version, so a forced re-provision does not download it again. `setup_system.sh` runs it under its repo name or its image name and then runs a bare `grok --version`; the Dockerfile copies it in as `default-workspace-template-install-grok`, and the three offload configs list it as a checkpoint build input. The version is the one mngr's `imbue-mngr-grok` plugin is tested against.

Hold grok agents to the workspace's tool-call policies. `.grok/hooks/policy.json` runs one PreToolUse hook, `system/scripts/agent_grok_policy_guards.py`, which hands each grok tool call to the same guard scripts claude runs, in claude's order: `run_terminal_command` and `monitor` reach them as claude's `Bash`, with the background flag grok itself applies (a `monitor` always counts as backgrounded), and every other tool reaches the guards that police every tool under its grok name. A `use_tool` call is judged by the call inside it; `workflow`, and a shell call whose input grok truncated past 128 KiB, are refused. A refusal reaches the model with the guard's whole reason, an allowed shell call runs with the OOM-band and git-identity prefix, and the require-a-step nudge rides the call's `additionalContext`. grok drops anything a UserPromptSubmit hook prints, so the open-steps reminder is delivered on the first allowed tool call of each turn instead. Each guard fails open on its own and logs to `grok_policy_guards.log` in the agent's state dir. The same hooks file runs the stop nudge and code-guardian's stop gate on `Stop`, and every handler sets its `timeout`, in seconds as grok 1.0.62 reads it. `agent_hook_wiring_test.py` now holds grok's guard list and order to claude's, and checks every grok handler's timeout and variable references.

The workspace guards now know grok's tool names. The secret-file guard (P9) refuses grok's `read_file` (its `target_file`) and `search_replace` on a file under `data/.secrets/` or mcpc's store, as it already did `write` and `grep`'s `path`, and lets `list_dir` list the directory, as it lets `ls`. The require-a-step nudge (P5) no longer fires on grok's read-only tools (`read_file`, `list_dir`, `grep`, `search_tool`, `web_search`, `web_fetch`, `get_command_or_subagent_output`, `wait_commands_or_subagents`, `scheduler_list`, `ask_user_question`, and plan mode), and still fires on everything that can change something, `monitor` included. `agent_require_steps_pretool_test.py` is new, and the stdlib-only check now covers the grok dispatcher and the rewriter it loads, which hook configs run with the system `python3`.

Register the `grok` agent type with mngr. `imbue-mngr-grok` is in `system/config/mngr_plugins.toml` for the mngr and chat tools, in the root `pyproject.toml`'s dev group and `[tool.uv.sources]` at the same pinned commit as the other mngr plugins (so `set_mngr_pin.py` moves it with them), and in `uv.lock`. `.mngr/settings.toml` gains `[agent_types.grok]`: it launches through the OOM band wrapper, runs unattended (always-approve, folder trust recorded, grok's updater off, no install check), pins no model and no version (`install_grok.sh` is the only version authority), leaves `share_auth` at its default so an account's `GROK_AUTH_PATH` reaches grok, and sets `busy_send_policy = "REFUSE"` so a send never waits inside grok. `--disallowed-tools` removes grok's `todo_write`, `ask_user_question`, plan-mode and image and video tools from every session, subagents included, and `settings_overrides` sets `disable_web_search` and `features.backend_tools = false`, which together drop grok's `web_search` and `web_fetch` tools and the xAI-hosted `web_search` and `x_search`, plus grok's `[permission] deny = ["Read(**/.secrets/**)"]`, which keeps grok's file tools out of `data/.secrets/` even by a `grep` glob or a `use_tool` argument file; all of it was measured on grok 1.0.62. `system/test_workspace_grok_config.py` loads the block through mngr's own loader and holds `share_auth`, the busy-send policy, the launcher, the absent version pin, the secrets deny rule, and a patch that keeps every key mngr renders.

`docs/design/grok-transcript-schema.md` records what grok 1.0.62 writes to a session's `updates.jsonl`, as measured with a stub model: the record kinds the chat reads, where each tool keeps the text its model was given, how exit codes and signals end a call and how a `PreToolUse` refusal is recorded, that one run of text is one line except where a background subagent's end splits it, the `interrupted` stop reason of a resumed session a quit left mid-turn, `will_wake` on the end of background work, the wake prompts and the Stop-hook note, and how to capture new fixtures.

A grok chat now reads as background, not idle, while work grok will wake up for is still running. `system/scripts/grok_background_task_hooks.py`, wired in `.grok/hooks/policy.json`, writes grok's `harness-grok-*` background-task markers. At a top-level session's `Stop` it copies the session's `backgroundTasks` (shells, monitors and subagents, each of which starts a turn when it ends, as measured on grok 1.0.62), and the markers are on disk before grok writes that turn's `turn_completed`. At the `PostToolUse` of a `spawn_subagent` that leaves a subagent running in the background it marks the subagent at once, so a turn cut short with Ctrl+C, which runs no `Stop`, still leaves it marked; a shell or monitor such a turn started never wakes grok, so it is not marked. At `SessionStart` it removes the markers of a grok that is gone. A background shell, which grok lists with no description, is described by its command, so the chat's list of background tasks names it. Each marker names the grok process mngr records in the agent's state dir (read as `imbue.mngr_grok.api.read_grok_pid` reads it), a shell command is recorded without the policy hook's prefix, a grok started by a grok tool and a subagent's own session write nothing, and a session's `Stop` leaves the tasks of another top-level session of the same grok (`/new`) in place, since each lists only its own. Each handler has a 10 s timeout against the 43-67 ms it was measured to take. `grok_background_task_hooks_test.py` covers the hooks, their wiring and the pid record against `read_grok_pid`; `agent_hook_wiring_test.py` holds their events and subcommands, and the stdlib-only check covers the script.
