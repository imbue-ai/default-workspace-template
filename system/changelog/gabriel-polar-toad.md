`.mngr/settings.toml` no longer defaults `commands.create.type` to `claude`: the type an unqualified `mngr create` resolves to, and the provider account it runs on, come from the git-ignored `.mngr/settings.local.toml` the chat app writes from its account store, so a create with no account signed in fails instead of launching a claude that cannot take a turn. A new `[pre_command_scripts] create` entry runs `system/scripts/require_create_account.py`, which refuses such a create with "No provider account is signed in on this machine. Sign in from a chat tab, then try again." in place of mngr's "No agent type provided" and its config-set hint; it gates on the create's project root being the work dir of the agent running it, so the create of the workspace itself -- run on the user's machine from a clone of this template that is nobody's work dir -- is never refused, and the entry's own shell test spares a plain user shell from starting `python3` at all (an mngr agent on that machine has `MNGR_AGENT_ID`, so an agent-run create there does start one). `[work_dir_extra_paths]` shares the local file into worker worktrees by symlink, so a create run from inside one resolves the same account. `system/scripts/default_account_args.py` is removed.

`system/vendor/mngr` is refreshed to the mngr branch of the same name, whose one change over the minds-v0.5.2 vendor is that a `[commands.<name>]` table in a higher-precedence settings layer adds to the parameters lower layers set instead of replacing them, which the local file depends on.
