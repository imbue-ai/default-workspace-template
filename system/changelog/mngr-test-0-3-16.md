`run_owner_exec.sh` (the supervisord launcher for the in-container owner-exec service) now runs the idempotent, version-gated `install_owner_exec.sh` before exec'ing the binary. On every normal start this is a millisecond no-op; on a workspace that adopted the owner-exec service via update-self (where the binary was previously installed only at image build) -- or after a version-pin bump -- it installs the pinned binary instead of hot-looping supervisord on a missing or stale one. This removes the reveal-order footgun where applying a merged supervisord.conf before running the installer left the service crash-looping.
