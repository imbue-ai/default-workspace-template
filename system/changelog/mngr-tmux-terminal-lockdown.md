Scrolling the workspace terminal no longer hijacks your keyboard.

Wheel-up puts a tmux pane into copy-mode with no obvious indicator. Every plain letter is then a copy-mode *command* rather than input: `t` opens a `(jump to forward)` prompt, `f` opens `(jump forward)`, `/` starts a search, and most other letters are swallowed with no feedback at all. The terminal looks broken, and the way out (`q`) is not something you would guess. Now any printable key leaves copy-mode and is typed into the shell instead, so typing after a scroll does what typing should do. Wheel scrolling, drag-to-select with the OSC 52 clipboard, and an agent TUI's own mouse all keep working.

tmux's own features are no longer reachable from these terminals. There is no prefix key, so every `Ctrl-b` command is gone -- new window, splits, detach, the clock, the session and buffer choosers, customize-mode -- and `Ctrl-b` returns to the shell as readline's backward-char. Tabs cannot be created, switched, killed or renamed, including via the status bar's click, wheel and right-click menus. Right-clicking the terminal area no longer opens a pane menu that swallows keystrokes, and middle-click no longer pastes the tmux buffer into your shell. Keyboard copy-mode selection (`v`, `y`, `g`, `G`) goes away with it; select with the mouse.

`Ctrl-S` can no longer freeze the terminal. It sends XOFF, which stops output and makes the pane look dead. The standard unfreeze is `Ctrl-Q` -- but mngr binds `Ctrl-Q` to destroy the agent, so tmux consumes it and the pty never sees it, making the reflex recovery from a frozen pane destructive. Interactive shells now run with flow control off, so nothing freezes in the first place. mngr's `Ctrl-Q` and `Ctrl-T` are otherwise unchanged.
