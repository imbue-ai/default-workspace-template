The shared embed module (`system/libs/workspace_ui`) now handles the minds embed contract's new `minds:focus-chat` message (contract v4): the Mind app sends it when the user opens a chat's notification, and the system interface shows that chat. Its payload names the chat by `chatId` (a chat's id is its first agent's id).

The module also announces `minds:workspace-ready` (contract v5) once the page's endpoint is listening. The app holds a focus-chat ask until that arrives, instead of guessing when a freshly-mounted frame's page is live; a send into a page whose listener is not up yet is simply lost. Like the other newer contract types, both constants are probed off the vendored snapshot so a build against an older snapshot still compiles.

The notify-user script addresses the notifications route with `MNGR_AGENT_ID`, not `MINDS_CHAT_ID`: Latchkey authorizes the runtime agent, while the Mind app derives the stable conversation destination from that agent's `chat_id` label. This fixes notifications being refused when the conversation and runtime agent ids differ.
