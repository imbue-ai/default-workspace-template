Corrected phase 1 to what the template does today (a worker's report is a file the lead polls for, never a message), stamped the lead's address by id, listed the real in-workspace message senders, and pinned the messaging script's contract: registry lookup, `mngr message` exit codes including 7 for a blocked send, 503 until the chat app knows its agents, a caller-minted message id with a delivered-id ledger for at-least-once replays, and backoff only on a failed connection or 404.

Phase 1 of that plan. `system/scripts/message_chat.py` is the in-workspace way to message a chat: it takes the chat's id (never a name), posts to the chat app's send route, and exits with `mngr message`'s codes (0 delivered, 1 failed, 7 delivered but blocked on a dialog). It falls back to `mngr message` only when the chat app cannot be reached or keeps answering 404, never on a refusal, and retries a 503 while the chat app is still reading its agent list. `--system` marks an automated nudge so the chat renders it as a collapsed chip.
