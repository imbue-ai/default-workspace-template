The claude, codex, pi, and opencode agent types in `.mngr/settings.toml` now pin their `version` to the binary `system/scripts/setup_system.sh` bakes into the image and set `version_mismatch = "WARN"`. Before, only claude was pinned, and a mismatch between the installed claude and its pin failed every create, so a workspace whose claude had drifted could not even create the update chat that would repair it; `message_chat.py --create` worked around that by skipping claude's installation check on every create (through the chat app and in its `mngr create` backoff). Now a mismatch on any of the four only logs a warning and the create goes ahead, so `message_chat.py --create` no longer skips anything. `check_installation` stays off for codex, pi, and opencode, so their baked binaries are still never reinstalled, and a pinned codex no longer runs mngr's provision-time codex update check (its version moves only with the image). A test now fails when a harness pin in `settings.toml` stops matching its `setup_system.sh` default. This needs an mngr that has the `version_mismatch` field: an older mngr refuses to load `settings.toml` because of the unknown key.
