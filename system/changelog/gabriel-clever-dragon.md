Fixed `scripts/setup_system.sh` aborting when re-run on a live workspace. A plain `curl -o /usr/local/bin/<name>` truncates the target in place, which fails with `ETXTBSY` when the binary is currently running -- e.g. `ttyd` under the `terminal` service, or an active `cloudflared` tunnel, both hit by the `update-self` reveal flow re-provisioning a live host -- and under `set -e` that aborted the script before its later steps ran. A new `install_downloaded_binary` helper downloads to a temp file beside the target and `mv`s it into place (an atomic rename over a busy executable is allowed), so the provisioner is safe to re-run live; the `ttyd` and `cloudflared` installs now route through it.
