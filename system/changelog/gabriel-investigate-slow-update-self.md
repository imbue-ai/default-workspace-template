`setup_system.sh` no longer lets a version pin inherited from the environment override the tree's. Containers built before minds-v0.4.3 carry the image's `CLAUDE_CODE_VERSION` and `CODEX_VERSION` in every process, and the script's `:=` defaults yielded to them, so a by-hand re-provision after an update reinstalled the old version and passed the script's own pin check. The guard library's new `provision_drop_inherited_pins` drops every exported `*_VERSION` before the defaults are read, saying which, unless `PROVISION_PIN_OVERRIDE=1` marks the override as deliberate. `_provision_guard.sh` also documents that the update apply forces every provisioner run past the marker, not only the rollback's.

The `tk` SessionStart hook (`ensure_tk_on_path.sh`) links the vendored script into `~/.local/bin` only when nothing on PATH already answers, and replaces a link that no longer resolves. Before, a worker running in a worktree repointed the workspace's shared link at its own checkout, which goes away with the worker.
