Installing the frontend dependencies no longer downloads onnxruntime's CUDA binaries from GitHub. `onnxruntime-node` (pulled in by `@huggingface/transformers` in `libs/workspace_voice`) ships its CPU binaries in the npm package, but on Linux x64 its postinstall script also fetches the CUDA execution provider from the onnxruntime GitHub release. When that URL started answering 404 on 2026-11-17, every `npm ci` on Linux x64 failed, which broke CI's frontend step, the image's dependency install, and update-self's frontend refresh.

The new `system/.npmrc` sets `onnxruntime-node-install-cuda=skip`, the value onnxruntime-node's install script documents for skipping that download. Every install of the npm workspace runs in `system/`, so all of them read it. The Dockerfile copies it in alongside the manifests for the dependency layer, and the offload configs list it as a checkpoint build input. Nothing in the workspace uses a GPU, so it loses nothing. npm 11 prints an "Unknown project config" warning for the key but still passes it to the install script.
