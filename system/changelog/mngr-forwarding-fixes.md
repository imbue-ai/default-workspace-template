Service-per-origin cutover (scripts/config/docs side): the `/service/<name>/` path-prefix proxy is gone; every registered service now owns a real browser origin (`http://<name>.host-<32hex>.localhost:8421/` locally; future share hostnames nest the same way), with routing handled by the external forwarder.

`forward_port.py` now validates app names as origin hostname labels (lowercase alphanumeric/underscore runs joined by single hyphens; `localhost` and the reserved `host-`/`agent-` prefixes are rejected with a clear error on both register and `--remove`; underscores stay legal, so `system_interface` keeps its name), with a new subprocess-driven `forward_port_test.py` including a drift guard against the build-app scaffold's stricter name rule.

`layout.py` speaks service coordinates: `replace-url` expectations stay service-relative (`service:<name>[/<path>]`) and the wait-stable check compares service name + path against the panel's stored origin URL (the service name is the hostname's first label when a `host-<32hex>` label sits deeper in). The browser supervisord program drops its dead `ROOT_PATH=/service/browser` env. `docs/system/workspace-internals.md` describes the new per-origin scheme.
