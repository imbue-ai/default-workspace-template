- A new env.d unit, `1010-playwright-test-headless-shell.sh`, installs Playwright's headless shell into `/opt/playwright-test-browsers`, for the test suites alone, and the repo-root `conftest.py` launches it ahead of Fortress (a `--headed` run still uses Fortress, since the shell cannot show a window). An existing workspace installs it in the `env-converge upgrade` its update ends with, and CI's image runs the unit too. On a staging workspace the chat and shell browser suites passed every test on both browsers and ran about a third faster in about a third less memory on the headless shell. It stays out of Playwright's default cache, so nothing else picks it up; a failed install leaves the tests on Fortress, is recorded as a failed env.d unit, and is retried on the next converge.

- A bare Playwright `chromium.launch()` in a workspace runs Fortress again. The unit linked Fortress only into the full-Chromium path, but a headless launch (the default) looks for the separate headless-shell build, so it failed with "Executable doesn't exist". Both paths are now linked, and the links are re-checked on every converge, so a Playwright upgrade no longer leaves them pointing at the old revision. Both browser units look these paths up through `system/scripts/playwright_browser_paths.py`.
