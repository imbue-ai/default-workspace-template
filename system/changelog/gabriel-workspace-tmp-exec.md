A new workspace container's `/tmp` is now executable (`--tmpfs /tmp:exec` in the docker provider's start args), matching mngr's gen-2 start args. Docker mounts a bare `--tmpfs` with `noexec`, so nothing written under `/tmp` could run: a stub executable a test puts on `PATH` from pytest's `tmp_path` was skipped and the real tool ran instead (one update's validation killed the user's terminal sessions this way), and OpenCode's TUI could not start. `nosuid` and `nodev` stay. The mount applies when a container is created, so existing containers keep `noexec` until they are recreated.
