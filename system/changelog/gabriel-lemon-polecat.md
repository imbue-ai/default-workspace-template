Added a plan for a new `migrate-workspace` skill at `docs/system/blueprint/migrate-workspace/`. Because the workspace tree was restructured after `minds-v0.3.9` and the container base image moved from Debian 12 to Debian 13, an existing workspace cannot update itself across that boundary; the guidance instead becomes "create a fresh workspace and have its agent pull the old one in". The plan covers that pull: source identification, pre-flight backups on both sides, a freshness check on the target, an inventory derived from diffing the source against its own template base, worker-driven transfer with path rewriting and app/skill/job re-registration, faithful chat recreation via `mngr create --adopt`, latchkey and AI-integration audits, verification, and the old-workspace disposition offer. No behavior changes yet -- this commit is the plan only.
