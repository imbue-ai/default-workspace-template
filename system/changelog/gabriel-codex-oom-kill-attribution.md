`setup_system.sh` now fails the build if the installed codex npm package does not hold exactly one native binary at `node_modules/@openai/codex-<platform>/vendor/<triple>/bin/codex`. The OOM launch wrapper execs that binary directly, so a codex version bump that moves it would otherwise quietly bring back unattributed OOM kills. The `.mngr/settings.toml` comment on the codex launch command now says the wrapper execs the native binary.
