grok agents are held to the workspace's tool-call policies. `.grok/hooks/policy.json` runs one PreToolUse hook, `system/scripts/agent_grok_policy_guards.py`, which hands each grok tool call to the guard scripts claude runs, in claude's order: `run_terminal_command` and `monitor` reach them as claude's `Bash`, with the background flag grok applies (a `monitor` always, and a `block_until_ms` under a second), and every other tool reaches the guards that police every tool under its grok name. A `use_tool` call is judged by the call inside it; `workflow`, and a shell call whose input grok truncated, are refused. A refusal reaches the model with the guard's whole reason, an allowed shell call runs with the OOM-band and git-identity prefix, and the require-a-step nudge rides the call's `additionalContext`, as does the open-steps reminder on a turn's first allowed call, since grok drops what a UserPromptSubmit hook prints. Each guard fails open and logs to `grok_policy_guards.log` in the agent's state dir. On `Stop` the file runs the stop nudge and code-guardian's stop gate, the gate through `grok_turn_end_stop_hook.sh` so it runs only at a turn's end. `agent_hook_wiring_test.py` holds grok's guard list and order to claude's.

The secret-file guard refuses grok's `read_file` and `search_replace` under `data/.secrets/` or mcpc's store, lets `list_dir` list it, and refuses a `spawn_subagent` whose `cwd` is there. The step nudge skips grok's read-only tools.
