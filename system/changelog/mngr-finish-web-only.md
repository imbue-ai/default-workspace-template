Fixed the `owner-exec` supervisord spawn error and re-enabled the service. Root cause: `owner-exec` was a uv workspace member but not a dependency of the root project, so any root-closure-scoped `uv sync` (the backup restore flow runs one right before `supervisorctl restart all`) pruned it from the workspace venv, deleting its console script and turning the next `uv run owner-exec` into a supervisord spawn error. `owner-exec` is now a root dependency (like every other `uv run <name>` service), and the `[program:owner-exec]` block is wired back into `system/supervisord.conf`.
