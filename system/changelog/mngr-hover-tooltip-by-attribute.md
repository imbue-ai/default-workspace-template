A hover tooltip is now a `data-hover-tooltip` attribute on the element that offers it, read at the moment the bubble goes up by one set of listeners on the document, rather than listeners and a captured string attached per element. It could previously go stale or go missing: mithril reuses an element across redraws and runs only the current vnode's hooks, so a view that stopped spreading the attrs left the old listeners and their last text in place, and attrs arriving on an element that never ran the create hook did nothing at all. Neither is expressible now -- an element stops having a tooltip exactly when the attribute goes away, whether a view passes null, stops spreading the attrs, or is patched over by a different vnode that never had them. A bubble that is already up follows the same rule, coming down when its element loses its text or leaves the page.

`hoverTooltipAttrs` takes `null` for "no tooltip". `attachHoverTooltip` (and the `HoverTooltip` handle, with its `setText`/`dispose`) is replaced by `setHoverTooltip(element, text)` for DOM built outside mithril; there is nothing to dispose, because removing the element is enough.
