A hover tooltip is now a `data-hover-tooltip` attribute on the element that offers it, read by one set of listeners on the document, rather than listeners and a captured string attached per element. A tooltip therefore cannot go stale or go missing: the element says what it says at the moment the bubble goes up, and it stops having a tooltip exactly when the attribute goes away -- whether a view passes null, stops spreading the attrs, or is patched over by a different vnode that never had them. A bubble that is already up follows the same rule, coming down when its element loses its text or leaves the page.

`attachHoverTooltip` (and the `HoverTooltip` handle, with its `setText`/`dispose`) is replaced by `setHoverTooltip(element, text)` for DOM built outside mithril. There is nothing to dispose: removing the element is enough.
