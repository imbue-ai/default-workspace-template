The desktop interface plan, its contracts and concepts notes, and the element reference menu plan state that on a non-touch client the pages of background windows take the pointer, and that the shell raises a window when the document's focus lands in its page in a press, not when the page took it in answer to a message the shell had just sent it or by itself with no press or key behind it. The shared `requestFrameFocus` answers a function that drops its pending posts, and takes an `isStillWanted` option that drops a post whose window no longer wants the focus and an `onPosted` option called after each post.
