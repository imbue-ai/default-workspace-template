The workspace image installs `mcpc` (`@apify/mcpc`, pinned as `MCPC_VERSION` in `setup_system.sh`), the MCP client every agent, app, and scheduled job shares, and removes its native keyring binding so it keeps credentials in its file on every provider; with the binding, a lima VM would hold them in the kernel keyring, which a reboot empties. A new env.d unit, `1300-mcpc-home-link.sh`, links `~/.mcpc` (mcpc's state directory) to `data/.secrets/mcpc`, moving in anything mcpc stored before the link existed; env-converge runs it on every boot and during an update, and the first-boot seed runs it too, so mcpc's sessions, OAuth sign-ins, and stored headers sit under the secrets guard and survive with the rest of `data/` in new and updated workspaces alike, for agents, apps, and cron jobs (all of which have `HOME=/home/user`). The guard (P9) counts `~/.mcpc` as the secrets directory too, in its checker and in the claude/codex and pi prefilters, so a read of the store by that name is refused like one of `data/.secrets`. `.claude/settings.json` drops `enableAllProjectMcpServers`, since no MCP server is wired into a harness's own config any more, and `data/.secrets/README.md` and `with_secrets.py` name `mcp-servers.json` where they named `.mcp.json`.
