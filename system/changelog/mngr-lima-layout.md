Lima workspaces keep their regenerable caches on the resizable btrfs data disk: the lima create template now runs `system/scripts/lima_cache_on_data_disk.sh` before the dependency install, which makes `~/.cache` a nested btrfs subvolume on the data disk (skipped by the home tree's btrfs snapshots, as restic already skips `**/.cache`) and turns `/var/cache/user` (the `XDG_CACHE_HOME` / `npm_config_cache` target) into a symlink to it, carrying over whatever the pre-baked image held there. The VM's boot disk stays the pre-baked image's 20 GiB, now holding only the OS and toolchain; `.mngr/settings.toml` documents which disk each `--disk` refers to and points at `mngr lima resize` for changing a workspace's CPUs, memory, or data disk afterwards.
