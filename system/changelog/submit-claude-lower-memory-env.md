Set three Bun runtime variables in `host_env__extend` (`BUN_JSC_useJIT=0`, `BUN_GC_TIMER_INTERVAL=250`, `BUN_JSC_smallHeapGrowthFactor=1.25`) so every Claude Code process -- the chat's claude and the claude -p helpers it spawns -- uses 15 to 20 percent less of its own memory. Claude Code is a Bun-compiled program, so `NODE_OPTIONS` does not reach it but these do; turning the JIT off is two thirds of the saving and the GC timer and heap growth factor add the rest, at the cost of about 2 to 4 more CPU seconds per short session. Add a test that starts the installed claude with the `BUN_*` entries set, because JavaScriptCore refuses an option name it does not know and the names change between Bun releases: re-run it on every Claude Code version bump.
