Scrolling a workspace terminal no longer hijacks your keyboard, and tmux's own features are out of the way.

Wheel-up puts a tmux pane into copy-mode with no obvious indicator, and every key is then a copy-mode *command* rather than input: `t` opened a `(jump to forward)` prompt, `f` `(jump forward)`, `Ctrl-S` `(search down)`, `Ctrl-R` `(search up)`, `Alt-1` a `(repeat)` count prompt, and most other keys were swallowed with no feedback at all. The terminal looked broken, and the way out (`q`) was not something you would guess. Now any printable character leaves copy-mode and is typed into the shell, and every other key simply leaves copy-mode. Scrolling itself is unchanged -- wheel, arrows and PageUp/PageDown still move through history, and drag-to-select still copies to the system clipboard.

tmux's features are no longer reachable from these terminals. There is no prefix key, so every `Ctrl-b` command is gone -- new window, splits, detach, suspend, the clock, the session and buffer choosers, customize-mode, the command prompt -- and `Ctrl-b` reaches the shell as readline's backward-char. Tabs cannot be created, switched, killed or renamed, including through the status bar's click, wheel and right-click menus. Right-clicking the terminal no longer opens a pane menu that swallows keystrokes, and middle-click no longer pastes the tmux buffer into your shell. Keyboard copy-mode selection (`v`, `y`, `g`, `G`) goes away with it; select with the mouse.

`Ctrl-S` can no longer freeze the terminal. It sends XOFF, which stops output and makes the pane look hung. The standard unfreeze is `Ctrl-Q` -- but mngr binds `Ctrl-Q` to destroy the agent, so tmux consumed it and the pty never saw it, making the reflex recovery from a frozen pane destructive. Interactive shells now run with flow control off. mngr's `Ctrl-Q` and `Ctrl-T` are otherwise unchanged.
