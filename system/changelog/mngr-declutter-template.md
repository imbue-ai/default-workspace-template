The workspace root is decluttered down to `README.md`, `CLAUDE.md`, `pyproject.toml`, `uv.lock`, and four folders: `creations/` (user-built packages, registered via a `creations/*` uv member glob), `data/` (all workspace data, fully gitignored, backed up by restic), `docs/` (user-facing docs plus `docs/system/` for specs, blueprints, and the style guide symlink), and `system/` (libs, scripts, vendor, config, Dockerfile, supervisord.conf, changelog, repo-wide tests).

`runtime/` and `uploads/` are replaced by the `data/` scheme: visible `data/creations/<name>/`, `data/memories/`, `data/uploads/`, `data/chat-files/`, `data/chat-images/`, `data/system/` (runtime-written config: backup.toml, github_sync.toml) and hidden `data/.tickets/`, `data/.tasks/`, `data/.state/`, `data/.secrets/`. Every folder carries a README, kept tracked via laddered gitignore negations.

`parent.toml` moves to `system/config/parent.toml`; `skills-lock.json` to `.agents/skills-lock.json`; `VERSION_HISTORY.md` to `docs/`; the legacy root `changelog/` and `dev/changelog/` consolidate into `system/changelog/`. `/etc/supervisord.conf` symlinks at the workspace config so bare `supervisorctl` works from any cwd. The changelog gate maps projects from `system/libs/` and `creations/`.
