The workspace build now installs the mngr tool and its plugins in one command, and pins where that install lands.

Before, `build_workspace.sh` installed the base mngr package and then registered its plugins in a second step (`mngr plugin add`). Installing the base alone rebuilds a uv tool environment from that package and drops every extra, so between the two commands the tool had no harness plugins -- and a build that stopped in that window left one that stayed that way. Such an mngr cannot resolve `[agent_types.claude]`, so `mngr create --template chat` fails on the `chat` template's `output_style`. That create is how the desktop app starts an update, so the workspace could no longer be updated from the app, while chats created by the workspace's own interface (which runs mngr from the root venv) kept working. Now both go in a single `uv tool install`, so the plugin-less state is unreachable.

The build also runs under two different `$HOME`s -- the image build's `/root`, and `/home/user` on a live create -- and uv's tool directories follow `$HOME`. Unpinned, a create installed a second copy of every tool under `/home/user/.local` that no update refreshed and that a login shell found first, which is what the desktop app's `mngr exec` and the terminal both use. `UV_TOOL_DIR` and `UV_TOOL_BIN_DIR` are now pinned to the location the build already puts on `PATH`, and a build that finds an mngr install left under another `$HOME` removes it. That removal refuses to run unless it can see the pinned install it is protecting, and compares the two by device and inode, so a home reached as `/root/` or through a symlink is never mistaken for a shadow of itself. Both of these run where the build does -- the image build and a create's provisioning -- so they keep new workspaces out of this state. A workspace already in it is not reached: it is never re-provisioned, and the update apply runs `setup_system.sh` rather than the build. Those remain the apply's own shadow cleanup to handle, and only once their update can start at all.

`AGENTS.md`'s recovery recipe for a broken mngr tool was itself the old two-step form; it now gives the single-command one.
