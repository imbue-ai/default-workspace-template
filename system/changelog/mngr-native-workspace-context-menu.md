In the Imbue Studio desktop app on macOS, right-clicking inside the workspace now opens one native menu. It carries the macOS items a page cannot offer (spelling suggestions, Look Up, Share, Speech, Services, Inspect Element) together with the page's own rows and Copy reference / Explain... / Modify.... When the desktop app says it draws the menu (`drawsContextMenus`, which reaches each page in its `shell:handshake`), the element menu (`installElementContextMenu`) opens nothing. It keeps its rows on the page's `__studioContextMenu` bridge for the app to read and run, and waits for the page to take focus before running a picked row so clipboard rows work. In a plain browser, on Linux, or in an older desktop app the element menu is unchanged.

Holding Shift while right-clicking now leaves the right-click to the browser's own menu everywhere.

A menu row may name an SF Symbol (`symbol`), which the desktop app's native menu shows beside it on macOS. The reference rows use `doc.on.doc`, `questionmark.bubble`, and `pencil`. The element-reference-menu plan (section 11) and contracts.md's `shell:handshake` row describe the new behavior.
