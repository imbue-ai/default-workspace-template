Image builds and first-boot seeding no longer run npm's audit round trip. The frontend `npm ci` now passes `--no-audit --no-fund`, and the two `pi install` calls that bake the pi extensions (`pi-subagents`, `pi-web-access`) -- plus the first-boot fallback that re-installs them -- now set `npm_config_audit=false npm_config_fund=false`, which is how those flags reach the npm that `pi install` shells out to.

The audit cannot affect what gets installed in any of these places (every version is pinned, by a lockfile or inline), but it is a per-install request to the registry, so when that endpoint is slow it adds minutes to the build for nothing. Removing it takes those three installs back to about a second each and gives the workspace image build back roughly nine minutes of headroom against its build timeout. Global installs (`npm install -g`) are unaffected: npm never audits those.
