Bug reports carry chat transcripts again. Since the collector began composing each agent's target as `name@host.provider` from its own `mngr list` output (late August), every report from a workspace said "no chat transcripts exist in this workspace": inside a container the listing names the host after the record the outer provider stamped (for example `workspace-1`), a name the workspace's own mngr did not resolve, so each `mngr event` failed and the collector read that as no transcript. The collector now hands `mngr event` and `mngr capture` the agent id it already lists, which every mngr resolves. A new integration test drives the collector against the real vendored mngr over a host dir shaped like a workspace's, so a change in mngr's addressing fails there rather than in the field.
