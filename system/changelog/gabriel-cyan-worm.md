Bug reports carry chat transcripts again, carry them as written, and carry each conversation whole. Since the collector began composing each agent's target as `name@host.provider` from its own `mngr list` output (late August), every report from a workspace said "no chat transcripts exist in this workspace": inside a container the listing names the host after the record the outer provider stamped (for example `workspace-1`), a name the workspace's own mngr did not resolve, so each fetch failed and the collector read that as no transcript. The collector now hands `mngr capture` and the transcript read a target built from ids alone, `agent-id@host-id.local`, which every mngr resolves regardless of what the host record names the host, and which still pins each call to the local provider so it never probes the cloud providers a container cannot reach. The conversations themselves are now read with `mngr transcript` rather than `mngr event`, which keeps each record exactly as the harness wrote it: the event reader overwrites a record's `source` -- the field that in a transcript names who spoke -- with the path it read the stream from, so attached chats no longer said whether the user or the agent said each line. A chat written before mngr's ATIF cutover is the one stream `mngr transcript` refuses, and such a chat is no longer collected. Finally, the archive now holds one member per CHAT rather than per agent: handing a chat to another harness retires one agent and starts another, so a conversation held in one place was spread across several agents' streams, attached as separate members and -- worse -- ranked against each other, which dropped the beginning of the very conversation whose end was kept. Segments are read in `chat_seq` order into one member named for the segment the chat is live on. New integration tests drive the collector against the real vendored mngr over a host dir shaped like a workspace's, so a change in mngr's addressing, or in what it makes of a real transcript, fails there rather than in the field.
