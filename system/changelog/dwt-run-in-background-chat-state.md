`system/scripts/run_in_background.py` now tells mngr that the calling agent is busy while its report is pending. Before it returns, it writes a marker, `$MNGR_AGENT_STATE_DIR/background_tasks/run_in_background-<task-id>.json`, holding the detached runner's pid, and appends an activity event so `mngr observe` re-reads the agent. `mngr list` then shows the agent as busy (`WAITING (background)`) instead of plain WAITING. Once the report is delivered, given up on, or the chat is gone, the runner removes the marker from whichever agent holds it (a chat handoff moves it to the successor) and appends another activity event.

The public `--chat-id` option is gone: every task is the caller's own wait, so the marker always lands on the agent the report goes to. The option remains only as the detached copy's internal argument, and passing it without `--foreground` is a usage error.
