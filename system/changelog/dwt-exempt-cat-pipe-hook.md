Agents may now run a command that is only `cat FILE... | head` or `| tail` (e.g. `cat notes.md | head -120`). The `agent_block_pipe_tail_head.sh` guard used to block it like any other pipe into `head`/`tail`, even though the files still hold the full output. The exemption covers the whole command only: `cmd | cat | head`, `cat $(cmd) | head`, and compound commands such as `cd x && cat f | head` are still blocked.

pi agents now get every command guard from this repo, the same way claude, codex and agy do. `.pi/extensions/policy_guards.ts` feeds the same hook scripts claude runs (`agent_prevent_commit_rewrite.sh`, `agent_block_pipe_tail_head.sh`, `agent_latchkey_request_standalone.sh`, `agent_tk_standalone.sh`) the payload they read on stdin, then prefixes an allowed command with `agent_rewrite_bash_command.py --prefix-only`. Until now the pipe-into-`head`/`tail` block, the git history-rewrite block and the OOM/git-identity rewrite were copied into mngr's pi extension, so a change to any of them needed a matching mngr release, and pi's refusal messages had drifted from the scripts' wording. `agent_hook_wiring_test.py` now fails if pi's list of scripts differs from claude's.
