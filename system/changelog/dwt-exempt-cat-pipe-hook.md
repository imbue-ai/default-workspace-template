The `agent_block_pipe_tail_head.sh` guard now blocks a pipe into `head`/`tail` only when the output it truncates would have to be regenerated. A new `agent_block_pipe_tail_head_check.py` splits the command with the shared shlex parser and judges each pipeline on its own. The pipe is allowed when everything feeding it only reads files, directories or git history (`cat`, `grep`, `rg`, `sed`, `ls`, `find`, `git log/show/diff/status`, ...), or when a `tee FILE` upstream keeps the full output. So `cd x && cat f | head`, `git diff --stat | tail -40`, `grep x /tmp/saved.txt | tail -3` and `pytest 2>&1 | tee /tmp/out | tail` now run. `pytest | tail`, `uv sync | tail`, `git fetch | tail`, `curl ... | head`, `python3 -c ... | head`, and anything fed by a command or process substitution are still blocked.

The guard no longer mistakes `||` for a pipe (`grep x f || tail -4 f` was refused), and it now catches `|& tail`, which it used to miss. The wrapper checks for a pipe into `head`/`tail` with bash's built-in regex, so the 95% of commands with no such pipe never start Python.

Replayed against the 4,540 Bash commands in one production workspace's agent history, the old guard blocks 213 and the new one blocks 76. All 53 blocks of test runs, dependency syncs, fetches, network calls and commits are kept.

pi agents now get every command guard from this repo, the same way claude, codex and agy do. `.pi/extensions/policy_guards.ts` feeds the same hook scripts claude runs (`agent_prevent_commit_rewrite.sh`, `agent_block_pipe_tail_head.sh`, `agent_latchkey_request_standalone.sh`, `agent_secrets_guard.sh`, `agent_tk_standalone.sh`) the payload they read on stdin (the secrets guard on pi's file tools too), then prefixes an allowed command with `agent_rewrite_bash_command.py --prefix-only`. Until now the pipe-into-`head`/`tail` block, the git history-rewrite block and the OOM/git-identity rewrite were copied into mngr's pi extension, so a change to any of them needed a matching mngr release, and pi's refusal messages had drifted from the scripts' wording. `agent_hook_wiring_test.py` now fails if pi's list of scripts differs from claude's. A guard or rewrite that fails (a missing script, a crash) lets the command run and is logged to `pi_policy_guards.log` in the agent's state dir.
