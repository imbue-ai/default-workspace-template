setup_system.sh now reloads a running sshd after writing the `60-workspace-root-keys.conf` drop-in. The script moves root's passwd home to /home/user and compensates by pointing sshd at the absolute /root/.ssh/authorized_keys -- but a running sshd listener hands its boot-time config to every future session, so without a reload the stale relative AuthorizedKeysFile resolved against the new home (which has no authorized_keys) and every root login was silently refused from that moment on. In lima mode, where the script runs against a live sshd at first boot, this made every locally-created machine permanently unreachable to mngr ("waiting for system interface to be ready" forever) while perfectly healthy inside; docker image builds run with no sshd up, where the reload is a no-op.
