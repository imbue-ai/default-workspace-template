Added a plan (docs/system/blueprint/earlyoom-gvisor-shed-order/) for making earlyoom honor the memory-shedding priority bands under gVisor. gVisor reports every process's oom_score as 0, so earlyoom currently sheds the largest process first regardless of band. The plan forks earlyoom to compute the kernel's badness from oom_score_adj, installs it during setup instead of from apt, and hotpatches existing imbue_cloud workspaces.
