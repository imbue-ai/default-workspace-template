`system/scripts/message_chat.py --create` makes a new chat through the chat app, the way it already messages one: the chat app mints the id, binds the workspace's default account and harness, takes `--name`, `--label NAME=VALUE`, and `--skip-installation-check`, sends the message as the chat's first, and the script waits for the create to finish, printing the chat's `chat_id`, `name`, and `display_name` as one JSON line on exit 0, or the create's own failure on exit 1. A plain `mngr create --template chat` with the same name, labels, and message is the backoff, taken only when the chat app cannot be reached or has no create route; both backoffs (this one and the send's) now answer in the script's own three codes rather than handing mngr's status back, so mngr's own exit 2 can no longer be read as the script not being there. The Minds app's assist and update chats use it (falling back to their own `mngr create` on a template without it).
