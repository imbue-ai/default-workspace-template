The desktop interface contracts (`docs/system/blueprint/desktop-interface/contracts.md`, section 1) now say that Imbue Studio owns the shell's client id: it keeps one per shell hostname and writes it under `si-client-id` before the shell boots, in a frame the Studio page frames directly whose origin label is the shell's. Renaming the key, keeping the id elsewhere, replacing a stored id, changing the shell's label, or nesting the shell in another frame would make every Studio window a new client. The workspace app model's contracts and `ClientIdentity.ts` point at that rule where they define the client id.
