A new blueprint, `docs/system/blueprint/launcher-and-getting-started/plan-launcher-and-getting-started.md`, specifies the launcher's next shape and a Getting Started app, and this branch implements it: the taskbar's field opens a compact menu of rows in which one row is always highlighted (Enter runs it; with no match, Enter starts a new chat with the typed text and Ctrl+Enter sends it to an existing chat, both in the chat's pinned window); a launch path declares which param takes typed text (`text_param`); and the "Start something" intents and the template catalog leave the shell for a Getting Started app that starts chats through one new contract message, `shell:start-with-text`, and opens its own window once per workspace, on the first desktop, for the first client that connects.

Repo-level wiring for the new app: `system/supervisord.conf.d/getting-started.conf`, the `getting-started-frontend` member of the npm workspace, `forward_port.py --manifest` copying a launch path's `text_param` into the registry, and `test_app_manifests.py` checking the new built-in and the chat's text params. The desktop-interface blueprint (concepts, plan, contracts), the window-bound-resources spec, the shell and apps READMEs, and `catalog/README.md` are amended as the plan's section 12 lists: the launcher is a menu, the New Tab sections are the Getting Started app's, `GET /api/templates-catalog` is the app's, and the catalog's cache lives under `data/.state/getting-started/`.
