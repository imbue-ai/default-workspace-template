Simplify the chat data model: full-residency transcript store, payload-free wire, on-demand payloads, and watcher eviction.

The claude session watcher's two-tier locator/body-LRU cache (and its re-parse-from-disk path) is replaced by a shared full-residency store (`harnesses/transcript_store.py`) all of claude/codex/pi converge on: every parsed event stays resident, with per-event source byte ranges kept beside the store. The pi watcher now registers every session file in its sessions dir chronologically, so history from before a `/new` rotation survives backend restarts and watcher eviction.

Events on the wire are payload-free: tool inputs (the 200-char `input_preview`), tool outputs (the 2000-char clipped `output`), and thinking no longer ride events. The default render's needs are stamped at parse time instead -- labels derived from the full input, `input_chars`/`output_chars`, `error_snippet` (a failed call's first line, visible without a fetch), `tk_command`/`tk_stamp` (the step progress view's facts, whole), `permission_request`, and `has_thinking`. A new `GET /api/agents/<id>/events/<event_id>/detail` endpoint serves the whole payloads on demand, statelessly (with a fallback scan when a byte range goes stale); expanding a tool row in the chat now shows the full, untruncated input and output, and assistant turns with readable recorded reasoning (codex, pi, antigravity -- never claude, whose thinking is encrypted) get a minimal "thinking" disclosure.

Chat memory now has a lifecycle: when an agent is destroyed or its lifecycle transitions into a dead state (UI stop, `mngr stop`, an OOM shed, idle shutdown), its watcher is evicted -- resident transcript, watch thread, and inotify watches released -- and rebuilt from disk on demand when the chat is next viewed. The activity tracker folds event deltas incrementally instead of re-reading the whole transcript per event (the old O(N)-per-event rematerialisation), and per-connection SSE queues are bounded with evict-and-close on overflow (the frontend's reconnect-with-snapshot resyncs); the vestigial STORE replay buffer is deleted.

Also deflakes the antigravity tap storm test (a sub-millisecond turn-release margin decided by ISO timestamp rounding).

Also hardens the first-run provider greeting: the boot-time account load now retries with backoff until the backend answers, so a page served before the API is up no longer silently skips the provider chooser on a workspace with nothing signed in.

Also fixes a pre-existing antigravity watcher CPU spin: its per-poll read-only SQLite open/close wrote to the watched conversations directory (wal-index build and WAL reset on the `-shm`/`-wal` sidecars), so every scan woke the next one -- a ~500Hz self-sustaining loop pegging a core whenever an antigravity chat existed. The watcher now holds one read-only connection per conversation db (closed on stop/eviction), making its own reads side-effect-free while agy's real commits still wake it instantly.

Also fixes the thinking disclosure not collapsing on a second click: the memoized assistant-message wrapper skips vdom repaints on expansion toggles, so the disclosure now flips its expanded class directly on the DOM (the same pattern the tool-call rows use) with the body always mounted and CSS-revealed.

Also reworks the provider chooser's account UX: the "Signed in" section now leads the page with the provider list following under an "Add more" header (both headers absent on a first run with nothing signed in), and removing an account -- from the chooser or the model card's account flyout -- now asks in a layered confirmation dialog with Cancel and a red Remove button instead of morphing the trash button in place and appending easy-to-miss text below the list.

Also gives codex chats the same revive-on-message behavior as the other harnesses: a message sent to a stopped codex agent now starts it (through the same path the start endpoint uses) and retries while the daemon comes up, instead of failing with "not ready". And because mngr's observe stream only notices a revival on its five-minute full snapshot, the server now reflects an agent it just started as alive immediately (start endpoint and revive path both), so the chat's liveness dot and send availability unblock without the multi-minute stale-dead window.

Also stops a stopped agent's terminal from wrecking the workspace: the agent-terminal pane (terminal tabs and the chat card's terminal face) now unmounts its ttyd iframe while the agent is positively dead -- showing a minimal stopped face with a Start button -- instead of letting the embedded client reconnect-loop against the missing tmux session (~5 attach attempts per second, each stealing the page's focus, which is what made the composer un-focusable and the transcript jitter). Terminal focus is now granted by the host when the user navigates to a terminal (tab activation, the terminal-view toggle) via a message the patched ttyd client honors; the client no longer takes focus on its own.

Also fixes a codex message getting stuck at "Sending..." after reviving a stopped agent: the file watcher's suppression of user_message events (the live ledger normally owns that broadcast) is now conditional on the ledger actually having delivered the turn, so when a just-revived connection misses the commit notification the file copy heals the live stream instead of leaving the composer waiting forever.

Also fixes the other leg of the stuck-"Sending..." family: a codex send whose daemon submit failed (for example against a connection that died moments earlier, before the background reader noticed) used to be quietly recorded as Returned while the endpoint still answered success -- so the frontend kept its Sending bubble forever, waiting on a message the daemon never accepted. A failed submit now propagates: a dead transport maps to the retryable not-ready outcome (the existing revive-retry loop rebuilds the connection and re-submits the same message), and any other daemon refusal becomes a real send error whose response restores the text to the composer. The messages-lifecycle contract's Send section now states the invariant explicitly: a successful POST means the harness accepted the message.
