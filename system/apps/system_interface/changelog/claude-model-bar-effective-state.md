Claude's chat model bar now reflects the agent's *effective* model/effort/fast, not just the settings preference.

Previously the bar read Claude's `settings.json`, which only records the *preference*: when fast mode is unavailable at runtime (usage credits exhausted) Claude silently runs standard, and when it auto-falls-back to a different model, `settings.json` never records either -- so the lightning stayed lit and the wrong chip showed. The resolver now prefers a durable `{model, effort, fast}` snapshot written by a Claude Code hook (see mngr_claude), which carries the effective model and the real fast state (the transcript's service tier) per turn. The bar reconciles within a turn (after each tool call), not only when it ends. A raw API model id from the transcript (e.g. `claude-opus-4-8`) is mapped to its catalog chip. A bar-driven switch still writes the snapshot optimistically, so the chip updates at once and the hook corrects it on the next fire. Agents with no snapshot yet fall back to the old settings-based read.
