When the shell starts, a services event stream over 5 MiB is archived out of the replay. Consumers (the minds desktop forward, through `mngr event --follow`) replay the whole `events/services/events.jsonl` each time they attach, and the retired `app-watcher` service, which re-announced every app on each registry rewrite, grew some of these streams past a gigabyte: one production workspace's reached 1.16 GB, about 341,000 repeated registrations. The shell's first announcement now renames such a stream aside before writing, so it starts a fresh stream holding only the current apps, then gzips the old one on a thread of its own to `events.jsonl.<timestamp>.gz`, a name mngr does not replay, keeping the newest three archives. A stream under the threshold is untouched, and a failed archive is logged as a warning without affecting the announcements.
