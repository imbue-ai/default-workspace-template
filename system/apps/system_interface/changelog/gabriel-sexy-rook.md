- The "Parts of this workspace were updated but not yet activated" banner no longer fires when an agent adds a new app. Scaffolding an app relocks `uv.lock` so the root lockfile covers the new workspace member, and the staleness check counted that as evidence that the running system interface was serving old code. It was not: a sibling app joining the workspace changes nothing this process resolves. The banner then stayed up on every page load until the process happened to restart, which trained users to ignore the one variant that matters.

- The root `uv.lock` is now excluded from the staleness check, while the root `pyproject.toml` still counts -- the scaffold does not edit it, so it remains a reliable signal for a `[tool.uv.sources]` re-point or a `[tool.uv.workspace]` members/exclude edit. A change to what this process actually runs still raises the banner, while routine app-building does not.
