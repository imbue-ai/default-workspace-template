Service-per-origin cutover: the system interface no longer proxies services. `proxy.py` and `service_dispatcher.py` (the `/service/<name>/` forwarding layer with its service-worker bootstrap, fetch-prefixing service worker, HTML rewriting, WebSocket shim, and cookie-Path scoping) are deleted; every registered service is reached on its own browser origin via the external forwarder, derived by one rule: `serviceOrigin(name) = protocol//name.location.host/` (the shell always runs at the bare workspace origin `host-<32hex>.localhost:8421` locally; future share hostnames nest the same way).

Frontend: a new `frontend/src/origin.ts` (`deriveServiceOrigin`) owns the derivation; all panel-URL builders (`serviceRefUrl`, `getTerminalUrl`, `buildAgentTerminalUrl`, `buildSessionTerminalUrl`, `resolveReplaceUrl`, the "+" menu) emit absolute service origins. On layout restore, persisted URLs are treated as stale hints: service panel URLs are re-derived from `serviceName` (preserving any `?query`, e.g. a browser pane's `session=<name>`) and agent-terminal URLs are rebuilt from their ttyd dispatch args, so saved layouts stay portable across hosts. Service panels are cross-origin iframes now; `IframePanel`'s src-reassignment refresh is the normal path.

Backend: a new same-origin `GET`/`POST /api/browsers` passthrough forwards the browser fleet API to the registered `browser` service's local backend (503 JSON error when unregistered or unreachable), so the shell UI keeps a same-origin endpoint for listing and creating browsers (`CreateBrowserModal` drops its `browserServiceUrl` attr). Layout ref resolution (`layout_ops.py`) parses service iframes by origin -- the service name is the URL host's first label when a `host-<32hex>` label sits deeper in the hostname -- instead of the removed `/service/<name>/` path prefix.
