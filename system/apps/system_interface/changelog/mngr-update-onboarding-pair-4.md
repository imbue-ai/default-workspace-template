The tour record (`GET` and `POST /api/tour`, `tour.json`) gains `is_finished`, false by default so an older file reads whole. A record written finished sets the `tour_finished` onboarding marker, and the owner's phone layout reporting what it shows (`POST /api/clients/<client_id>/shown`) sets `phone_layout_used`; the chat's activity suggestions read both. A marker that cannot be written is logged and does not fail the request. The markers come from the new `onboarding_activity` library, which the shell's "updated, not activated" check counts among the code it runs.

The shell's page records the tour as finished when Done on its last card or Exit walkthrough is pressed, and the owner's page does so for a tour that has run and has nothing to resume.

A page can ask for a coach card with the new `shell:show-coach-card {text, chromeAnchor}`: its words and a Got it button under a control of the Imbue Studio chrome, which is ringed until the card goes. The card is shown only while the tour shows nothing, and gives way to a tour that starts. `shell:handshake` tells each page, with `showsCoachMarks`, whether the chrome draws coach marks on its own controls.
