An update rolled back to this shell (or a later one) no longer replaces the desktops with a fresh default one: the shell reads past fields this shell does not know, at every level (the document, each desktop, shortcut and its target and cell, window, and wallpaper), and every write puts them back where they were, so a field a newer shell added survives this one reading and rewriting the file. A field on a desktop, shortcut, or window this shell deletes goes with it. Request bodies and the `workspace_layout` records stay strict.

A `desktops.json` that cannot be read (bad JSON, another version, or failing validation) is renamed to `desktops.json.unreadable-<UTC timestamp>` beside it, with a warning naming why, before a new desktop is written in its place, instead of being written over.
