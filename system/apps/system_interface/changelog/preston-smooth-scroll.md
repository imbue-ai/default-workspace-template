Transcript smooth-scroll rework, phase 3 of docs/system/specs/transcript-smooth-scroll.md (phases 1 and 2 landed the engine and the ChatPanel migration).

SubagentView runs on the same scroll engine with an empty virtual layer: its whole transcript is loaded, so the custom scrollbar is 100% pixel-space and the fill planner idles. One scrolling mechanism now serves all transcript viewing.

The old machinery is deleted: the shared scroll controller (transcript-scroll.ts), the virtual-window math (virtualWindow.ts), the follow-state decision (scrollFollow.ts), the mounted-row measurer (row-measurement.ts), and the disjoint pinned-run selection mechanism (selection facts consolidated in scroll-selection.ts; row estimates and the segment type live in conversation-rows.ts). The phantom-spacer estimate geometry -- the root cause of the scroll-jump bug -- is gone entirely.

A ResizeObserver on the message list catches content resizing outside any redraw (image loads, font swaps) so positioning corrects on the next frame, closing a one-frame FOLLOW gap flash during initial fill.

Live testing fixes: row geometry now measures each row's outer pitch (distance to the next element's top) rather than its margin-less border-box height -- rows carry CSS margins, so height-based geometry drifted from the DOM by the cumulative margins and deep anchors resolved to the wrong row, producing jumps on scroll and on expand/collapse (verified fixed to sub-pixel: a new expand/collapse scenario holds the top message at 0px). And the anchor is now the row CONTAINING the viewport top (offset into the row), not the next row whose top edge is visible. Holding the spanning row means its own height corrections -- a first real measurement replacing an estimate mid-scroll, or expanding/collapsing content below the fold -- shift only rows after it, so the top message on screen cannot move. This eliminates the jumps seen while wheel-scrolling up through not-yet-measured history and when expanding blocks.

Not yet manually verified: the subagent view click-through itself (the standalone fixture carries no subagent session linkage); it shares the verified engine and render path, but should be eyeballed in a real minds workspace. Possible follow-ups noted in the spec: a "jump to latest" pill and a thumb-drag position tooltip.

Further live-testing refinements: any upward wheel intent detaches from the tail immediately (the wheel event itself dispatches the transition; the 40px bottom band only governs re-attaching on the way down, and echo matching is tightened to 0.25px so a pin echo can never swallow a gesture's first small events); the FOLLOW pin only pulls the viewport down while the agent is generating or history is still filling in, never on a quiescent relayout; and positioning is event-driven -- during pure native scrolling the engine writes nothing at all, with a single compensation write only when content changes under the viewport (fill, measurement, spacer, jump, restore).

Sticky-bottom root cause (reproduced against the live workspace during real agent generation): streaming redraws run positioning every frame, and the engine's 1px classification thresholds treated a trackpad gesture's opening sub-pixel deltas as non-input, reverting each one before the next arrived -- 296px of wheel produced 1px of motion. All pending-delta classification is now exact (0.01px epsilon), so any nonzero non-clamp movement folds as user input; quiescence additionally requires fully measured geometry so the tail pin keeps following while offscreen measurements land. The verification suite gains a streaming sub-pixel-gesture scenario with frame-rate content churn (22/22).

Jumpiness under load (reproduced with 4x CPU throttling, mirroring a busy Electron app): three more root causes fixed. Row measurement now records each row's own outer size (border-box height plus its own margins) instead of the distance to the next sibling -- the message list is a flex column where margins never collapse, so the old pitch included the NEXT row's margin-top and flip-flopped as the mount boundary swept past, oscillating geometry and bouncing the anchored viewport by 18-45px per frame. The engine's per-redraw measure-and-position pass is deferred to a microtask (still pre-paint): mithril runs lifecycle hooks parent-first, so the synchronous pass measured freshly mounted rows before their own oncreate had injected content (MarkdownContent fills innerHTML in oncreate), poisoning the height table for a frame and visibly bouncing the viewport on every row mount during scrolling. And the native-input recency clock now starts at negative infinity instead of 0, which had made the initial fill's giant spacer clamp classify as recent user input during the first 150ms after page load, silently detaching a fresh chat from FOLLOW into a mid-history anchor.

The trace also records live and offscreen height measurements, and its ring holds 8000 entries so a multi-second interaction can still be reconstructed afterwards.

Live Electron testing against a real workspace surfaced one more stranding bug: scrolling to the bottom while the agent streams left the machine detached (the deciding scroll event fires while the client's fill still lags the server total, so the at-tail check fails on data grounds -- and a clamped scrollTop emits no further scroll events to retry), so the chat never re-followed new messages. A downward scroll or scrollbar drag ending in the bottom band now records a tail intent that completes the FOLLOW attach as soon as the tail is fully loaded. The ?debug=scroll handles are also attached to each engine's own scroll element (window globals are last-engine-wins when hidden dockview panels exist).

Two more live-testing fixes. A completed message that lands as a late append (after the agent already reads idle) now still pins the viewport to its bottom: the engine tracks appends the FOLLOW pin owes a scroll for, instead of gating purely on the agent's generating state -- previously the render plan windowed rows around the theoretical bottom while the pin stayed put, painting a mostly blank viewport until the next scroll. In quiescent FOLLOW the row window now tracks the actual viewport position so the mounted rows and the painted position can never disagree.

The custom scrollbar now feels like a native one: pressing ON the thumb grabs it at the pointer's offset (no teleport), pressing the empty track still jumps to that spot, and the thumb's rendered position accounts for its 24px minimum size so it spans exactly the track and never overflows the bottom on very long transcripts.

Engine-driven position changes now glide instead of snapping: the streaming follow pin advanced in discrete multi-hundred-px lurches per streamed chunk, and on a very long transcript each scrollbar pointermove teleported the content by thousands of px -- both captured live from a real session and both reading as "jumpy". Small-to-medium writes ease toward their target over a few frames (echo-tracked, so the state machines never mistake them for input, and any genuine user input cancels the glide instantly); large jumps -- track clicks, the initial pin, fill/measurement churn -- still snap, since gliding across those reads as animation or lags the fill. The debug trace can also be enabled in the embedded desktop-client pane via localStorage (no query string there).

Expanded blocks now stay expanded: which tool-call blocks, system chips, progress-step bodies, and markdown-wrapped tool outputs the user has opened is recorded in a session-scoped in-memory store keyed by stable identity (tool_call_id, event id, section + ticket id), instead of living only in the DOM or per-component state. Previously any re-render or virtualization remount silently collapsed them -- losing the user's place and snapping the row height down by the expanded content's size, which the live-session watcher captured as recurring multi-thousand-px jumps (a 7000px continuation summary and a 900px tool result flapping open/closed).

The custom scrollbar now actually fades out after its idle window in a quiescent view: hiding previously waited for the next unrelated redraw, which an idle chat or a finished subagent view never produced, so the bar stayed visible indefinitely.

A glided scroll (the eased scrollbar-drag steps) now keeps the recorded reading anchor in lockstep with the moving viewport. The anchor used to be captured at the glide's start and never updated (the glide's own writes are invisible to the state machines by design), so on a long transcript the first measurement or spacer change after a drag could teleport the viewport back by the glide distance, and a reload restored that stale position.

Dragging the scrollbar into unloaded history and stopping could leave the screen entirely blank: the SCROLLBAR interaction state froze the virtual end spacers along with the track mapping, so when the jump's fetch re-centered the loaded window the stale spacers left the viewport over an unpadded void -- outside any spacer, so even the loading overlay had nothing to key on. The freeze now covers only the track mapping and the px-per-event estimate (what stable scrubbing actually needs); the spacer sizes always track the loaded extent, so a landed jump either shows its rows or sits over a real spacer with the loading overlay.

Physical-cap regime fixes (reproduced against a 14.7k-event workspace chat with the cap temporarily lowered below the transcript length; previously the 50k cap exceeded every real chat so this regime had never run). Four fixes in the engine: a retained selection freeze range is clamped to the current rows, so a jump or eviction shrinking the window while a selection is live can no longer produce row indexes past the rows array (previously rows[i].render() threw on undefined and every subsequent redraw died, freezing the panel on "Loading messages..."); the fill planner's focus falls back to the anchor's approximate event index when the anchor row is briefly gone (a jump's window replace), instead of reading as "focus the tail" and issuing a tail window replace that discarded the jump and churned fetch/evict cycles indefinitely; planFill holds off while a landed jump awaits its re-anchor; and a landed fill that changed nothing is not refired verbatim, so the planner can never loop an identical fruitless request.

Scrollbar correctness under the cap: the frozen mapping's physical band is trusted in pixel space only while it still matches the loaded window -- once fills or evictions move the window mid-scrub it resolves in index space (new scrollbarMap helpers mappingPhysicalExtent and resolveTrackFractionToIndex, unit-tested), positioning onto the row when the target is loaded and through the jump path (loading overlay, never stale content) when it is not. A scrollbar move into a virtual region also leaves FOLLOW immediately: a near-window target fills via fetch-before, which never dispatches JUMPED_TO_INDEX, and the still-standing follow pin used to drag the viewport straight back to the bottom so the jump silently never happened.

Edge landings: dragging the scrollbar all the way down (or up) now lands exactly on the last (or first) message. Previously a drag to the track end while that edge was unloaded jumped to the edge event but anchored its row at the viewport TOP -- a tall last row left the true bottom below the fold with no scroll event ever firing to correct it -- and never re-entered FOLLOW; a chunked backfill toward the top landed wherever the height estimates put the anchor. Scrollbar and wheel gestures targeting an extreme now record explicit edge intent, and once that edge is fully loaded the engine snaps exactly onto it (the bottom also attaches FOLLOW). Two new harness scenarios (H1/H2) drag the thumb past each track end from the opposite edge and assert the exact landing; 24/24.
