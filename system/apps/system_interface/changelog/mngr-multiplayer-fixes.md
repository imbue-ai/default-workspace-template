The roster lists everyone a domain grant let in (the mngr repo's `specs/multiplayer-refinements/spec.md`, section 4.2, and mngr-internal issue #2732): a person admitted by a workspace-level `email_domains` entry had no roster entry at all, so the tray never showed them, their desktop read as "Left behind", and no Lounge was made for them. A domain grant names nobody, so the roster now lists every presence record whose email's domain the grants still name, after the accounts the grants name and before the invited emails, marked `is_admitted_by_domain`; a revoked domain takes them off the roster again, presence files and all. The person card says "Here through <domain>" for such an entry.

A granted account that has never arrived is named rather than shown as its raw id: the Imbue Studio desktop writes what it knew of each granted account (the email and display name the grant was resolved from) to `data/.secrets/share_identities.json` beside the grants with every save, and the roster falls back to it after the profile and the arrival record, before the email's local part. The shell watches the file like the grants documents, so a save re-announces the roster.
