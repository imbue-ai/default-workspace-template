The shell runs launch paths through a new route, `POST /api/desktops/<id>/launch`, with a target of `new`, `focus`, or `window` (point a named window at the page). A GET launch path opens at its path with the presets and params as the query; a POST launch path is posted the presets, the params, and the shell's envelope (`client_id`, `desktop_id`, `window_path`) and the window opens or is navigated at the page the app answers. An app's refusal (a 4xx) is answered as a 400 naming the app and its reason; an app that cannot be asked, or answers no path, as a 502. Undeclared params are refused.

Every place that ran a launch path uses the route: the launcher's rows and free-text rows (a draft launch path is a free-text row too), shortcuts, the `?launch=` deep link, `shell:start-with-text`, the avatar dialog's "Design your own..." (which now looks for the pinned app's launch path with a `draft_param` and targets the pinned window), and the op route's `open`. A free-text row of an app with a pinned window points that window at the page whatever its scope, since the page is pure. Only GET free-text rows are bounded by the window path length.

Settling is gone: windows have no `is_settling` (a stray one in an old `desktops.json` is dropped on read), the windows route takes no `launch`, no restore is deferred, and no taskbar entry dims for a window mid-launch. A visitor's seeded desktop copies every window of the first desktop.
