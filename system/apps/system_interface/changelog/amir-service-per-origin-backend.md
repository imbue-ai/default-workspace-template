Service-per-origin cutover (backend side): the system interface no longer proxies services. `proxy.py` and `service_dispatcher.py` (the `/service/<name>/` forwarding layer with its HTML rewriting, service worker, WS shim, and cookie scoping) are deleted; services are reached on their own origins via the external forwarder. A new same-origin `GET`/`POST /api/browsers` passthrough forwards the browser fleet API to the registered `browser` service's local backend (503 JSON error when the service is unregistered or unreachable), so the shell UI keeps a same-origin endpoint for listing and creating browsers. Layout ref resolution (`layout_ops.py`) now parses service iframes by origin -- the service name is the URL host's first dot-label locally (`terminal.agent-<hex>.localhost`) or its first `--` token on shares (`terminal--<host>--<user>.<domain>`) -- instead of the removed `/service/<name>/` path prefix, and the hidden chrome registration is `system-interface` (the renamed supervisord service).
