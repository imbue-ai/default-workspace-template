Taught the service-origin derivation the workspace-keyed share-domain shape (`<share-label>.<user-hash>.<region>.<domain>`), whose coordinate leads with a bare 32-hex share label instead of a `host-<hex>` machine label. Before this, every service panel in a workspace shared under the new domain shape derived a nested hostname (`<service-label>.<shell-label>.<share-label>...`) that the relay has no tunnel claim for, so panels died with an `SSL_ERROR_UNRECOGNIZED_NAME_ALERT` TLS error in the visitor's browser.

Updated the three copies of the rule inside this app: the canonical `frontend/src/origin.ts`, the frontend-not-built placeholder page's inline mirror in `server.py`, and the service-URL recognizer in `layout_ops.py` (which also gained a first-label guard so the bare workspace-keyed origin -- whose user-hash label is also bare 32-hex -- is never misread as a service URL).
