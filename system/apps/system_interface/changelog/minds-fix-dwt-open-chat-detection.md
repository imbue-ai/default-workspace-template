Opening a chat's notification in the Mind app now brings forward a chat window that already shows that chat, switching desktops if it is on another one. Otherwise the chat is selected in the chat list window you have on screen on this desktop (else the pinned one), and only when there is neither does a new chat list window open with the chat selected. Before, a chat selected in the chat list never counted as already showing it, and the pinned chat window was sent a path it could not read, which cleared its selection.

The shell no longer decides any of this about chats. It relays a message from the Mind app to the app whose manifest registers its type, through the new `POST /api/embedder-messages`, and that app asks the op route's new generic `show` op for the window: `show` takes an app, a path, and the other paths that count as already showing it, and answers which of raised, navigated, pinned, or opened it did. A preview shell relays nothing: its registry copy names the live apps, so it refuses the relay as it refuses stopping and starting an app.
