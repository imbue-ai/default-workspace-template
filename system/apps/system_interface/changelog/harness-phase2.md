- Claude's stop button now holds mngr's per-agent message lock (the shared bounded 2s wait) around every restart-drain delegation: the queue mirror is refreshed and the queued block captured under the lock, so a message an in-flight send parks mid-stop rides the block back to the composer instead of being silently lost to the SIGKILL (message conservation, U1). When the wait expires the stop still proceeds on a fresh best-effort re-capture -- the in-flight message is stopped, never runs (the shipped pi/codex posture).

- Claude's empty-queue chord path acquires the message lock with the same bounded wait instead of blocking indefinitely, so a stop can no longer stall (up to ~90s) behind a slow send's turn-confirm; when the lock stays held past the wait it falls back to the base restart-drain (stop wins, bounded, U2).

- The default stop implementation for a harness without a native override captures under the same bounded lock, so future harnesses inherit the message-conservation guarantee.

- The restart-based flush endpoint's mirror read is deliberately left as-is: the shipped pi/codex in-flight-lock designs scoped flush out (the codex plan lists "Any change to Flush semantics" as a non-goal and the pi plan defers flush-writer locking to a residual), and a stale-empty flush read only no-ops, leaving the message visibly queued and retryable.

- Codex's stop no longer strands the lifecycle in RUNNING after a native retract: once the abort lands in the rollout (the retracted turn's boundary is observed -- confirm-before-clear, and never within the send lock), the stop clears the stranded `codex_root_active`/`active` markers through the new mngr_codex idle-marking primitive, the way claude's chord path already runs its own idle-marking after a confirmed abort (U2/U6). If the abort is never observed (version skew) or a new turn already opened, the markers are left for their own lifecycle to settle.

- A codex stop with queued messages but no open turn now hands the captured block back to the composer and clears the mirror instead of returning an empty block over a still-populated mirror: nothing is running to commit those messages, so they were stranded as ghost chips (message conservation, U1; disk-is-truth, U6). With nothing queued and no turn it remains a pure no-op.

- The codex atomic shoulder-tap (flush) control line is now written under the same per-agent message lock the retract path and mngr's sends hold, with the shared bounded 2s wait: the flush can no longer race an in-flight send (only frontend button-greying guarded that before). When a send holds the lock past the wait, nothing is written and the endpoint reports an explicit, retryable failure.

- The pi atomic shoulder-tap (flush) sentinel is likewise now written under that same per-agent message lock, via the new `flush_pi_queue_atomic` in the pi harness (mirroring the codex writer): the sentinel is ordered after any in-flight send's inbox append, so the lifecycle extension parks that just-landed message as a steer before the interrupt and the flush resubmits it instead of racing it (flush never races a concurrent send, U1). When a send holds the lock past the bounded 2s wait, nothing is written and the endpoint reports the same explicit, retryable failure.

- The claude watcher's queue-feed replay is now scoped by process epoch: `claude --resume` re-appends to the SAME session JSONL, so a full ledger replay (backend-restart priming, the truncation reset) could re-derive enqueues a killed claude process never resolved -- messages briefly reappearing as queued and then silently evaporating via the idle backstop. Enqueue records stamped before the `claude_process_started` marker's mtime (the restart boundary mngr's SessionStart hook maintains) are now excluded from the queue populator, so a replay converges to the live process's real queue (disk is truth, no ghosts, U6). Leaves are never excluded -- a dead epoch's leave nets against its excluded enqueue harmlessly -- and a missing marker keeps the old feed-everything behavior.

- Claude main-session discovery no longer sleeps inline on a miss: a session listed in history whose file is not on disk yet (an agent's startup window) previously cost a 0.5s sleep per missing session on every synchronous read, stalling /events; the miss is now simply retried on the next poll or read cycle (display converges within a poll cycle, U6).

- A claude main session whose file is found late is now inserted at its history position instead of appended: an append misordered the merged multi-session timeline and pointed the latest-session gates (queue feed, shoulder-tap baseline) at a dead session -- which also reset the live derived queue with no replay left to rebuild it. The queue tracker now resets only when the newly registered session actually becomes the latest (U6).

- Invariant U1 now has its enforcement centerpiece: a seeded, deterministic ledger-conservation storm (`harnesses/conservation_storm_test.py`) drives ~30 randomized rounds of interleaved send/park/stop/flush/restart per harness -- claude's tap + stop executors over a REAL session watcher (including backend-restart full replays as the ghost check), codex's stop/flush control-line writers, and pi's flush/retract inbox writers -- with REAL `message.lock` flock contention staged by in-flight sends, asserting after every round that enqueued = delivered + returned (zero lost, zero ghosts; the shipped slow-send hammer corner is the only sanctioned kill, and only when staged). Failures print the seed plus the full op log for replay. A companion release test (`test_message_conservation_release.py`) proves the same ledger against a REAL claude agent: a live create, mid-turn sends, the real drain-to-composer stop, the real restart-drain flush, and one epoch-settled fresh replay, with conservation read straight off the on-disk session records. (Observed while building it: a watcher created inside the few-second window between a stop's SIGKILL-relaunch and the relaunched claude's SessionStart marker touch replays the dead epoch's enqueues as queued and, being feed-time-scoped, keeps them until the manager's idle sweep -- transient in production, but worth knowing.)
