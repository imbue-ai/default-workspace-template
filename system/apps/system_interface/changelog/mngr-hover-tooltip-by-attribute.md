Hover tooltips no longer go stale when an element changes state. Before, a New Tab launcher opened before the app list loaded left the "Build a new app" tile saying "No app on this machine can start a chat" after the tile became usable, an "Open new" tile kept naming its action while greyed out for a pending create, and renaming a stopped row in the project rail left that row's "not running" explanation hanging beside the name being typed. The same could happen to the template detail dialog's actions, stopped rows in the all-apps picker and the rail, and the rail's menu rows.

A tooltip is now driven by an attribute the element carries rather than by listeners attached to it, so it cannot outlive what it was explaining. Every tooltip keeps its behaviour, and the dock's tab strip no longer has to remember to dispose a tab's tooltip when the tab closes.
