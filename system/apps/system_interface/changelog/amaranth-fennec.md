A new bundled wallpaper, an app's icon drawn as the tile it now is, and a title bar that recedes behind the window you are in.

- A new bundled wallpaper, arcs, in a warm taupe colourway, and the default every desktop wears until it picks one of its own. It is the only one the shell bundles: dawn, the wallpaper it replaces, is no longer shipped, so a desktop that never chose one moves to arcs and a desktop that had chosen dawn draws arcs too, by the rule below.

- A desktop's chosen wallpaper is painted *over* the default rather than instead of it. A reference outlives the file it names -- a bundled wallpaper the shell stops shipping, a file taken back out of `data/.apps/system_interface/wallpapers/` -- and the desktop goes on holding it, since the choice is still the choice and the file may come back. A background layer whose image does not load is simply not painted, so what shows in the meantime is the default, which is what a desktop with no wallpaper of its own already wears. Before, such a desktop fell all the way to the flat page colour and read as a broken shell rather than as a wallpaper that had gone missing.

- A desktop shortcut paints nothing behind an app's icon. Every icon is a tile now (`docs/system/app-icons.md`), with its own background and its own 32 per cent corner, so the white surface and the 8px of padding the icon box used to carry -- there to make a transparent line glyph legible -- were framing each tile in a second one and drawing it at 32px inside a 48px box. The box keeps the matching rounding and `--desk-icon-shadow`, since the shadow and the hover are what it still owes the tile.

- An app that registered no icon wears its monogram on a tile too: its initial in Courage on Strength, the most neutral pair on the board, built to the same rules. With nothing painted behind it, the outlined `currentColor` letter it used to draw would have been left floating on the wallpaper.

- A window's title bar carries the app's icon at 20px rather than 14, starts 6px from the window's edge, and leaves 6px between the icon and the title. At a control's size the tile read as mud; 20 in a 36px bar leaves it 8px of clearance and makes it a picture again. The title is bold while the window is focused, and stays at medium when it is not -- the shade of grey that said which window you were in does not read from across the screen.

- An unfocused window's bar recedes further: its icon fades to half, its title to seven tenths, and the refresh and window-menu buttons beside the title are dropped rather than greyed, so a background window reads as a name and the controls every window owes you. The icon has to be faded by hand, since a tile that paints itself cannot take the bar's colour the way a line glyph did. The buttons return with the click that focuses the window, and nothing to their right moves when they do; the taskbar entry's own menu still reaches a window you are not in.

- The desktop settings dialog reads a wallpaper the workspace no longer offers as Default, and saves it as one. Every swatch sat unlit before, which said nothing about what the desktop was actually wearing -- the backdrop had already fallen back to the default, and the picker now agrees with it. Saving what the picker shows clears the dead reference in passing, so a desktop stops carrying a name nothing answers to.

- An app that brought no tile of its own is given one, and the monogram and the older glyphs are given the same one: `#492222` on `#F5D6A0`. The monogram wore the board's most neutral pair, which turned out to be the arcs wallpaper's own colour -- a tile in it vanished into the backdrop and left the letter and the shadow standing for the app alone.

- An icon drawn before `docs/system/app-icons.md` is put on that tile rather than left as a bare stroke on the wallpaper. Such a glyph has no filled shape and takes `currentColor` from the text beside it, which is nothing to take now that no surface paints behind an icon. It is drawn into the same centred 144 box a drawn icon's mark sits in, since it was authored to fill its own frame edge to edge and at full bleed it crowded the corner and outweighed every icon next to it. An icon with a filled shape is left exactly as it is.

- A floating entry paints nothing behind the app's icon either. The surface, the border and the 8px of padding it carried framed each tile in a second one -- the pale edge around the drawing when a pinned avatar is switched to the app's icon -- so what is left is the shadow that says raised and the corner it is cast around, the tile's own 32 per cent rather than a fixed radius. The hover is the tile growing and an open menu is a ring, since a tint behind the tile can no longer be seen.

- A new desktop's shortcuts are laid out along its top edge rather than down its left. The blind grid -- the one the shell assumes when it seeds a desktop or places a shortcut an agent added with no cell of its own, since it knows no backdrop at that point -- is one row eight columns wide rather than one column down the side. Eight columns is 784px of backdrop, and a stored cell past the last column a narrower one holds is re-packed where it is drawn, so a long row never runs off the screen.

- Those shortcuts are seeded in launcher order (`launcher_rank`, lowest first, registry order breaking a tie) rather than in registry order. Registry order is the order the apps happened to finish registering in, which is boot order, so which icon sat at the top left was nobody's decision; one manifest key now says where an app sits on the backdrop and in the launcher alike.
