Move the frontend from `/service/<name>/` path-prefix URLs to service-per-origin URLs.

Every workspace service now owns a full browser origin, derived as a pure function of the shell's own host by the new `frontend/src/origin.ts` (`deriveServiceOrigin`): locally service `foo` lives at `http://foo.agent-<hex>.localhost:8421/`, and on shares at `https://foo--<host>--<user>.<domain>/` (the text before the first `--` of `location.host` is swapped). All panel-URL builders (`getServiceUrl`, `serviceRefUrl`, `getTerminalUrl`, `buildAgentTerminalUrl`, `buildSessionTerminalUrl`, `resolveReplaceUrl`) now emit absolute origins instead of same-origin `/service/` paths.

Saved layouts stay portable across hosts and shares: a persisted panel `url` is treated as a stale hint, and on restore the URL is re-derived on the current host from the panel's identity -- `serviceName` for service iframes (preserving any `?query`, e.g. a browser pane's `session=<name>`), the ttyd dispatch args for agent terminals, and `terminalSessionName` for persistent terminals (as before).

Because the browser service is now a sibling origin, the browser-fleet listing and the New-browser create POST go through the shell backend's same-origin `/api/browsers` passthrough instead of hitting the service directly (`CreateBrowserModal` no longer takes a `browserServiceUrl` attr). The "+" menu filter tracks the shell service's DNS-safe rename (`system_interface` -> `system-interface`). Service panels are now cross-origin iframes; the existing src-reassignment refresh fallback in `IframePanel` is the normal refresh path (comments updated, no behavior change).
