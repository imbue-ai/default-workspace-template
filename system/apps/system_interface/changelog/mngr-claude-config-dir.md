Claude auth and session discovery now resolve the config dir the way claude itself does: `$CLAUDE_CONFIG_DIR` when explicitly set, else the shared `~/.claude` (the workspace never sets the var anymore). The sign-in modal's key approval writes to `~/.claude.json` (beside the dir, claude's global-config location when the var is unset) instead of a path inside the dir, and the unset-var error path is gone.

Fixed: `chat`-typed agents (the initial welcome chat and every "New Agent" chat) were silently skipped by the credential-change restart, so they kept running with stale credentials after a sign-in change. `chat` is now in `CLAUDE_BINARY_AGENT_TYPES`, and a new test derives the expected set from `.mngr/settings.toml`'s claude-parented types so a future type split cannot dodge restarts again.
