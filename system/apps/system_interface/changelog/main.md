Added the codex message ledger (`harnesses/codex/ledger.py`) -- the single backend authority for a codex agent's message lifecycle over the stock `codex app-server` event stream. It keeps every accepted message in exactly one of the contract's states (Sending / Queued / Delivered / Returned), keyed by the minted `clientUserMessageId`; delivery is decided by the committed `userMessage` item (never the ack), with a `thread/read` uncertainty guard for a non-full `itemsView`. The queue is ephemeral (no durable journal, swept empty when the thread goes idle, never revived), foreign `clientId` messages never touch our chips, and the activity dot stays RUNNING until `turn/completed`. The reducer is fully unit-tested against a scripted app-server event stream via constructor injection (no live daemon).

Wired the shoulder-tap and interrupt semantics onto the ledger: `is_tap_available()` (offered iff nothing is Sending and the queue is non-empty -- codex's parked steers are already in the running turn, so the tap needs no force call) and `interrupt()` (one `turn/interrupt`, then a single authoritative settle against the committed thread that Delivers any steer that committed before the stop and Returns the rest in send order, clearing the activity dot at once). Both are unit-tested against the scripted event stream.

Restored the codex model bar on the uniform read path (no codex special-casing). The ledger now mirrors every `thread/settings/updated` to the agent's `minds_model_state.json` as the uniform `{model, effort, fast}` (`fast = serviceTier == "priority"`), so the shared model-bar read (`agent_manager._recompute_model_choice` -> `read_model_identity` -> `match_option`) reconciles the chip for codex exactly as for claude/pi. The codex model switch now applies over the stock `codex app-server` via `thread/settings/update` (model/effort/serviceTier) on a short-lived per-switch connection, replacing the old `/model` + `/fast` pane sends (which no longer work against the stock binary). An unavailable model is not an error (the daemon falls back and echoes the effective value, which the mirror reconciles), so a failed switch is a silent no-op with no popup. `CODEX_CATALOG` is unchanged; the dynamic `model/list` catalog remains deferred. Covered by scripted-client/scripted-event-stream unit tests.

Added the codex message-lifecycle conservation gate (`test_codex_message_lifecycle_conservation.py`, contract Part D): a seeded, randomized storm of Send / Queue / Shoulder-tap / Interrupt interleavings driven through the real `CodexMessageLedger` over a scripted `codex app-server` event stream (a fake daemon transport, no live daemon). After every step it asserts the full live-state law -- every accepted message in exactly one of Sending / Queued / Delivered / Returned with the four states partitioning the total (zero lost/ghost), the ledger's per-message state matching an independent expectation, send-ordered queue snapshots and interrupt returns, the A3b chip removal on delivery, delivery-is-COMMIT (an accepted-then-interrupted steer returns), the required interrupt-during-flush corner, the foreign-`clientId` rule (never creates a chip), and the ephemeral queue dying with the session.

Fixed a double-return in the codex ledger's `interrupt()`: it returned the CUMULATIVE Returned text (`reconcile_returned()`), so a second stop in the same session (or a stop after an idle sweep already Returned parked steers) would re-prepend already-returned messages to the composer. `interrupt()` now hands back only the messages Returned since the last hand-off (`_take_returned_block()`, tracked via `returned_handed_off`), so each Returned message reaches the composer exactly once; `reconcile_returned()` stays the cumulative snapshot read used by the conservation invariant. Added a ledger regression test (a second stop returns nothing) and taught the conservation storm to model the once-only hand-off.
