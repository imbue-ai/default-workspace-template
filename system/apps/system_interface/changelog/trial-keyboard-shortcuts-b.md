The keyboard shortcuts screen reads shortcuts in a context: the platform, and whether the workspace runs in the desktop app or in a browser. The chrome tells the framed `/keyboard-shortcuts` page which with `minds:embedder-capabilities` (one that can pull a window out is the desktop app); the in-workspace dialog reads the same flag off the shell.

- `meta` is the primary modifier: ⌘ on a Mac, Ctrl on Windows and Linux, so every shortcut is written once and shows as the key the platform has. A Mac's Control shortcut is hidden off a Mac, and a shortcut a browser keeps for itself (⌘W, ⌘T, ⌘N and the like) is hidden when the workspace runs in a browser. A row whose shortcuts are all hidden here reads "Off" and names them on hover with the reason for each (a Mac's Control shortcut is named with the Mac's symbols, "⌃K is set, but not available on Windows"); hidden shortcuts take part in no clash and no Reset offer, and never run.

- The reserved-shortcut warning is replaced by three that never block a save, shown under the row and while recording: a shortcut a browser would keep (shown in the desktop app), one the OS is known to keep for itself (⌘Tab, Alt+Tab, and the rest), and one the desktop app takes from the OS (Alt+F4 on Windows). Only Ctrl+Alt+Delete is refused by the recorder, with a reason.

- The shell declares workspace-wide actions (`scope = "workspace"` in its `app.toml`): Close the focused window ⌥⌘W, Next and Previous window ⌥⌘] and ⌥⌘[, Open the launcher ⌘K, Show the keyboard shortcuts ⌘/, and Show every window (no default). The catalog answers each action's `scope`. A workspace-wide action clashes with every action of every app, since it wins inside any app's page, and an app's action with the workspace-wide ones; Replace then saves across apps. The recorder refuses, for a workspace-wide action, a shortcut typing could trigger (no modifier beyond Shift and no function key).

- The workspace-wide shortcuts work wherever focus is in the workspace: in the shell's own document, inside any app's page (which hands the key to the shell before its own handlers see it), and, in Imbue Studio, inside the terminal and the Screen too, which Imbue Studio relays. Next window raises the window at the back of the desktop's stack, so pressing it again visits every window, and Previous window sends the focused one to the back; both skip minimized windows. Show the keyboard shortcuts opens them in Imbue Studio's Workspace settings, or in the shell's dialog in a browser. The shell tells Imbue Studio every shortcut in use, so the desktop app can take a key such as Alt+F4 from Windows when an app binds it.

- The launcher's secondary send defaults to ⌘Enter alone (Ctrl+Enter off a Mac), and the Windows key is no modifier.
