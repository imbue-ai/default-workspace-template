Fixed a blank screen that appeared if the workspace interface was rebuilt while the workspace server was running. The server used to decide whether to serve the interface's scripts once, at startup, based on whether a build existed at that moment -- so a build that appeared later was never served, and the browser silently refused to run the page, leaving nothing at all on screen. The scripts are now always served, and a genuinely missing one returns a plain "not found" instead of the page itself, which is what produced the blank screen. That "not found" is identical whatever was asked for: a request that tries to point outside the scripts' directory learns nothing -- not even whether the file it named exists.

Turned the page you get when the compiled interface is missing into somewhere you can actually fix it from. Previously it explained the situation and printed a command naming a directory that is not present in the situation where you would most need it, which left you reading instructions with no way to act on them: the interface is the only thing in the workspace that opens a terminal, so losing it also loses the way in. The page now carries a terminal of its own -- the workspace's terminal, the same one the interface would have opened, which was running the whole time -- and it offers, if you would rather not work out the repair yourself, a single line that creates an agent right there and opens the conversation with it already told what you are looking at. Nothing is started on your behalf: the terminal is already there, the line is one you run rather than a button that runs itself, and the agent only exists if you ask for one.

It deliberately does not offer to do the rebuild for you at the press of a button. A button has to be right about what went wrong, and the situations that leave a workspace here are mostly ones where the rebuild would fail too -- no network to fetch from, not enough memory, a dependency list that no longer resolves -- and it would fail with nowhere to tell you, since the thing that would show you the failure is what is missing. A terminal covers the repair that a button would have done and every other one besides.

The page also still brings itself back the moment the interface returns, so an interface restored by anything else -- most often an update rolling itself back, or a build you run in that terminal -- needs nothing further from you. It now does that by asking whether the interface is back rather than reloading itself every few seconds, which would have thrown away whatever you were typing into the terminal each time it fired.

Your work and your agents are untouched throughout, and the page says so: only the interface itself is gone.

The server also now records a warning naming the exact directory it looked in whenever it falls back to that page, so the cause is visible in the service logs rather than only on screen.
