Fixed two ways the workspace interface could be left showing nothing after an update, with no way for you to recover it.

If the compiled interface goes missing, the page you get now offers to rebuild it for you, shows the rebuild's progress, and reloads into the working interface once the interface is actually back. Previously it printed a command that you were not in a position to run, so a workspace in that state stayed broken until someone with a terminal fixed it. If the interface goes missing again after a rebuild -- an update running against the workspace clears it before writing the new one -- the page offers another attempt rather than reloading, which would otherwise loop it for as long as that update took. When the interface's sources are not present at all, the page says so plainly instead of offering a repair it cannot perform. A rebuild that runs too long to be waited on is reported as having run out of time rather than as a mysterious failure, and if the workspace becomes unreachable at the moment you ask for a rebuild -- which an update running against it can cause -- the page hands the offer back instead of leaving you on a dead button.

Fixed a blank screen that appeared if the interface was rebuilt while the workspace server was running. The server used to decide whether to serve the interface's scripts once, at startup, based on whether a build existed at that moment -- so a build that appeared later was never served, and the browser silently refused to run the page. The scripts are now always served, and a genuinely missing one returns a plain "not found" instead of the page itself.

A rebuild started from that page is also now treated as the most disposable thing in the workspace when memory runs short. Rebuilding is memory-hungry, and because the workspace server starts it, it would otherwise have inherited the server's own protection -- so a workspace running low on memory would have shut down your chats, your background agents, and the work they had running in order to keep the rebuild going. It is now first in line to be stopped instead, the same as a rebuild an agent runs for you. (This steers the choice rather than dictating it: how much memory a process is actually using still counts too.)

The server also now records a warning naming the exact directory it looked in whenever it falls back to the "not built" page, so the cause is visible in the service logs rather than only on screen.
