Replace named dockview layouts with **projects**: views over one machine-wide pool of objects, with a project rail, a New Tab launcher, machine-wide names and recency, and per-kind tab verbs.

The machine holds one pool of objects -- chat agents, terminal sessions, browsers, registered apps, and ad-hoc pages -- and a project is a filter over that pool plus its own dockview arrangement. Membership is an explicit, durable list of refs kept separately from the layout, and it is many-to-many: the same object can sit in any number of projects at once, nothing owns anything, and there is no "move". A member with no panel is *backgrounded* -- still running, still listed in the sidebar -- so closing a tab stops nothing and files nothing away. "Remove from project" hides an object in that one view only. **Everything is the unfiltered view, and it is the home**: not a project (no registry entry, no member list, cannot be renamed or deleted) but with its own layout, enumerating the machine, so an object filed in no project at all still appears there. An existing machine upgrades into one starter project ("Project 1") holding its whole old `desktop` arrangement, so nothing moves and nothing is lost.

Objects are singletons: **one live page per object, machine-wide**. An app open in three projects is one iframe and one document; a view decides only whether and where it is shown, never whether it is running. Switching projects, closing a tab, and re-arranging panes no longer reload or duplicate anything, because the element holding a page never leaves the DOM. Type into an app, switch to a project that does not include it, and switch back: the same page is still there, holding everything that was typed. A page is torn down only when the object behind it is destroyed. Two consequences: an app's Refresh reloads its backgrounded panes too, and a restored arrangement naming the same object twice keeps the first tab.

The old top-bar picker is gone; a **project rail** runs down the left edge, 37px at rest and expanding on hover to float over the dock. Top to bottom: the view's glyph and name (the row opens the view switcher; right-click opens project settings), shortcut rows for Chat, File Viewer, Browser, and Terminal, the project's pinned apps, a quieter "All apps" popover, a search pill that filters by label and kind with matches bolded, and the tab list itself -- open members as primary text, backgrounded ones as tertiary, each row with a hover kebab offering the verbs for its kind (Remove from project, Share app, Delete from this machine). The shortcuts go to what the view already shows and create only when it shows none; backgrounded objects count and are opened into the active pane. File Viewer renders disabled until a file-viewer app exists.

**Every project is created with a chat of its own**, opened in place of the launcher an empty view would mount, carrying the project's id in its agent's `project` label; the rail's Chat shortcut goes to that chat rather than minting another. Everything is not a project and has no chat of its own. The chat is started in the background and the project is usable either way; a failure reports its reason and points at the Chat shortcut to retry.

**Pinning an app in a project is the same fact as its membership.** The rail's app shortcuts are the project's app members in member order, and the "All apps" popover has exactly two headings -- "Pinned in <project>" and "Unpinned" -- whose toggles add or remove the member ref and nothing else. Unpinning never stops the app and touches no other project. Because it is membership, pinning is server-side and shared across browsers. Everything pins nothing (it already lists every app), so its popover is one flat list. The old per-browser `si-sidebar-app-pins` preference is not migrated; the new default shows strictly more than the old one did.

The "+" dropdown and the empty-state overlay are both replaced by a full-page **New Tab launcher** that opens as a real tab: tiles to start a chat, browser, or terminal from scratch, an "In this project" table that is the member list itself, and an "On this machine" table of everything else. Each table has a checkbox kind-filter (only kinds it actually holds, with a "Reset filters" action, and an explicit "No tabs match this filter" state) and a genuine last-active column. Opening a row from the machine table *adds* the object to the project on screen and takes it from nowhere; in Everything the launcher shows the single machine-wide table and changes no membership. The dock never goes empty -- closing the last tab opens a launcher -- clicking "+" in a pane that already has one flashes it, and a launcher folds up on its own once another panel takes focus.

Visually the dock is a set of connected tab cards: a flat grey canvas inset from the window frame, each pane a white card with a hairline border and 12px radii, and an active tab that shares its pane's outline. Every tab renders at the same width, recomputed on layout, pane, and window changes, with overflowing titles fading out rather than ellipsizing. When the strip runs out of room, the hidden tabs' dropdown lists each one as a plain row -- icon and title only, under the same friendly name the strip shows, no close or options controls -- whose whole job is to focus the tab. Workspace tooltips were restyled and retimed to match the minds shell's. Dragging a tab reads more like an edit than a selection: the drop overlay is a light neutral wash rather than dockview's opaque blue-grey slab, and dropping onto a tab draws a thin insertion line on the seam the tab would land against instead of shading half of its neighbour. Dropping into a pane still shows the filled region, since there the question really is which half of the pane you mean.

Because putting a tab away and ending the thing behind it are different acts, they wear different controls. Each tab carries a hover-revealed **minus** -- Hide tab, which puts the tab away and does nothing else -- and a menu offering Refresh (not on terminals), Share for app tabs, Rename, Hide tab again, and one confirm-gated destructive verb wearing a **power** icon: **Quit {name}**, naming whatever the tab is currently called. Quitting is machine-wide -- the object leaves every project at once -- and each confirmation spells out what it takes down, which differs by kind: a chat's agent is destroyed, a terminal's tmux session killed, a browser retired from the fleet. An app's Quit is deliberately the weaker act, and says so: confirming calls the new `POST /api/apps/<name>/deregister`, which removes the app's row from `data/.state/apps.toml` and its member ref from every project, while the program answering on the port keeps running, because nothing in the workspace supervises it -- the confirmation and the response (`is_process_stopped: false`) both say so. A launcher tab carries only the minus, and an ad-hoc page has no destructive verb at all.

**Names and recency belong to the object, machine-wide, not to any one view's layout.** Names are keyed by ref in `workspace_layout/member_titles.json` (`GET|POST /api/member-titles`), and per-object last-used timestamps -- touched, throttled, and server-stamped whenever a tab is focused or opened -- live beside them in `member_last_used.json` (`GET|POST /api/member-last-used`). Every surface therefore agrees: the dock tab, the rail, the launcher tables, the settings dialog, and Everything all call an object the same thing and rank it the same, and changes broadcast so other clients repaint live, including views they never opened. Destroying an object drops its name and recency with it, so a reused ref never inherits a dead one.

Renaming happens from any tab: double-clicking the title (or the menu's Rename) turns it into a field -- Enter or blur commits, Escape restores, an empty name is refused -- and names the object everywhere it appears. A name the user chose wins over machine renames (a tmux session rename no longer takes a chosen name off a terminal tab), and the agent-facing `layout.py rename` goes through the same path with the same validation. **Things you create are named automatically** -- "Chat 1", "Terminal 1", "Browser 1", taking the lowest free number -- so the "New chat" and "New browser" naming dialogs are gone and machine identifiers stay internal. A hand-picked name reserves its number; destroying "Chat 1" frees the slot.

**Apps can carry their own icon.** A registry row written by `forward_port.py --icon` / `--icon-file` holds the app's SVG markup, which reaches the client with the rest of the app list and is drawn wherever the app appears -- the rail's shortcut and tab rows, the "All apps" popover, the launcher tables, and the dock tab's leading glyph. The markup is treated as untrusted at the point it enters the DOM: one DOMPurify-based sanitizer stands in front of every surface, refusing anything that could execute or reach off the page, namespacing ids per icon, and falling back whole to the generic glyph on anything doubtful; an adversarial test battery holds that rule down. An app with no icon wears its monogram in the house style -- the initial in an outlined tile, currentColor strokes on a transparent ground -- since color is the projects' identity language, not the apps'.

Storage and API: projects live under `workspace_layout/projects/<id>.json` with a `projects_meta.json` registry holding metadata, member lists, and the last-active id. Member endpoints joined the project ones: `POST /api/projects/<id>/members`, `POST /api/projects/<id>/members/remove`, `POST /api/projects/members/share`, and `GET /api/projects/members`; membership changes broadcast over the existing WebSocket. Deleting a project is confirm-gated, enumerates what it will stop, and never offers to stop anything another project still holds. Agent-driven layout ops keep working: a connected client reports its active view as its active layout, so `--layout <name>` resolves through the projects registry, `Everything` included.

Dead code from the rework is swept out: the named-layout save/load/delete dialog and its API client are gone (the layout backend stays for the migration path), along with the old "create agent" naming modal -- every create path now names things automatically.

**Shutting an object down now clears it out of Everything too.** Everything keeps its own saved arrangement but has no registry entry, so the destroy sweep used to miss its content file: reopening Everything would restore the dead tab -- and a restored terminal panel would silently respawn a fresh tmux session under the old id, wearing the raw id instead of its chosen name. The sweep now strips Everything's saved layout in the same locked pass as the projects', and clients showing the destroyed panel in any still-mounted view (Everything included) drop it live on the `project_panel_removed` broadcast instead of ignoring it, so a later autosave can no longer write the dead panel back.

The same sweep now also finds panels by the destroyed object's ref, not just by one panel id: browser and app pane ids are minted per open, so the same object sits under a different id in each view's saved file (and in each client's live dock), and a destroy used to leave those other copies behind as dead tabs. Each saved panel's params resolve to the object's one stable ref, which is what the sweep and the broadcast now match on.

Deleting a project stops its terminals and fleet browsers, and what it stops now gets the full destroy sweep too: the stopped object's panel leaves Everything's saved arrangement and every surviving project's, its ref is unfiled everywhere, and the removal is broadcast so clients still showing the tab drop it live -- previously the panel lingered in Everything and would respawn a fresh tmux session under the reused name on the next restore.

A round of polish on the rail, the canvas, the launcher, and the tab menu. The rail's project switcher now shows a rename pencil on every row, not just the one you happen to be pointing at, and the row for the project you are already in carries a visible gray fill so "where am I" reads at a glance; the dropdown itself is now genuinely wider than the collapsed-or-expanded rail it hangs off, so a longer project name and its pencil both have room. Hovering the rail open no longer nudges anything vertically -- every row that both states share sits at the exact same height and y-position it always did, only the width (and the fading-in label) changes -- and picking one of the rail's own shortcuts while the pointer is still resting on it no longer snaps the rail shut out from under you; it now stays open until the pointer actually leaves, the same way the "All apps" popover already worked. The switcher header's tooltip now reads "Switch projects", and the three working shortcut rows (Chat, Browser, Terminal) carry tooltips explaining what each one opens.

The canvas's inset now runs only along the top, against the title bar -- the left, right and bottom edges sit flush with the window, where before all four carried the same 4px gap. Dragging a tab no longer leaves a half-rounded ghost behind the cursor: the floating drag preview now keeps the pane card's full corner radius on all sides instead of just the top.

The New Tab launcher's "Open new" row is capped to a readable max width instead of stretching edge to edge on a wide window, and its four tiles (Chat, File Viewer, Browser, Terminal) are shorter and now split that width evenly instead of wrapping at their own content width.

The tab menu's Share row changed icon, from an arrow-into-a-box glyph to Lucide's up-arrow-lifting-out-of-an-open-box, a closer match for what sharing actually does. The safe, membership-preserving verb -- the one that puts a tab away and leaves the object running -- says "Hide tab" rather than "Close tab" in both places it appears: the tab strip's minus button and the row in the tab's own menu. It reads as distinct from the menu's destructive verb that way, and the two surfaces agree on what the act is called.

**Every destructive verb now reads "Quit {name}"**, not just the app one -- "Shut down agent" / "Shut down terminal" / "Shut down browser" are gone, and all four kinds share the same wording and power icon. The name interpolated is whatever the tab itself is currently showing (its chosen name if it has one, the derived one otherwise), so the menu entry always matches the tab it is on. What each Quit actually does underneath is unchanged and still kind-specific -- an app's is the weaker unregister, spelled out in its own confirmation; the other three still fully destroy the object.

**Project settings is now just a name and an icon.** The dialog's "In this project" member list -- staged remove, staged rename, Save/Cancel -- is gone entirely; a project's contents are no longer something you edit from a form, since every tab already carries its own Remove-from-project and Rename controls where the object actually lives. What's left is the name field and the color/squiggle picker, plus the existing Delete-project flow. The rail's per-row settings pencil (above) opens this same, smaller dialog for whichever project's row you click.

The "All apps" popover's "Pinned in <project>" heading now clips an overlong project name with an ellipsis (the full name is still one hover away, in the tooltip) instead of wrapping across lines inside the popover's fixed-width card.

The canvas's left edge carries the same 4px inset the top already had (right and bottom stay flush): fully flush left made the rail's hover reveal awkward to land the pointer on, right at the literal window edge. And the switcher dropdown's settings pencil now shows a pointer cursor on hover, matching every other clickable control.

**Internal services (owner-exec) no longer show up as apps to open.** A registered service with a port to forward but no page of its own -- `forward_port.py --internal`, new alongside `--icon` -- is now excluded everywhere the machine's apps are offered: the New Tab launcher's machine table, the rail's All apps popover, and its shortcuts, all of which share the one `pickableApps()` choke point this filters at. It previously showed up as an ordinary app that opened blank, since the workspace had no way to tell "has a URL" apart from "has a page."

Fixed a real bug behind an intermittent test failure: switching views could leave the rail permanently stuck expanded, covering the dock, until something else happened to reset it. A completed switch rebuilds the rail's own DOM subtree, so a pointer already resting on it at that moment picks up a fresh native mouseenter with no native mouseleave ever following -- nothing left to flip the rail's own state back closed. The rail now also collapses directly whenever the active view changes, rather than depending solely on hover; if the pointer genuinely is still over it afterward, the very next real hover re-expands it as normal.

The expanded rail now stops 4px short of the window's bottom edge, matching the canvas gap above and to its left: expanded it is a floating card, and running it to the literal edge ran its rounded bottom corners and shadow off the screen. The dock underneath stays flush at the bottom, as before -- this insets only the rail.

The rail's lower divider now draws in the same hairline grey as the one above it. It was rendering as a near-black rule: a bare `border-t` takes `currentColor` under Tailwind v4, and that one call site never supplied the border token, so it inherited the rail's text color. The color moved onto the shared divider constant, so a future divider cannot repeat the omission.

A page now takes its pane's corners rather than a fixed radius. The pane card squares its top-left while the leftmost tab is the active one, but the layer a page is drawn in kept all four corners rounded, so its clipped corner let the card's white show through -- invisible under a chat, obvious under anything dark like a terminal. The live layer now copies the card's own corner shape whenever it repositions, so the two stay in step through tab switches and splits without restating the rule.

**An agent layout op with no target now goes to the view the user is looking at.** Clients report their view id (a project id, or Everything) as their active layout, but the last-active bookkeeping still wrote into the retired named-layout store -- which rejected view ids, warned on every switch, and stayed pinned at `desktop` forever -- so a defaulted op resolved to a view no client was ever on and always failed with 412, and mutating ops flatly demanded `--layout` besides. The default is now the single connected client's own view (with the projects registry's last-active id as the tie-break when zero or several distinct views are connected), the client-state write lands in the projects registry, and the 412 that remains names the view that actually missed.

**`layout.py load <view>` now actually switches the client.** The op has resolved and broadcast for as long as views have existed, but no client listened -- the CLI reported success while nothing on screen moved. The client now applies a load addressed to it (or to everyone) by running the same `switchToView` the rail's switcher uses, Everything included.

New chats can be started on the codex or pi harness from the New Tab launcher: two extra tiles, shown only where the host enables the alt harnesses, that create the same `chat` role stacked on the other harness template -- named automatically ("Codex 1", "Pi 1") like every other create, with no naming dialog. This carries the harness feature through the launcher-based create flow that replaced the old "+" menu and its modals.

**Views are arranged per device.** A desktop and a phone want different tab arrangements of the same project, so each view now keeps one arrangement per device kind -- `projects/<id>.json` for desktop, `projects/<id>.mobile.json` for mobile -- while membership stays shared: the devices differ in where tabs sit, never in what the view holds. Each client routes its own loads and autosaves by its UA-derived kind, a save neither seeds nor disturbs the other device's file, a save broadcast carries its device so only same-device clients re-apply, and the destroy sweep and project deletion strip both files. The read ops take a `device` argument (default desktop).

**The retired named-layout store is gone.** `workspace_layouts.py`, the five `/api/layouts` endpoints, and the layout_saved/layout_deleted broadcasts are deleted -- nothing called them since views took over. The one-shot upgrade migration is inlined into the projects registry and reads the old store's files directly: `layouts/desktop.json` (or the older implicit `layout.json`) becomes the starter project's desktop arrangement, and the old `mobile` layout folds into the starter project's mobile arrangement. Layout ops resolve their target purely against views (projects + Everything) now, a miss lists the known views, and the client's duplicated active-layout localStorage mirror is folded into the single active-view store.

The agent surface speaks projects: `layout.py` documents `--view` (with `--layout` kept as the same flag under its old name), mutating ops no longer require a target (the server defaults to the view the connected client is looking at), the read ops take `--device desktop|mobile`, and the module help, README, and the manage-layout / build-app / caretaker / update-self / update-app / update-system-interface / migrate-workspace skills drop the retired try-both-named-layouts loops for the projects-native wording.

A new read op, `views`, enumerates the views themselves -- every registered project plus Everything, each with its member refs, per-device content presence, and which connected clients have it in front, plus the last-active view id -- so an agent can discover the machine's projects directly instead of inferring them from an error message.

Typing got tighter where the types are real: the ``views`` op's entries are a pydantic model rather than a hand-built dict, the registry-entry builder's shape is a TypedDict (reads stay tolerant, since the registry is hand-editable), the layout script's query args are ``dict[str, str]``, and the deliberately-tolerant inputs (a saved panel's ``url``, the title and recency stores' raw reads) are ``object`` instead of ``Any`` so their isinstance narrowing stays checked.

Registry and arrangement writes are atomic now (same-directory temp file + rename), so a concurrent reader -- another process, an agent inspecting the file, a crash mid-write -- sees either the old or the new content in full, never a truncated or empty file.

**An agent's layout op now targets the agent's own view, not whatever the user is looking at.** Asking an agent in one project to build an app put the new tab in whichever project happened to be on screen when the op landed -- the op defaulted to the connected client's current view. It now defaults to the requester's own view: the view its last message came from (recorded per message, so it names where the request was made rather than where the client has since wandered), falling back to the project its `project` label names -- which mngr propagates to spawned children, so a child's work lands where its parent chat lives -- and only then to the connected client's view. The tab and its project membership therefore land in the same, correct view. When the user has moved off that view the op fails with the existing 412 naming it, rather than quietly opening somewhere else.

**Agents carry their human-readable name from mngr.** mngr now stores the name a user typed for an agent (`mngr create 'Chat 1'`) as the agent's `display_name` label, with the true agent name being its canonical form (`Chat-1`). The serialized agent state the workspace receives lifts that label into a top-level `display_name` field, alongside the existing `project` field, so the UI can show what the user typed while still addressing the agent by `name`. It is null for agents mngr holds no such label for, and `name` is unchanged in every case.

Chats are created under their human-readable name. The launcher's tiles, the rail's Chat shortcut, and a new project's own chat all pass "Chat 2" / "Codex 1" to `mngr create` instead of minting a machine coolname, so mngr names the agent its canonical form (`Chat-2`) and keeps the typed name as the agent's `display_name` label. `mngr list` inside a workspace now reads like the tabs do rather than showing word-salad names, and the title the workspace files is the same string the create used, so the two cannot drift.

The human-named creates do not depend on the workspace's vendored mngr being new enough to canonicalize names itself: both halves are sent explicitly -- the canonical form (`Chat-2`) as the agent name and the typed form as the `display_name` label -- which every mngr version accepts, and which is exactly the pair a newer mngr derives on its own. Sending the spaced form and letting mngr split it would have failed first-boot chat creation outright on any workspace whose vendored mngr predates free-form names.

**Renaming a chat renames the agent.** Renaming a chat tab (or a chat row in the sidebar, or an agent's own `layout.py rename`) wrote only the workspace's title store, so `mngr list` kept showing the old name. A rename of a `chat:` member now runs `mngr rename` on the agent behind it first, giving it the canonical form of the typed name plus that name as its `display_name` label -- the same pair a create establishes, and one every vendored mngr accepts. mngr goes first and the title store is written only when it succeeded, so a refused rename leaves both names as they were and surfaces the error rather than letting the two disagree silently; the renamed agent also answers to its new name immediately instead of after the next observe relist. Terminals, browsers, apps and URLs are not agents and are stored exactly as before, and clearing a chat's chosen name is a store-only change (mngr has no empty name to be given, so the chat keeps the name it has).

The e2e fixture ships a stub `mngr` on PATH beside the stub `claude` it already had: renaming a chat renames its mngr agent before the workspace records the new name, and the fixture's agents are injected fakes with no real mngr behind them, so without it a rename fails and the tab keeps its old name. The failure policy itself is unit-tested rather than end-to-end.
