Replace named dockview layouts with **projects**, and make a project a *view* over the machine rather than a container that owns things.

A machine holds one pool of objects: chat agents, terminal sessions, fleet browsers, registered apps, and ad-hoc pages. A project is a filter over that pool plus its own dockview arrangement. Membership is explicit and durable — a list of refs (`chat:<agent-id>`, `terminal:<name>`, `service:<name>`, `service:browser?session=<name>`, `url:<hash>`) kept separately from the layout — and it is **many-to-many**: the same object can sit in any number of projects at once, so the one app a machine runs can appear in every project that wants it. Nothing owns anything, and there is no "move".

Because membership no longer lives in the layout, **closing a tab stops nothing and files nothing away**. A member with no panel is *backgrounded*: the tmux session keeps running, the fleet browser stays up, the app stays supervised, and the object stays listed in the project's sidebar so it can be reopened. **"Remove from project" hides an object in that one view only** — it keeps running, and it stays in every other project showing it. Only destroying an object takes it off the machine, and that drops it from every project at once.

**Everything is the unfiltered view, and it is the home.** It is not a project: it has no registry entry, no member list, and cannot be renamed or deleted. It does keep its own layout like any other view. Its tab list enumerates the *machine* rather than unioning the projects' member lists, so an object filed in no project at all still appears there — and selecting a row opens it in Everything's own dock rather than jumping somewhere else.

The old top-bar picker is gone. Everything now hangs off a **project rail** down the left edge: 37px at rest, expanding on hover to a 240px panel that floats over the dock. Moving the pointer off the rail folds it back up and takes any open menu with it, rather than leaving one hanging over the dock with nothing behind it; the "All apps" popover is the one exception, since it is a browse-and-pick list that extends past the rail's own box and has to survive the pointer working down it. A click into a pane is a click into a cross-origin iframe and raises no event in the shell at all, so the window losing focus closes the menus too. Top to bottom it holds the project's glyph and name (the whole row opens the view switcher; right-clicking it opens project settings), shortcut rows for Chat, File Viewer, Browser, Terminal plus the project's own apps, a quieter "All apps" popover with per-project pin/unpin, a search pill that filters on label and kind with the matched substrings bolded, and the tab list itself. Open members render as primary text and backgrounded ones as tertiary; there is deliberately no persistent selected-row highlight, since the dock shows several panes at once. Each row's hover kebab offers the verbs that make sense for its kind — sharing for apps, "Remove from project" for anything in a project, and a destructive "Delete from this machine" for chats, terminals and browsers. File Viewer renders disabled with a tooltip, because no file-viewer app backs it yet.

The "+" dropdown and the empty-state overlay are both replaced by a full-page **New Tab launcher** that opens as a real tab. It offers tiles to start a chat, browser or terminal from scratch, a table of what this project already shows, and a table of everything else on the machine; each table has a kind filter and a recency column. Opening something from the machine-wide table *adds* it to the project you are looking at and takes it from nowhere. The dock is never empty — closing the last tab opens a launcher — and clicking "+" in a pane that already has one flashes it instead of stacking a second.

Visually the dock is now a set of connected tab cards: a flat grey canvas inset from the window frame, each pane a white card with a hairline border and 12px radii, a transparent tab strip, and an active tab that shares its pane's outline so the two read as one shape. Every tab in every pane renders at the same width, recomputed on layout, pane and window changes, with overflowing titles fading out rather than ellipsizing. Tabs carry a kind icon plus two buttons revealed on hover, and because putting a tab away and ending the thing behind it are different acts they wear different glyphs. The inline button is a **minus**: it closes the tab and nothing else — the agent keeps working, the tmux session keeps running, the browser stays up, the app stays supervised, and the object stays filed in every project that listed it, so the sidebar reopens it exactly where it was. The options menu offers Refresh, Share for app tabs, the same minus for Close tab, and then, below a divider, one destructive verb per kind wearing an **x** — Shut down agent, Shut down terminal, Shut down browser. Those are machine-wide and confirm-gated: they end the object itself, so it leaves every project at once rather than the one on screen. An app's entry is deliberately the weaker Unregister app, described below — it takes the app out of the registry and out of every project, and it does not stop the program answering on the port, because nothing in the workspace supervises that program. A launcher tab is a question about a pane rather than an object, so it carries only the minus. Workspace tooltips were restyled and retimed to match the minds shell's.

An existing machine upgrades cleanly: its whole `desktop` arrangement becomes one starter project ("Project 1") with each of its panels filed as a member, so nothing moves and nothing is lost. Projects are stored per-view under `workspace_layout/projects/<id>.json` with a `projects_meta.json` registry holding metadata, member lists and the last-active id. Deleting a project is confirm-gated and deletes the view, not what it showed.

The API gained member endpoints alongside the existing project ones: `POST /api/projects/<id>/members`, `POST /api/projects/<id>/members/remove`, `POST /api/projects/members/share`, and `GET /api/projects/members`. Membership changes broadcast over the existing WebSocket so every client's sidebar catches up, whether or not it has the affected project mounted.

Agent-driven layout ops (`system/scripts/layout.py`) keep working: a connected client reports its active *view* as its active layout, so `--layout <name>` resolves through the projects registry, and `Everything` resolves too even though it has no registry entry.

**Objects are singletons: one live page per object, machine-wide.** An app open in three projects is one iframe and one document, not three. A view decides only whether an object is shown at all, which pane shows it, and at what size — never whether it is running. Switching projects, closing a tab, dragging a tab into another pane and re-splitting no longer reload or duplicate anything, because the element holding a page never leaves the DOM: removing an iframe destroys its document, and re-parenting one reloads it. Type into an app, switch to a project that does not include it, and switch back: the same page is still there, still running, still holding everything that was typed, resized to whatever pane is showing it now. A page is torn down only when the object behind it is destroyed.

Mechanically, a dockview panel is now only a *place*: an empty slot dockview creates, positions, hides and disposes at will. The live pages sit in a global registry keyed by object identity — the same grammar the member refs use — in the layer dockview already positions its panel overlays in, so each page mirrors the geometry and visibility of whichever pane currently shows it. Two consequences worth knowing: an app's Refresh now reloads its backgrounded panes too (it has always meant "the app", and those panes are still live), and a restored arrangement that names the same object twice keeps the first tab and drops the rest.

Apps can now carry their own icon, and it reaches the client with the rest of the app list. A registry row written by `forward_port.py --icon` holds the app's SVG markup; the workspace reads it into `AppEntry` alongside `name`, `url` and `label`, and every place the app list is serialized — the `apps_updated` payload sent on connect and rebroadcast whenever `apps.toml` changes — carries the markup too. An app that registered no icon reports an empty one, which is the common case and leaves consumers on their generic app glyph.

`forward_port.py` is the real validator, but the workspace re-checks the markup on the way out rather than trusting the file: a hand-edited registry whose icon is oversized, is not a bare `<svg>` element, or carries a script, style, event handler or `javascript:` URL loses its icon while the app itself still registers normally.

Apps finally have a destructive verb of their own, named for what it really does: **Unregister app**. Nothing in the workspace supervises the program behind a registered port, so the tab menu does not pretend to stop one. Confirming runs `system/scripts/forward_port.py --remove` for that app (via the new `POST /api/apps/<name>/deregister`), which takes its row out of `data/.state/apps.toml`, and drops its `service:<name>` member from every project, broadcasting the change like any other membership mutation. The confirmation says both halves plainly — the app disappears from every project and from the app list, and the program it runs keeps running until the agent that started it stops it — and the response reports the same, including `is_process_stopped: false`. The shell's own `system_interface` row is refused, and an unregistered name is a 404.

The rail's **Chat and Browser shortcuts now go to what the view already has** instead of starting another one every time. Chat opens the view's own chat — see below — and Browser opens the first browser it lists; only a view holding none of that kind gets a fresh one (chat and browser still ask for a name first). Backgrounded objects count: a chat or browser that is listed but not docked is opened into the active pane rather than skipped. Terminal still starts a new session on every click, and the New Tab launcher's "Open new" tiles still always create, which is where starting a second chat or browser now lives.

**Every project is made with a chat of its own.** Creating a project from the rail's switcher now also starts one chat, files it as a member of that project, and opens it in place of the launcher an empty view would otherwise mount — so a new project lands you in a working chat rather than on an empty picker. That chat carries the project's id in its agent's `project` label, and the rail's Chat shortcut goes to it: one chat per project, whatever else the project is given later, and a second one only ever from the launcher's "Open new" tile. Everything is not a project and has no chat of its own, so its Chat shortcut is unchanged. The chat is started in the background and can fail (the project is created first, and is created and usable either way); a failure says so, names the reason, and points at the Chat shortcut to try again, instead of leaving the project silently chatless.

Those icons are now **drawn**. Wherever an app is listed — the rail's shortcut rows and its tab list, the rail's "All apps" popover, the New Tab launcher's tables, and the dock tab's own leading glyph — an app that registered an icon wears it, at the size and stroke weight that surface already used, and an app that registered none keeps exactly the generic glyph it had before.

The markup is authored by a skill and is treated as untrusted at the point it enters the DOM: one sanitizer stands in front of every one of those surfaces, and no registry string is inlined without it. It parses with the browser's own parser (DOMPurify) rather than pattern-matching the string, keeps an SVG allowlist, and refuses anything that could execute or reach off the page — scripts, `on*` handlers, `javascript:` URLs, links, remote images and iframes, embedded HTML, animation, CSS (which can fetch), classes, and any reference that is not a `#fragment` into the icon itself. Anything left doubtful — markup that is not a single `<svg>` element, art with no viewBox or size to scale from, an oversized icon — is refused whole, and that app falls back to the generic glyph rather than drawing something half-trusted. An icon that paints itself keeps its colors; a monochrome one inherits `currentColor` like the built-in glyphs. Ids inside an icon are namespaced per icon, so two apps that both ship a gradient called "a" cannot borrow each other's paint.

That rule is held down by an adversarial test rather than by review: a battery of hostile icons — inline scripts, `on*` handlers on the root and on shapes, `javascript:` links, HTML smuggled through `<foreignObject>`, remote images and sprites, `data:` URIs, cross-origin filter paints, an animation that retargets an attribute after the fact, and comment, `<style>` and CDATA payloads written to break out of their own element when the sanitized markup is serialized and re-parsed — is delivered through the registry, drawn through the same call the sidebar and the dock tab make, and mounted in a real document. The assertions then sweep the mounted subtree for residue of any kind instead of checking one named vector at a time.

**Objects can be renamed, from the tab showing one.** Double-clicking a tab's title turns it into a field seeded with the name it has now: Enter or clicking away commits, Escape puts the old name back, and a name that is empty once trimmed is refused rather than leaving a tab with nothing to click on. What the gesture names is the *object*, machine-wide — see below — not the tab it was typed on, so the new name appears on every surface listing that object and in every project holding it. The same double-click works on a row of the project settings dialog's "In this project" list — and like the removals beside it, a rename there is *staged*: the new name shows in italic, the header counts what Save would apply, and Cancel throws it away with the rest of the form. Everything inside that dialog obeys its Save button; the tab strip, which has no Save button, commits on the spot.

A name the user chose wins wherever the object is listed, while an object renamed on the machine (an agent renamed through mngr) still drags its row along with it, and a tmux session rename no longer takes a chosen name back off a terminal tab.

The agent-facing `system/scripts/layout.py rename` now goes through that same one path, so an agent's rename is a chosen name too: it shows up in the rail and the settings list the way a hand-typed one does, and a tmux session rename cannot take it back off. It is held to the same rules as a typed name — whitespace collapsed, length capped, an empty title refused — rather than writing whatever string it was handed straight into the tab strip.

**A name now belongs to the object, machine-wide.** Names used to be kept with the panel showing an object, which meant they were kept in one view's saved layout: the app renamed "Docs" in one project still read "docs-viewer" in another, and an object with no panel anywhere — backgrounded, still running, just not docked — had nowhere to keep a name at all. Names are now filed by ref, in their own small registry (`workspace_layout/member_titles.json`) beside the projects one, because a name is a fact about the machine and a member list is a fact about a project. `GET /api/member-titles` returns the whole map and `POST /api/member-titles` names one object or, given a blank name, puts it back to whatever it calls itself; both are capped at the same 120 characters the tab strip enforces. Every change broadcasts over the existing WebSocket, so a client showing the object in a project this one never opened repaints too. Destroying an object drops its name with it, so a ref handed out again later — `terminal:terminal-4`, a name the allocator does reuse — never inherits a dead one. Deleting a project does the same for whatever the delete actually stopped: the terminals and browsers it tears down lose their names along with themselves, while a member it left running — a chat, an app — keeps the name it is known by everywhere else.

The client reads and writes names through that store, so **every surface that names an object says the same thing**: the dock tab, the rail's tab list and its app shortcuts, the New Tab launcher's tables, the project settings list, and Everything. The one app open in two projects is called the same in both, and renaming it in one repaints the other — including another browser window, and including a view this client never opened, because the change arrives as a broadcast rather than as a saved layout. **Backgrounded rows are renameable**, which is the whole point of naming the object: a member with no tab has somewhere to keep a name now, so the gesture is offered on every row a view lists rather than withheld with a "open this first" tooltip. Only a row already staged for removal in the settings dialog refuses it, and one click of Undo brings it back. Renaming a tmux session carries the chosen name onto the session's new ref, so a terminal keeps the name it was given.

No rename writes a name into a view's saved layout any more. A saved layout still carries a copy of whatever was on the tab strip, because that is what dockview serializes, but nothing reads one back as a name: mounting a view puts the object's own name on every tab, so a view whose file was written before the rename still shows it. The one exception is a layout saved before this change, which is carrying a name of its own on the panel; that one is read as a fallback so nothing loses its name on upgrade, and the store always wins over it.

**Pinning an app to a project is the same fact as its membership.** There used to be two things — whether the project listed the app, and a separate per-browser pin preference layered on top — whose cross product gave four states to reason about and which disagreed between browsers, so the same project's rail looked different on a laptop than on a desktop. There is now one fact: an app is pinned in a project exactly when the project's member list holds its `service:<name>` ref. The rail's app shortcuts are that list, in member order. The "All apps" popover has exactly two headings — **"Pinned in `<project name>`"**, this project's app members, and **"Unpinned"**, every other app on the machine — and each row's toggle adds or removes the member. Unpinning takes the same path as any other "Remove from project": the app keeps running, it stays in every other project showing it, and it stays in Everything. Because it is membership, pinning is server-side and shared, so it follows the project rather than the browser it was done in. Everything pins nothing — it is the unfiltered view and lists every app already — so it draws no app shortcuts and its popover is one flat list with no toggles. The old per-browser `si-sidebar-app-pins` entry is not migrated: its "unpinned" half would have to remove members, dropping apps out of the project's tab list entirely rather than only off its rail, and whichever browser loaded first would impose its own preferences on everyone else's view of the project. The new default is strictly more visible than the old one — every app the project holds now appears on the rail — so nothing that was reachable becomes unreachable.

**The settings dialog's removals now wait for Save.** Marking a row used to remove it from the project on the click, which made it the one control in a dialog full of Save/Cancel fields that obeyed neither: a user could mark a row, think better of it, press Cancel, and find the object already gone from the view. Now marking a row stages it — the row is struck through, its button turns into Undo, and a count beside the list header says how many removals Save would apply — and Cancel throws the marks away with the rest of the form. Save applies them, then saves the project's name, color and glyph, so a removal that fails reports itself in the dialog instead of behind the dialog it just closed. The rail's own per-row "Remove from project" is unchanged and still removes on the click; it has no Save button to obey.

**The launcher's "last active" column is real.** The machine now keeps a per-object last-used timestamp, keyed by the same member refs as names (`member_last_used.json` beside `member_titles.json`), so both launcher tables genuinely order by recency instead of listing everything as unknown. Focusing or opening a tab records a touch for the object behind it — throttled per ref, so focus flapping between two panes does not write per click — and the server stamps every touch with its own clock (the client sends only the ref), so two machines' clocks never disagree about what was used when. Recency is machine-wide like a name: the same object ranks the same in every project's launcher and in Everything, a backgrounded object keeps its place with no panel to keep it on, and a `member_last_used_changed` broadcast re-orders every client's open launcher live. Destroying an object drops its entry along with its name, so a reused ref never surfaces at the top of the launcher on the strength of a dead one; an object never used simply shows the dash it always did. New endpoints: `GET /api/member-last-used` and `POST /api/member-last-used`.

Each launcher table's kind filter is now a proper checkbox menu: one row per kind the table actually holds — a project with no browsers is not offered a browsers checkbox — each row wearing its kind's icon beside its name, and a "Reset filters" action below a divider that re-checks everything at once. Unchecking a kind hides that kind's rows in that table alone, and a table whose filter hid every row says so ("No tabs match this filter") instead of pretending to be empty.

An app without an icon of its own now wears its monogram in the house icon style -- the initial in an outlined tile, currentColor strokes on a transparent background -- rather than a colored tile. Color is the projects' identity language (the squiggles and their palette), not the apps'. Agent-authored icons are likewise directed to the same monochrome line style by default, in the build-app skill and the forward_port.py flag help; color only when the user asks for it.
