Replace named dockview layouts with **projects**, and make a project a *view* over the machine rather than a container that owns things.

A machine holds one pool of objects: chat agents, terminal sessions, fleet browsers, registered apps, and ad-hoc pages. A project is a filter over that pool plus its own dockview arrangement. Membership is explicit and durable — a list of refs (`chat:<agent-id>`, `terminal:<name>`, `service:<name>`, `service:browser?session=<name>`, `url:<hash>`) kept separately from the layout — and it is **many-to-many**: the same object can sit in any number of projects at once, so the one app a machine runs can appear in every project that wants it. Nothing owns anything, and there is no "move".

Because membership no longer lives in the layout, **closing a tab stops nothing and files nothing away**. A member with no panel is *backgrounded*: the tmux session keeps running, the fleet browser stays up, the app stays supervised, and the object stays listed in the project's sidebar so it can be reopened. **"Remove from project" hides an object in that one view only** — it keeps running, and it stays in every other project showing it. Only destroying an object takes it off the machine, and that drops it from every project at once.

**Everything is the unfiltered view, and it is the home.** It is not a project: it has no registry entry, no member list, and cannot be renamed or deleted. It does keep its own layout like any other view. Its tab list enumerates the *machine* rather than unioning the projects' member lists, so an object filed in no project at all still appears there — and selecting a row opens it in Everything's own dock rather than jumping somewhere else.

The old top-bar picker is gone. Everything now hangs off a **project rail** down the left edge: 37px at rest, expanding on hover to a 240px panel that floats over the dock and stays open while any of its menus is. Top to bottom it holds the project's glyph and name (the whole row opens the view switcher; right-clicking it opens project settings), shortcut rows for Chat, File Viewer, Browser, Terminal plus the project's apps and any the user pinned here, a quieter "All apps" popover with per-project pin/unpin, a search pill that filters on label and kind with the matched substrings bolded, and the tab list itself. Open members render as primary text and backgrounded ones as tertiary; there is deliberately no persistent selected-row highlight, since the dock shows several panes at once. Each row's hover kebab offers the verbs that make sense for its kind — sharing for apps, "Remove from project" for anything in a project, and a destructive "Delete from this machine" for chats, terminals and browsers. File Viewer renders disabled with a tooltip, because no file-viewer app backs it yet.

The "+" dropdown and the empty-state overlay are both replaced by a full-page **New Tab launcher** that opens as a real tab. It offers tiles to start a chat, browser or terminal from scratch, a table of what this project already shows, and a table of everything else on the machine; each table has a kind filter and a recency column. Opening something from the machine-wide table *adds* it to the project you are looking at and takes it from nowhere. The dock is never empty — closing the last tab opens a launcher — and clicking "+" in a pane that already has one flashes it instead of stacking a second.

Visually the dock is now a set of connected tab cards: a flat grey canvas inset from the window frame, each pane a white card with a hairline border and 12px radii, a transparent tab strip, and an active tab that shares its pane's outline so the two read as one shape. Every tab in every pane renders at the same width, recomputed on layout, pane and window changes, with overflowing titles fading out rather than ellipsizing. Tabs carry a kind icon plus a close button and an options button, both revealed on hover; the options menu offers Refresh, Share for app tabs, Close tab, and a per-kind destructive verb (destroy the agent, kill the tmux session, retire the fleet browser) behind its own confirmation. Workspace tooltips were restyled and retimed to match the minds shell's.

An existing machine upgrades cleanly: its whole `desktop` arrangement becomes one starter project ("Project 1") with each of its panels filed as a member, so nothing moves and nothing is lost. Projects are stored per-view under `workspace_layout/projects/<id>.json` with a `projects_meta.json` registry holding metadata, member lists and the last-active id. Deleting a project is confirm-gated and deletes the view, not what it showed.

The API gained member endpoints alongside the existing project ones: `POST /api/projects/<id>/members`, `POST /api/projects/<id>/members/remove`, `POST /api/projects/members/share`, and `GET /api/projects/members`. Membership changes broadcast over the existing WebSocket so every client's sidebar catches up, whether or not it has the affected project mounted.

Agent-driven layout ops (`system/scripts/layout.py`) keep working: a connected client reports its active *view* as its active layout, so `--layout <name>` resolves through the projects registry, and `Everything` resolves too even though it has no registry entry.
