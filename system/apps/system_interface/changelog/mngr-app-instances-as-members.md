Plain workspace apps are now multi-instance, with numbered instances ("File Viewer 1", "File Viewer 2") as first-class members exactly like chats, terminals, and browsers. An instance is derived rather than stored: it exists while any project's member list or any view's saved layout references it (refs ride the service-query grammar as `service:<name>?instance=<name>-<N>`), and the backend mints canonical names lowest-free-number-first via `POST /api/apps/<name>/instances/allocate`, with `GET /api/apps/instances` listing the machine's inventory.

Opening an app resolves to the view's most recently used instance or mints the first one; launcher tiles, "new"-mode shortcuts, and the shortcut menu's "New X" always mint. Everything's tab list and the launcher's machine table list instances (a zero-instance app has no tab-list row); Everything's rail shows a fixed shortcut row for every openable app, and its All apps popover shows the already-pinned empty state.

Instance rows and tabs carry the uniform confirm-gated Delete (the instance leaves every project and its name, recency, and stored location are cleared; the app's service keeps running), with the service's own Share and Stop/Start verbs in a trailing menu group so they stay reachable from any instance.

Instances that beacon their location reopen where they were looking: the shell listens for one-hop `minds-location` posts from framed apps, validates the sender against its own service origins, and stores the path machine-wide per instance ref (`GET|POST /api/member-locations`).

App panes restored from a pre-instances layout adopt the app's lowest free instance on first mount and file through the normal auto-membership path. Bare `service:files` member entries left behind by older builds -- dead entries that only ever rendered a phantom "files" tab row, since the file viewer's pin is its built-in rail row -- are purged from the project registry on read, alongside the existing legacy `url:` member purge.
