Point the composer's Opus entry at Claude Opus 5. It selects the `opus[1m]` alias, which Claude Code resolves to whichever Opus is current, so on the new 2.1.220 pin that entry serves Opus 5.

Two things had to move with it. The label read "Opus 4.8 (1M)", naming a different model than the picker actually selects. More consequentially, `harness_reported_model_id` was still `claude-opus-4-8`: `match_option` keys the live model-state read against that id, so once the statusline started reporting `claude-opus-5` nothing in the catalog would have matched -- neither the reported id, nor the option id, nor the prefix-tolerance pass -- and the model bar would have fallen through to the shrug case with no model shown. Both now say Opus 5. Fast mode still applies to the entry.
