The chat no longer shows "Thinking..." or a running tool forever after a turn is interrupted directly in the terminal (Esc in the Claude TUI). Claude fires no hook on an interrupt, so the `active` marker created at prompt submit was stranded: the lifecycle kept reporting RUNNING and the chat activity indicator stayed pinned on a dead turn while the terminal sat idle -- the chat-side stop button healed its own interrupts, but nothing watched for terminal-side ones. The claude session watcher now detects interrupt sentinel records (both shapes) as it parses the latest main session and clears the stranded markers the same way the hooks do (`mark_claude_agent_idle`), guarded by the marker's mtime so a turn started after the interrupt (an immediate resubmit, or a queue flush) is never un-marked.
