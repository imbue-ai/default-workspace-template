The shell can be routed to from the first moment of a boot instead of only once it has imported. Its program line binds port 8000 first (`listen_then_exec.py`), then registers with `forward_port.py --announce`, which puts the shell on the services stream at once. The server (`make_threaded_server`) serves on the socket it inherits through `WERKZEUG_SERVER_FD`, so a request that arrives while the shell is still importing waits and is answered as soon as it serves, instead of being refused. A socket on any other address than the configured one is refused with `InheritedSocketMismatchError`.

The shell also starts serving before it starts its theme watch, which loads the whole theme catalog, and before its profile snapshot watch, presence sweep and roster watch. `ShellState.start` is split into `start_before_serving` (the client prune, the registry read that announces the apps, the lifecycle sweep, the update notice and the avatar status) and `start_after_serving`. `start` still runs both.
