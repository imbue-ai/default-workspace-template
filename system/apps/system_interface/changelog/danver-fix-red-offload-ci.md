Tests only: the shell's test servers no longer lose their port before they start. The harnesses picked a free port, gave it back, started other servers, and bound it only then, so a bind in between could be handed that port and the shell's server failed to start with "Address already in use", as `test_shortcut_menu_changes_mode_and_removes` did on main. A server whose port must be known before it is built (the e2e shell, the layout pipeline's, the theme gallery's) now adopts a socket held listening since the port was picked: `listening_loopback_socket` in `testing.py`, through a new optional `fd` on `make_threaded_server`. `serve_app` binds port 0 itself. The running shell passes no `fd` and binds as before.
