The launcher is now a menu (launcher-and-getting-started plan sections 3 to 6). The taskbar's field ("Start app or send message...") opens a compact card above itself with one row per launch path of every app, a row per window of every desktop while typing, and at the foot the free-text rows: one per launch path that declares a `text_param`, which run that launch path with the typed text. One row is always highlighted; the arrows and hovering move it, Enter or a click runs it, and Ctrl+Enter (Cmd+Enter on macOS) runs the secondary free-text row whatever is highlighted. A free-text row of an app with an independent pinned window points this client's view of that window at the path (restoring and raising it) rather than opening a new window; a text whose encoded path would pass the window path bound is disabled with "Too long to send from here". Typing filters the rows with the library's `matchesQuery`; free-text rows always stay.

The shell answers a new contract message, `shell:start-with-text` (`startWithText(text)` on the connection `connectToShell` returns): it runs the launcher's primary free-text row with the text, so a framed page starts a chat without naming the chat app, and notifies "No app on this machine can start a chat" when nothing on the machine declares one.

The "Start something" intents, the template shelves and detail, and the template catalog (`template_catalog.py`, `GET /api/templates-catalog`, `Config.system_interface_template_catalog_url`) left the shell for the Getting Started app; `LauncherOverlay.ts` and the tiles' `.launcher-tile` class are gone. The registry wire form of a launch path gains `text_param`. The menu's width is the theme token `--desk-launcher-menu-width`. Selectors: `data-launcher-overlay` names the menu, `data-launcher-row`, `data-launch`, `data-launcher-window`, `data-text-action`, `data-highlighted`, and `data-disabled` its rows (contracts section 12).
