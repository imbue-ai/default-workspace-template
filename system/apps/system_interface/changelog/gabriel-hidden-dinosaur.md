- The chat OOM prioritizer now ages chats out as well as protecting them, so a chat left untouched for hours becomes more expendable under memory pressure than the worker a live chat just spawned. Previously it could only ever *protect* a chat (down from the launch band toward the protected floor) from reported UI engagement, which meant a workspace under memory pressure always shed a running worker before a chat nobody had messaged in days.

- Idle time is measured wall-clock from the most recent of: a message sent through the UI, the moment a chat's tab was switched to, either edge of a turn, or -- as a floor -- the chat's own `claude_process_started` mtime, so a freshly revived chat is never treated as stale. Switching *to* a tab counts as engagement; leaving one visible does not, so a repeated presence report never resets the clock. A chat with no evidence at all counts as fresh: it is demoted only on positive evidence of abandonment.

- Chats messaged outside the workspace UI (by `mngr message`, or by another agent) are now visible to the prioritizer. It consumes the observe stream's lifecycle states, so a chat entering a running state counts as engagement, and a chat that stays running is treated as mid-turn and exempted from aging until its turn ends. Without this an agent-driven chat would look abandoned and could be shed ahead of workers.

- Re-tagging is now event-driven plus a slow sweep (60s). The events (activity reports and lifecycle changes) still cover everything that changes a chat's engagement; the sweep exists because staleness is the one input that changes with no event to announce it -- a chat crosses a threshold by sitting still. Per-chat message times are re-seeded at startup from the durable client-activity log, so restarting the system interface no longer makes every chat look never-messaged and restart its staleness clock.
