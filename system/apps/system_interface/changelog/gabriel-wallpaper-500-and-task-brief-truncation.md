A wallpaper of your own now displays. An image placed in the workspace's own wallpapers directory (`data/.apps/system_interface/wallpapers/`) was offered by the picker and could be set on a desktop, but every request for the image itself failed, so the desktop rendered with no backdrop at all; the wallpapers that ship with the shell were unaffected. That directory is configured as a path relative to the workspace root, and the route that sends the image resolved it against the shell's own package directory instead, looking for the file somewhere it had never been written. A configured directory is now resolved to one absolute place where the shell's state is built, so the listing and the image both name it; the avatar catalog directory, configured the same way, is resolved there too.
