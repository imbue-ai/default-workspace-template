The shell records a person interacting with a window as a `window_input` client-activity event (desktop contracts.md section 6), one per client, window and minute: the page driver keeps the window each page's `shell:input` report came from and carries the windows on the presence heartbeat (`client_id` and `input_windows`), and the shell writes the event with the desktop's app and desktop. A page that has declared no capabilities (a wrapped third-party server) reports no input, so focus landing in its frame, by a click or a raise, is recorded as a `focus` kind instead. Never the path, the title, the key or the pointer position. A heartbeat is never refused for its input fields; a field off its shape drops the reports and records presence as before.

The client-activity log is now bounded the way the announcement stream is: past 8 MiB it is staged aside before a write and gzipped off-thread, two archives kept; the `context` op and the attribution of an agent's op to a page's last message read the live stream alone.
