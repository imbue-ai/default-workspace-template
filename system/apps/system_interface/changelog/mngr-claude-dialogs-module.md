
Added `docs/specs/send-failure-notice.md`: a spec for showing a failed send inside the workspace instead of in a native system alert. Any send failure -- a dialog holding the agent's input, a readiness timeout, a transport error -- would open the same in-app notice the workspace already uses for declined commands, with a title, the failure text, and an OK button that Enter, Space, and Escape all dismiss. Not scoped to dialog errors, and deliberately not a harness-declared popup: those fire before a message is sent, off what the user typed, whereas this reports what the backend refused.

A send that fails now says why, inside the workspace. Previously the reason was discarded deep in the send path -- the messenger reduced mngr's result to a yes/no -- so the chat could only report "Failed to send message to agent 'Chat 2' (0 successful agents)", and it reported it through a native system alert. The harness's own words now travel to the chat, which shows them in the same notice style the workspace already uses for declined commands: a title, the reason, and an OK button that Enter, Space, Escape, and a click outside all dismiss. So a message refused because the agent is sitting on an unsubmitted shell command now says exactly that, and which keys resolve it. A failed interrupt uses the same notice. The `/welcome` resend logs the reason it failed rather than just that it did.
