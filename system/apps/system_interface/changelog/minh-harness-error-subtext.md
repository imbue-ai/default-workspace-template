A failed turn on pi or codex used to be silent -- the agent just stopped, with nothing in the transcript to say why. Both harnesses now surface their failures the same way claude does, and every failure carries a subtext telling the user what to do about it.

**pi:** a rejected request comes back as an ordinary assistant message with empty `content`, `stopReason: "error"`, and the whole failure in a sibling `errorMessage` field. The parser read its text from `content` alone, so the event was emitted with `text: ""` and painted a blank bubble -- an agent stuck on a billing rejection looked like an agent that had simply stopped answering. The text now comes off `errorMessage` when the turn failed, gated on `stopReason` so a real reply that merely quotes an error JSON is not styled as one.

**codex:** a failed turn carries its reason on the persisted `task_complete` event, in `error` (`{message, codex_error_info}`); the parser emitted only the turn-completed marker and dropped it. That was the *only* durable copy -- codex classes its live `EventMsg::Error` non-persistent, so it never reaches the rollout -- meaning the failure was unrecoverable once the turn ended. It is now surfaced as an assistant message ordered before the marker, classified off the structured `codex_error_info` tag where we know it and off the message prose otherwise.

**Shared classifiers:** `error_patterns` and `auth_patterns` moved out of `harnesses/claude/` to `harnesses/`, since all three harnesses now use them. `error_patterns` gained pi's bare `"<status> {json}"` surface form (claude's required a literal `API Error:` prefix), anchored to the start of the string so a status code mentioned mid-message is not read as a failure.

**Auth errors no longer reach into the transcript.** An auth error used to auto-open the sign-in modal, from two places: the SSE stream hook and a snapshot-load scan of the latest assistant message. Both are gone. The transcript now just says what to do -- an auth or quota failure renders in the same red block as any other error, with the subtext "Choose or add another provider to continue this conversation!" -- and the sign-in surface stays where the user chose to go looking for it (the "Agent auth" button under the composer, or `/login`). One fewer coupling between the transcript and a modal, and the guidance is visible whether or not the modal would have opened.

The credentials family is deliberately broader than literal 401s. Anthropic's third-party-usage exhaustion arrives as a *400 invalid_request_error*, and codex reports quota exhaustion as `usage_limit_exceeded` -- neither is an authentication failure in the HTTP sense, but the only way forward for both is different credentials, which is exactly what the subtext offers. They join claude's already-flagged "Credit balance is too low" and the LiteLLM proxy budget rejections. A failure in this family is never also stamped `is_api_error`, so the two subtexts can't stack under one message.

The pre-login hiding rule is unchanged: auth errors from before a successful reply are still folded away once login recovers, and a currently-broken agent still shows its failures in full.
