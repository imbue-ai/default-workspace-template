The system interface gains an `app.toml` manifest (`internal = true`, `critical = true`, `priority = "system_interface"`), and its supervisord program registers through `forward_port.py --manifest system/apps/system_interface/app.toml` instead of `--name system_interface --no-icon`. Its registry row now carries `display_name`, `critical`, `priority`, and `program`; nothing the shell renders changes (the row was already hidden by name). The `system-interface` tool is now installed by the generic per-app loop in `system/scripts/build_workspace.sh`, with its mngr plugins looked up under its manifest name (`system_interface`) in `system/config/mngr_plugins.toml`. Phase 1 of the workspace app model (`docs/system/blueprint/workspace-app-model/`). Deregistering an app (`POST /api/apps/<name>/deregister`) now runs `forward_port.py --remove` under a plain `python3` instead of `uv run`, since the script is standard-library only.

Phase 3 of the workspace app model (the terminal app): `POST /api/terminals/notify` prefers a `terminal_id` in the body over its own lookup in `$MNGR_AGENT_STATE_DIR/commands/ttyd/clients/`. The terminal app owns the pty-to-tab records now (under `data/.state/terminal/commands/clients/`), resolves the tab id itself, and forwards each tmux hook event here with it, so live tab titles keep working until phase 7 replaces this endpoint with the generic tab route.

Phase 4 of the workspace app model (the files app): the location-beacon listener (`frontend/src/locationBeacon.ts`) accepts `{type: "shell:location", path}`, the contract's message the vendored file viewer posts now, beside the older `minds-location` spelling, which phase 7 drops together with the listener.

Phase 6 of the workspace app model (chat as a document): every chat renders inside an iframe at the registered `chat` origin, served by the system-interface process itself, and behaves as before.

- The chat pages, their bundle, and their API are a second Flask app, `imbue/system_interface/chat_document.py`, over the same state: `GET /<agent-id>` (and `/<agent-id>.<session-id>` for a subagent view) serves the new `chat.html` document with the chat's ids in meta tags; the chat routes moved off `server.py` verbatim (every `/api/agents/<id>/...` route except `destroy`, `start`, and `stop`; `create-chat`, `harnesses`, `uploads`, `claude-auth`, `accounts`, `lanes`, `latchkey`, `proto-agents`); the instances API of `contracts.md` section 4.3 is served at `/_instances` over the agent manager (`chat_instances.py`: agents, chats still being created, and subagent views as instances, with status from the activity state, a pending permission request, and the lifecycle; `503` until the agent list has been read from mngr once); and `POST /api/agents/<id>/presence` replaces the frontend's `/api/activity` reports as the OOM prioritizer's open and visible inputs (`presence.py`: per client, `visible`, `hidden`, `closed`, ten-minute expiry, a sixty-second heartbeat from the page; the send route records `messaged`). Requests reach the chat app by path (`wsgi_dispatch.py`), never by origin label, so loopback callers such as the minds evals bridge keep working.

- The shell (`server.py`) keeps `GET /api/agents`, the three agent verbs, the projects, member, terminal, browser, app, and layout routes, and the WebSocket; it gains `GET /api/health` (`{"status", "is_frontend_built"}`) and serves the browser-side contract module at `GET /_static/app_contract.js` with `Access-Control-Allow-Origin: *`. `/api/activity` is gone.

- The agent manager nudges the shell on every agent-list broadcast (`set_nudger`; `main.py` installs a `ThreadedNudger(ShellNudger("chat"))`), reports whether its agent list is known, tracks pending permission requests per agent from the transcript events (the chat row's `attention` status), and owns the destroy path (`destroy_chat_agent`) the shell's route and the instances API share. `naming.py`'s canonical-name rule delegates to the instances library's.

- The frontend is two documents from one build: the shell (`index.html`) and the chat page (`chat.html` -> `src/chat/index.ts`), with the chat views, models, plugin API (`window.$llm`, hooks, slots), and markdown moved under `src/chat/`; the shell bundle imports nothing from there (a new check in `test_embed_ratchets.py` holds it). `src/app_contract.ts` is the app page's contract module (`connectToShell`; `contracts.md` section 10), built as its own library into `static/_static/app_contract.js`; `src/relay.ts` is the shell's child-frame boundary: the minds relay of section 11 (chat pages' permission cards reach the minds chrome through it, and the chrome's verdicts come back down) and the shell side of section 10 (`shell:handshake`, sent by `IframePanel` on every load of the frame and again when the tab or view showing the page changes, `shell:shown`, `shell:hidden`, and `shell:close-request`; `shell:focused` activates the posting frame's tab; `shell:open` docks a chat or subagent page beside it, with an optional `title` hint until phase 7; `shell:location` is logged until phase 7). A chat or subagent tab is an `IframePanel` at the chat page's URL (the chat origin, or this document's own origin when the host carries no workspace coordinate). The provider chooser, the launcher's provider picker, and the first-run greeting stay on the shell until phase 10; the chat page renders the chooser too for the model bar's "+ Add a provider".

- `system/apps/chat/app.toml` (with `icon.svg`) is the chat manifest, registered from the shell's supervisord line at the shell's own port; until phase 7 and 10 it declares `internal = true`, `program = "system_interface"`, and `priority = "system_interface"`, each with a `# CLEANUP:`. `system-interface` depends on `app-instances` and `app-manifest`.
