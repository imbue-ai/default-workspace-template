Phase 8 of the workspace app model (the layout file is the truth): a client's layout file on the shell is the truth of its arrangement, and agent ops no longer need a connected browser. The shell applies `open`, `focus`, `split`, `close`, and `move` to the target client's file itself (`shell/dockview_document.py`, a pure editor over dockview's saved document: tree-based neighbours, splits as a share of the anchor's extent, a nominal root for a never-arranged view, launcher panels dropped from the group docked into) and announces every write of a client layout, its own and a browser's, as `layout_updated {view_id, client_id, save_id}`; the owning client's windows refetch and apply it without reloading any page (pages live in the live-surface layer, so re-mounting the grid tears down slots, not pages), skip their own save ids, and record the dock's serialization after applying so two windows of different sizes never save their rescaled copies at each other. A browser's save carries a `save_id` and the `base_updated_at` it was based on and answers `{"updated_at"}`; a save over a newer stored arrangement is refused with 409 and the window takes the shell's, and a save that changes nothing is skipped; only browser saves rewrite the per-device seed, while the shell's own prunes and tab rebinds edit the seed files directly. Every op targets exactly one client (`--client`, else the client that last messaged the requesting agent, else the one connected client; otherwise a 412 naming the connected clients and never "every client"); `--view` edits that view's file and switches the client to it; `open` of an app with instances creates through the relay inside the op (`--action`, `--param`; a bare URL is the browser's `new` with `url`) and answers with the created address, so an app's refusal is the op's error; only `maximize`, `restore`, `refresh`, and the interface reload still travel to the browser as `layout_op` messages, targeted at the client's windows. The active view lives on the client record: `GET /api/clients` (with `is_connected`) is what a window reads on boot, local storage no longer holds it, `active_view_changed` is broadcast only when a stored view actually moves (a `client_state` report, a `load`, an op's `--view`), a follower reports without a previous view, and `load_layout` is gone. `GET /api/inventory` serves the document of contracts section 9 with every client's `docked` addresses. Deep links (`?view=`, `&open=`, `&action=`) are applied by the browser on load and stripped from the URL. The advisory layout mutex, the "no client on view" 412, and `layout.py`'s wait-stable polling are gone, and so are the op route's `list` and `views` ops (the script reads the inventory endpoint; the route's read ops are `inspect` and `context`). The dock root carries `data-view-id`.

The browser saves a tab added, removed, or moved about a tenth of a second after the gesture rather than after the 1.5 s resize debounce, so an agent op that follows a click finds the click's tab in the arrangement the shell edits; resizes keep the longer debounce.
