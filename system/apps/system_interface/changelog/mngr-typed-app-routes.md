The shell's routes are typed: every route is in a route table the API document publishes, each JSON body is read through the shared `parse_request_body` and each JSON answer through `model_response`, so the document shows a request and response schema for every one of them (the desktop, window, placement, client, avatar, wallpaper, update-notice and presence routes, and the agent-facing op route's bodies and answers as a choice), and every refusal is the shared `{"detail"}` shape. Two wire shapes changed: `GET /api/updates/pending` answers `{"notice": <notice or null>}` instead of the bare notice or null, and the embedder-message relay's answer carries `detail` as an explicit null when every app took the message, and its deliveries carry `shown`, `has_no_desktop_window` and `window_id` as explicit nulls when no page was shown.
