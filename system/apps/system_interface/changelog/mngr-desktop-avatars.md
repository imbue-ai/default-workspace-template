Pinned taskbar entries and the chat avatar (`docs/system/blueprint/pinned-taskbar-entries/plan-pinned-taskbar-entries.md`).

- An app whose manifest declares a `[pin]` has exactly one pinned window on every desktop: the shell reconciles it on every read of the desktops after the registry is read (adopting the earliest-opened window of the app at the home path, else creating one) and gives a new desktop its pinned windows at birth. A pinned window is never closed: the close route answers `409`, the `close` op is refused with "minimize it instead", its title bar has no close control, its window and entry menus offer no Close, and the minds close chord minimizes it. Withdrawing the pin turns the window back into an ordinary one.

- `desktops.json` stays at version 1: each window gains `is_pinned` (default `false`) and `scope` (default `linked`). The inventory's `app` object and `apps_updated` carry `pin` (the manifest table, or `null`). A workspace upgraded to this version gets a pinned window on every existing desktop on the first read; a chat root that had drifted to `/?chat=<id>` is not adopted, so that desktop briefly holds it beside the new pinned window until the old one is closed.

- A window's location scope is `linked` (the V1 rule: one shared path and title every client follows) or `independent`: the shared path stays the home path forever, and each client keeps its own path and title in `window_paths/<client_id>.json`, written only by that client's own location report (the route's body gains `client_id`) or by an agent's `navigate` targeting that client, and announced to that client with `placements_updated` and a shell-minted save id. `GET /api/placements/<desktop>` answers `window_paths` beside the layout, which the browser uses to open, title, and follow an independent window's page. A client's window-path file is pruned with the client.

- How one client shows a pinned entry is three values on its client record, keyed by app and global across desktops: the mode (`bar` or `floating`), the style (`plain` or the pin's declared style), and the floating position in fractions of the backdrop, written by `POST /api/clients/<client>/entries/<app>` and announced to that client's windows as `client_entries_changed`. A floating entry is drawn above every window and page at the theme's sticky level; a click is the taskbar entry click, a drag moves it and writes the position once on release, and its context menu is the entry menu with Close removed plus Float or Move to taskbar and Show as plain entry or Show as <style>. Compact mode renders every pinned entry in the bar without rewriting the mode. New theme tokens: `--desk-floating-entry-size`, `--desk-floating-entry-inset-x`, `--desk-floating-entry-inset-y`.

- The `avatar` style draws the workspace's avatar in place of the entry's icon: an isolated SVG image (`GET /api/avatars/<id>/image.svg?mood=&preview=`) of the workspace's selected design wearing the mood one backend module folds from the agents event file the mngr observer writes under `$MNGR_HOST_DIR` (working when any agent but the services agent is running; stale past ten minutes or with no file), pushed to every window as `avatar_status {mood, is_stale}` on connect and on change. The seven bundled designs come from the desktop-mode prototype; `GET /api/avatars` lists them with the registered ones, `POST /api/avatars` (loopback only) registers an original an agent drew (validated with defusedxml against the vocabulary in `docs/system/avatar-designs.md`, kept verbatim in `data/.apps/system_interface/avatars/catalog.json`, at most 32), `GET /api/avatars/<id>/source.svg` serves the original, and `POST /api/avatar-selection` writes the workspace's choice to `avatar_selection.json` and announces `avatar_selection_changed`. The entry's menu gains "Change avatar...", which opens the chooser: every design's still preview, a link to the selected original, and "Design your own...", which starts a chat seeded with the design prompt through the app that takes a message. `register_avatar.py` posts a file through the running shell. New dependency: `defusedxml`.
