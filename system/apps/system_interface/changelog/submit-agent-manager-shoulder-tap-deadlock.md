Fixes a lock-order-inversion deadlock that could permanently freeze the whole workspace UI. `AgentManager.get_agents_serialized` computed each agent's shoulder-tap availability while still holding `AgentManager._lock`, and that computation calls into the harness session -- for an Antigravity chat, into its `QueueTracker`'s own lock. Antigravity's queue-flush worker acquires that same `QueueTracker` lock and, while holding it, publishes a snapshot back into `AgentManager.update_queued_messages`, which needs `AgentManager._lock`. Two threads acquiring the same two locks in opposite order deadlocks both permanently, and every later request needing `AgentManager._lock` -- including creating a new chat, on any harness -- queues up behind it forever. `get_agents_serialized` now copies the agent snapshot out under `_lock` and computes `shoulder_tap_available` after releasing it, so the manager never holds its own lock while calling into a session.
