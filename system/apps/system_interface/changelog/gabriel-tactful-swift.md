The system interface hardens against update-time version skew.

Its single mngr `load_config` call site now parses with `strict=False`, so a `.mngr/settings.toml` written for a newer mngr degrades to a logged warning instead of a 500 on every agent listing and message send (the lockout that made a broken update self-locking). `mngr config set` and the CLI keep strict parsing.

The server records the tree HEAD it started from and injects a `system-interface-update-staleness` meta tag into the built app shell when the live tree has moved under it in a way that affects what this process runs (backend code, its dependency manifests, the vendored mngr, `.mngr/settings.toml` -- never ordinary agent commits, docs, or the frontend, whose bundle is rebuilt without a restart) -- `updated-not-activated`, `update-interrupted` when the update apply's marker is present, or `update-emergency` when a failed update's rollback could not restore a healthy workspace -- and a small informational banner renders the three messages, pointing the user at their agent (the meta tag is the whole surface: nothing reads a response header, so the shell does not carry one). The emergency variant outranks the other two and is the only one whose copy does not tell the user to wait: it is the one state here that will not resolve on its own, and it is invisible to both other checks (that exit clears the marker, and the rollback puts the tree content back).

The reveal machinery that lived in `reveal_system_interface.py` moved into the general update apply (`update_self.py apply`); the script keeps only the pre-merge `preview`/`unpreview` adapters, and going live is now one atomic merge-and-reveal with no agent-prose pause between landing and activation.

The frontend build now stamps its output: an npm `postbuild` step writes the git tree hash of the frontend source directory into `static/.source-tree-hash` (best-effort; absent when the build runs without a git repo). The update apply compares that stamp against the merged tree so a `--worker-bundle` built from other frontend source is never served as if it were the merged source (the apply builds live instead); a live build's stamp is checked the same way as a consistency guard.

A chat asking to have its tab surfaced (the `assist` label, or the new purpose-neutral `auto_open` label) is now shown its tab once, reliably, instead of only if a browser happened to be connected the instant it appeared. Before, the open was a broadcast to whoever was connected: a chat created from outside the workspace -- the minds app's update flow -- appeared while the user was still on their way in, so the open went to nobody and the tab never showed. The open is now held until a client has registered, and which chats have been shown is remembered on disk beside the saved layouts, so the interface that comes up after an update's own restart neither re-pops a tab the previous one surfaced nor loses one it never got to show: a recent chat found at startup that no client has seen (an update run overnight) is shown on the next connection, while older ones are left as the saved layout has them.


The bundle directory the shell routes serve from is now ordinary state configuration: `SystemInterfaceState.static_directory` defaults to the package's own `static/` and the routes read it from the state, instead of a module constant plus a `None`-means-default override that only a test ever set (and that the bundle tests patched around with `unittest.mock`).
