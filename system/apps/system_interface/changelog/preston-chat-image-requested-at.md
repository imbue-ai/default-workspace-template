Stopped new chat messages from rendering a stale cached copy of an image (or file) whose path an earlier message reused. Chat files are served with a one-year immutable cache keyed by their on-disk path, so overwriting a referenced file and showing it again under the same path could display the browser's old cached bytes. The frontend now tags each message's image `src` and download-link `href` with a `requested_at` query parameter set to the message's post time, making every message's file URL unique: a new message's URL has never been cached, so the browser fetches the current bytes, while re-rendering the same message reuses its stable URL and cache without refetching. The server ignores the parameter, and now serves non-image downloads with the same one-year immutable cache header images already use, so a re-download of an unchanged message never refetches either.
