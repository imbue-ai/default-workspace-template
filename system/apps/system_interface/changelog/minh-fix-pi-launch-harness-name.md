The New Tab launcher's "Pi chat" and "Introductory Pi chat" tiles now actually create an agent. They were sending the tile's own kind (`pi`) as the harness, but mngr's agent type is `pi-coding` (`pi` is only an mngr-side alias, which the create endpoint's harness enum does not accept), so every Pi launch was rejected before any `mngr create` ran and surfaced as a raw validation error. Codex and Claude were unaffected, their tile kinds happen to match their agent types.

A launcher tile now carries what it starts as data -- the harness it runs on and whether it stacks the `first` template are fields, not syllables spelled into a kind string ("intro-pi"). Nothing encodes them, so nothing has to decode them back out, which is where the wrong name was introduced. The harness a tile names reaches `mngr create --type` verbatim, a tile naming something mngr does not call itself is now a compile error, and a new harness is one row in the tile list.
