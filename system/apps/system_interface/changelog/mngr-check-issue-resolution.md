The shell's layout files hold each tab's identity in one place: the `params` dockview keeps on the panel (`{"kind": "instance", "address", "tabId", "lastFocusedMs"}`, or `{"kind": "launcher"}`). The separate `tabs` block a layout carried beside the dockview document is gone, and so is the frontend's hand-synced `panelParams` map: the dock reads what a panel shows from dockview's own panel list, learns it in each renderer's `init` (the `addPanel` path and the `fromJSON` path alike), and records a focus through `updateParameters`, so no bookkeeping has to be kept in step with dockview's panel lifecycle and a restore cannot bind a pane to the wrong instance. A layout file or a save body in the older shape is folded into the panels' params on read.

`tabId` in a panel's params is the page's id, not the panel's: the same instance docked in two views is one page under two panel ids, which is what lets a tab rebind (a terminal switching sessions) reach every view showing it.

The `layout` wire shape of `GET`/`POST /api/layouts/<view>` is `{"dockview", "device_kind", "updated_at"}`; `layout.py inspect` keeps reporting `tab_id` per panel, read from the params. The pure document editor, the prune and rebind paths, the referenced-instance sweep, and the inventory's `docked` list all read the params through one accessor.
