The workspace desktop says what failed in its own words, names apps as people know them, and offers the next step.

- Toasts and dialog lines name what failed ("Docs couldn't be opened.", "This window couldn't be closed.", "Couldn't move this shortcut, so it's back where it was."). A failure with no reason of its own ends "Try again." and offers Try again where pressing again could help; the shell's reason sits behind "See details". Apps are named by their display name everywhere, and a launch says "<App> couldn't open that."

- An agent by default: every failure that owes the person help (one the server did not explain, or wrote a sentence about without calling it expected), and every refusal that leaves the person stuck, offers "Ask an agent to fix this". It goes to the chat about the app when the failure is the app's (a launch it answered with an error, a failed quit, a message it refused), else to the main chat, worded as Imbue Studio telling the agent what the user was shown. No help is owed for a stale view the desktop fixes itself, for the last desktop's delete, for an app still starting, or for a request nothing answered. "Report a bug" is offered in the agent's place, never beside it, only where no agent can be asked: the ask would go through what failed (Chat itself), or no app that takes one is known. It opens Imbue Studio's bug report with the failure attached, wherever Imbue Studio opens one by the time it is drawn.

- Every ask the shell sends ("start it", "look at it", "finish it", "free up space") is one task: what the person was shown, the details, and what to do, said as Imbue Studio, never as the user. A full disk's "Ask an agent to free up space" tells the agent to free up space, in the main chat.

- The shell's refusals carry a sentence for people (`user_facing_message`, with `expected` where the refusal is ordinary operation that owes no help) and a `kind` where the desktop words them. An app the workspace has no record of "couldn't be found in this workspace, so nothing was opened." (the registry drops a broken row as it drops a removed app, so no removal is claimed, here or in a gone app's window), with "Remove shortcut" when a shortcut ran it; that and a launch path an app no longer offers have the desktop read its app list again. A request on a desktop another window deleted moves the window off it and says so ("... You're now on “Home”."), with Try again there. A change that could not be saved says so (a full disk offers an agent to free up space, and every failed save offers Try again).

- Shortcuts keep what their app and launch path were called (`shortcut_names.json`, beside the desktops file, which older shells still read), so one whose app is gone is named and labelled rather than shown by its internal name.

- A launch into an app that isn't running says what the app's window would ("Terminal is not running right now." with "Ask an agent to start it"; the note goes once the app runs again), and a launch that woke a stopped app that didn't come up says what its could-not-start page says (couldn't start, failed several times so not started again, or still starting).

- Once an app has taken a launch, a failed write of where its window is no longer fails the launch: the window shows the page, the launcher lets go of the text, and a note says so ("Your message was sent to Chat, but its window's position couldn't be saved, so it may move back after a reload.", or on a full disk "... this workspace is out of space, so window changes can't be saved." with an agent to free up space). When no window could be opened for it, the note says so, with "Open <App>" and an agent (on a full disk, only the agent to free up space), and no Try again, which would ask the app a second time. A launch that is not a send is named by its label ("“New doc” went through in Docs, but ...").

- The launcher and the phone's start sheet keep the typed text until a row runs, and show a failure under the field ("Couldn't send that to Chat, so your text is still in the box."), with "Open Chat" beside "Report a bug" when it is Chat itself that failed, so the person can send the text there. Text sent into Chat that is refused leaves Chat's window where it was.

- Until the startup read answers, the backdrop (and the solo and phone views) shows a spinner. When the workspace doesn't answer it, the spinner stays with "The workspace didn't answer. Still trying…", and the read is tried again on a timer (2 to 15 seconds) and whenever the socket reconnects, with Report a bug after about a minute. When the shell answers it with an error, the page goes to the shell's recovery page (below).

- A stopped app's window says it isn't running and offers to ask an agent to start it (or to report a bug, for Chat); its launcher row says the same. A window whose app couldn't be found says so and offers to close it.

- Pressed, each "Ask an agent to ..." button reads "Asking an agent…" and takes no second press until the chat is up; one that fails comes back, with the failure told in a note of its own that offers "Draft it in a chat" (the same request, left unsent in a chat's message box for the person to send) beside "Report a bug". Each leaves its note up.

- Delete is withheld from the only desktop in the overview, saying why. The wallpaper and theme choosers, the resource gauge's settings and the keyboard shortcuts dialog say what couldn't be changed (or loaded) with the reason behind "See details", and offer Try again (and, on a full disk, an agent to free up space). The theme gallery page says it couldn't load, with Try again, and an agent where a shell frames it. The avatar chooser retries its designs in place. A replaced desktop of the same name is named once. The update notice says how long ago the update was, names what a rollback restarts by display name, and, after a rollback that left the workspace's restart to an agent, says so in words with the restart command behind "See details" and offers an agent to finish it.

- A stopped app's page says "Starting <name>..." without guessing a cause; one that couldn't start waits for Try again instead of reloading on its own (with no Try again once it has failed to start several times in the last few minutes, when a press could not help), offers an agent to look at it, asked in the chat about the app (a refused ask offers "Draft it in a chat" and "Report a bug"), and shows the end of the program's error log behind "See details" (no "See details" when the log can't be read).

- The shell's recovery page, served when its interface needs to be rebuilt and when its desktops couldn't be loaded, offers "Ask an agent to fix this", which asks in the main chat and shows it. For the desktops, the page reads them again itself and shows the shell's own failure behind "See details", says so when the workspace is out of space (with "Ask an agent to free up space", which tells the agent to), offers Reload, and goes back to the desktop on its own once they load; it offers no "Report a bug" for now. Until an ask fails, the command (behind `/assist`, carrying the button's message) and a working terminal session are behind "See details"; once one fails, the page says "You can start one yourself" and shows the command, Copy and the terminal in the open, keeping only the failure's reason behind "See details". Its launches go through `POST /api/recovery/launch`. A page load that fails shows a page of ours with Try again instead of raw JSON.
