Every desktop is shared, and each signed-in visitor gets a desktop of their own.

- The `sharing` mode (`shared` or `personal`) is gone from desktops, the settings dialog, the settings route, and the desktop record; a `desktops.json` that still carries the key is read with it dropped. A window holds a resource for everyone, so a private desktop was never private.

- A shell page now posts its arrival (`POST /api/clients/<client_id>/arrive`) before reading the desktops, and lands where the shell answers. The owner and any request without a user id land as before. A visiting user (the `X-Imbue-Identity` header's `owner` false with a `user_id`) landing on the owner's desktop would open and close the owner's windows, so on their first arrival the shell makes them a desktop named after them (display name, else the email's local part, else `Guest`, made unique), with the next free glyph and its colour, seeded from the first desktop: its shortcuts, its wallpaper, and a new window at the path of each settled window open there (one still mid-launch is skipped).

- The shell remembers each visitor's desktop in `data/.state/system_interface/users.json` and the user on each client record (`clients.json` gains `user_id`, as does `GET /api/clients`). Later clients of the same user land on that desktop; a returning client keeps the desktop it was on. If the desktop was deleted meanwhile, the next arrival seeds another and the page shows a notice naming the deleted one.

- The presence strip from the share identity work is a tray widget (`data-tray-widget="presence"`) beside the Desktops widget rather than a fixed overlay in the corner of the window, and the `presence_updated` push reaches the desktop store through the shell socket like every other message. The identity header's record and parser moved to `shell/identity.py`, shared by presence and the arrival.
