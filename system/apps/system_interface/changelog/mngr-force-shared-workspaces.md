Every desktop is shared, and each signed-in visitor gets a desktop of their own.

- The `sharing` mode (`shared` or `personal`) is gone from desktops, the settings dialog, the settings route, and the desktop record; a `desktops.json` that still carries the key is read with it dropped. A window holds a resource for everyone, so a private desktop was never private.

- A shell page now posts its arrival (`POST /api/clients/<client_id>/arrive`) before reading the desktops, and lands where the shell answers. The owner and any request without a user id land as before. A visiting user (the `X-Imbue-Identity` header's `owner` false with a `user_id`) landing on the owner's desktop would open and close the owner's windows, so on their first arrival the shell makes them a desktop named after them (display name, else the email's local part, else `Guest`, made unique), with the next free glyph and its colour, seeded from the first desktop: its shortcuts, its wallpaper, and a new window at the path of each settled window open there (one still mid-launch is skipped).

- The shell remembers each visitor's desktop in `data/.state/system_interface/users.json` and the user on each client record (`clients.json` gains `user_id`, as does `GET /api/clients`). Later clients of the same user land on that desktop; a returning client keeps the desktop it was on. If the desktop was deleted meanwhile, the next arrival seeds another and the page shows a notice naming the deleted one.

- The presence strip from the share identity work is a tray widget (`data-tray-widget="presence"`) beside the Desktops widget rather than a fixed overlay in the corner of the window, and the `presence_updated` push reaches the desktop store through the shell socket like every other message. The identity header's record and parser moved to `shell/identity.py`, shared by presence and the arrival.

- Presence is now mtime based. Each user has one file, `data/.state/presence/users/<user_id>.json`, holding their identity snapshot (`user_id`, `email`, `owner`, `first_seen`); a heartbeat touches the file's mtime instead of rewriting it, a user is connected while the mtime is within 70 seconds, and the mtime is their last seen. Files are never removed, so whoever is gone is still the record of who was last here. The per-tab session id, the `sessions` map, `POST /api/presence/leave`, the page's leave beacon, and the `data/.state/presence/events.jsonl` join/leave log are gone; the heartbeat takes no body. A sweep every 10 seconds broadcasts `presence_updated` when someone's heartbeats have stopped, so every window learns of a silent departure. A present user on the wire is `user_id`, `email`, `display_name`, `profile_picture_url`, `owner`, `first_seen`, `last_seen` (no `session_count`).

- Display names and profile pictures come from imbue_cloud, not the identity header. The `X-Imbue-Identity` header is read for `owner`, `user_id`, and `email` only (a header that still carries `display_name` or `avatar_url` is read the same way). The shell fetches `GET {SHARE_BROKER_URL}/users/<user_id>/profile` from the broker `data/.secrets/share.env` names, with a 2 second bound, and caches each answer -- and each failure -- for 5 minutes under `data/.state/presence/profiles/<user_id>.json`; the presence route, the `presence_updated` push, and the tray get `display_name` and `profile_picture_url` from there, and a visitor's desktop is named after their profile's display name (else their email's local part, else `Guest`) on their first arrival, the profile resolved before the arrival takes the state lock. A workspace that is not shared, or whose connector is unreachable, shows no names and names desktops by email; no request fails or hangs on a profile.

- The shell page boots from REST. After posting its arrival it reads `GET /api/inventory` once, taking the desktops, the apps, and its own client record from that one answer, in place of the separate desktops and clients reads; the apps no longer wait on the WebSocket's first `apps_updated`, so a shortcut is never drawn for an app the page does not know and a desktop is complete even when the socket is slow to connect (the socket still sends `apps_updated` on every connect, for the resync). Until the inventory answers, a shortcut whose app the page cannot look up draws faint as "Connecting to the workspace..." (`data-connecting="true"`) and running it says "Still connecting to the workspace" instead of that the app is not registered; once the apps are known, a genuinely missing app is reported as not registered, as before.

- The "Refresh my sign-in" link is gone from the Presence tray widget (the gateway's identity refresh route it pointed at is removed with it); nothing in the shell links to a sign-in.

- The Presence tray widget is drawn only while two or more users are connected (one is just you), everyone else first and the requester's own entry last, with an accent ring, "(you)" on its hover text, and `data-presence-self="true"`; the own entry is the one whose `user_id` the heartbeat's answer names.

- A user's picture is their "profile picture", not their "avatar" (the avatar is the workspace's creature). The connector's public profile route answers `{"user_id", "display_name", "profile_picture_url"}`, and the shell's `UserProfile`, the profile cache under `data/.state/presence/profiles/`, the presence route, and the `presence_updated` push carry `profile_picture_url` in place of `avatar_url`.
