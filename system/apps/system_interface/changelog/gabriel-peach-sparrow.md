The system interface answers the Mind app's new `minds:focus-chat` embed message (sent when the user clicks a chat's notification in the app) by showing the chat its `chatId` names. A window already showing that chat is raised, switching desktops when it is on another one; otherwise this viewer's pinned chat window is pointed at the chat, the way the launcher's draft is, so the chat lands where they already read chats; with no pinned chat window to take it, the chat opens in a window of its own. A subagent view of the chat counts as showing it. The shell names no app here: the app that holds chats is the one declaring a launch path that takes a `message`, so a workspace whose apps cannot start a chat simply ignores the ask. Once it has read its desktops and apps, the workspace tells the app it is listening, so an ask that arrives while the page is still loading is delivered when the page can act on it rather than lost.
