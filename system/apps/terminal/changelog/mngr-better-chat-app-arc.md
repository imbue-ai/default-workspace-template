The terminal is a Python package now (phase 3 of the workspace app model, `docs/system/blueprint/workspace-app-model/`), installed as its own uv tool like every Python app; nothing changes from the user's seat: the same tabs, titles, session switching, renaming, and reattach after a container restart.

- `terminal-app` (`src/terminal_app/main.py`) replaces `run_ttyd.sh` as the `terminal` supervisord program: it writes the ttyd dispatch scripts (moved verbatim into `dispatch.py`) into `data/.state/terminal/commands/` instead of the mngr agent state directory, installs the vendored OSC 52 web client (a missing, truncated, or corrupt archive leaves ttyd on its stock client, with a warning), writes the `server_registered` discovery event, and runs ttyd on 7681 as the child of the `app_instances` sidecar launcher.

- The instances API is served on `127.0.0.1:7682` (`sessions.py`, `TmuxSessionSource`): every non-`mngr-` tmux session lists as `idle`, every terminal the new store `data/.apps/terminal/instances.json` remembers but tmux no longer has lists as `stopped`, `new` allocates the lowest free `terminal-<N>` (with an optional `workdir` carried in the instance URL), delete kills the session, and rename follows the workspace's naming rule: the typed title is kept and the session is renamed to its canonical true name (`My Build` becomes `My-Build`).

- The tmux hooks post to the app's own `POST /tmux-hook` (`hooks.py`) instead of the shell: a session switch or rename re-points the affected tabs through the shell's generic tab route, nudges the shell (a switch may be the attach that created a session, so the list is refetched rather than left to the 30-second sweep) and, until phase 7, is forwarded to the shell's `/api/terminals/notify` so live tab titles keep working; the route reads its body and answers errors (a malformed body, a tmux failure) through the library's shared parser and handler, so they get the same `{"detail"}` bodies as the instances routes. `notify_terminal_session.py` moved into `bin/`; a symlink at the old path keeps tmux servers started before the move working.

- The store of remembered terminals lives at `data/.apps/terminal/instances.json` (app data, where every app keeps its instance records; `terminal-app --store` overrides it) rather than beside the dispatch scripts under `data/.state/terminal/`, which now holds only machine state (contracts.md section 17, added in phase 4).
