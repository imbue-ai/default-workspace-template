The pty frame reports typing to the shell's presence (the mngr repo's `specs/multiplayer-refinements/spec.md`, section 4.3): the terminal's xterm lives in a nested frame on the pty's origin, whose key and pointer events never reached the wrapper page that binds the app contract, so a person typing in a terminal read as idle. The pty page now posts a throttled `shell:input` to the wrapper, which hands it up to the shell as the chat root hands up its nested pages'.

A terminal viewed on somebody else's desktop attaches to its tmux session as a viewer from the first moment (the multiplayer spec, section 8.3): a framed wrapper points its pty frame only once the shell's handshake has said whether the window is viewed (attaching plainly after a two-second grace when no handshake comes; an unframed wrapper points at once), and the session script attaches read-only and as a client tmux never sizes the window by (`tmux attach -r -f ignore-size`), so looking at a terminal neither types into nor resizes its owner's. The pty path always carries the workdir argument, so the viewer marker is a fixed third argument, and the viewer attach names its session exactly (`-t =<name>`), so a viewer of a lost `terminal-1` is refused rather than shown `terminal-10`. The agent dispatch script (`agent.sh <name> [view]`, the chat's terminal back face) takes the same viewer marker after the agent name.
