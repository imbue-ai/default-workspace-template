The pty frame reports typing to the shell's presence (the mngr repo's `specs/multiplayer-refinements/spec.md`, section 4.3): the terminal's xterm lives in a nested frame on the pty's origin, whose key and pointer events never reached the wrapper page that binds the app contract, so a person typing in a terminal read as idle. The pty page now posts a throttled `shell:input` to the wrapper, which hands it up to the shell as the chat root hands up its nested pages'.

A terminal viewed on somebody else's desktop attaches to its session as a viewer: the wrapper frames the pty with a viewer argument when the shell's handshake says the window is viewed, and the session script attaches read-only and as a client tmux never sizes the window by (`tmux attach -r -f ignore-size`), so looking at a terminal neither types into nor resizes its owner's. The pty path always carries the workdir argument now, so the viewer marker is a fixed third argument.
