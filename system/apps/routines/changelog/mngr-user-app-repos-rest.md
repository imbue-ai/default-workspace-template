A routine an app owns now says so on its page: it names the app it is part of, says that only its schedule and its on/off switch can be changed here, and no longer offers Remove, which the server always refused. While the user's own schedule is in place of the app's, the page shows the app's schedule beside it and offers "Back to the app's schedule", which drops the user's through the new `DELETE /api/routines/<id>/schedule` (409 for a routine no app owns). The list groups such a routine under the app whose directory holds its file, whatever its definition names. Each row the API answers carries `owning_app`, `is_schedule_only`, `has_schedule_override` and `app_schedule_text`, which are the routines library's own row fields.
