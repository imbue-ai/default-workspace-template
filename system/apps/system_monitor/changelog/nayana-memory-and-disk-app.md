A new built-in app, Memory & disk (`system-monitor`): one page showing how much memory and disk the workspace is using, which chats, code checkers, apps, and workspace programs hold the memory, and which programs the memory guard stopped in the last 24 hours, each described in plain words with its exact command behind Details.

- It started as a user app built in a cloud workspace and keeps that app's page and readers. As a built-in it serves on 8040 (below the 8080 the build-app scaffold starts handing out), runs in its own memory band, sits last in the desktop's seeded shortcuts and the launcher (`launcher_rank = 50`), and declares `system = true`, so the Share tab lists it under its System group.
- A chat on any agent type (claude, codex, pi) counts under Chats with everything it started: its main processes come from oom_priority's agent-pid registry, with claude's command line as the fallback.
- Memory per row is exact where the kernel has `smaps_rollup`: each row is its programs' private memory, memory several programs share is one Shared row, the files in the scratch space (`/tmp`, a tmpfs) are a Temporary files row with its size limit and an info popup, and the rest is a System row, together adding up to the memory in use. Where it has none (gVisor) the rows fall back to resident sizes scaled down by one factor, and the page says they are approximate.
- The memory graph covers the last 10 minutes on a 0 to 100 percent scale, draws readings the app itself records every 5 seconds while it runs (so the line stays whole while a window is hidden or reloaded), and leaves blank any stretch with no readings.
- The memory and disk bars label their used share on the filled side and their free amount on the empty side.
- From 80% memory used, the bar and a note turn orange: the note gives the percentage, says the memory guard stops programs once less than 10% is free, and names the largest kind of memory the user can free (chats, their apps, code checkers, or temporary files) with what frees it. Under 80% the note appears only to report programs stopped in the last 24 hours.
- The app keeps its own overhead low: it asks supervisord over its control socket with no `supervisorctl` process per refresh, every open window shares one snapshot taken at most every 4 seconds, the stop history and the guard's log are read only from their last 256 KB and 1 MB, and only again once they change (on a stop), and a hidden window stops polling. One refresh costs about 25 ms of CPU (it was about 80).
- The page takes its colours, type sizes, fonts, radii, and tooltip style from the workspace's design tokens (`system/libs/workspace_ui/src/base.css`), copied by name since the page has no build step.
- The icon is the gauge it shipped with, now inked cream on a terracotta tile per `docs/system/app-icons.md`. The exported glyph named no fill, so it drew as an empty tile.
- The code is split by topic: `memory` (totals, disk, the graph's history), `programs` (the running programs and who they belong to), `usage` (the breakdown's rows), `stops` (what the guard stopped), and `stats` (the shared snapshot). It reuses oom_priority's agent-pid registry, ledger path and headroom-file path, and app_manifest's shell module paths.
- Tests cover the /proc and smaps_rollup readers, the grouping, the exact breakdown and the scaled fallback, the temporary files row, the pairing of the guard's records with its log, the supervisord socket (and that its path matches `system/supervisord.conf`), the shared snapshot, the memory history, and the routes.
