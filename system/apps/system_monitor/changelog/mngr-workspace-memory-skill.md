On gVisor, which every cloud workspace runs under, the memory breakdown is now exact instead of approximate. With no `smaps_rollup` there, each process's anonymous memory and the shared memory segments come from `/proc/<pid>/smaps`, each segment counted once in the Shared row. The rows used to be resident sizes scaled by one factor, and gVisor's resident size counts every file a process maps, so a program with many processes (Chromium maps its binary into each one) showed several times what it holds.
