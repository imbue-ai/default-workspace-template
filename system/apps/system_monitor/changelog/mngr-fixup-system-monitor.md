Memory & disk becomes System Monitor: the app adds CPU and gains a view per resource. The overview shows three tiles (CPU as a share of the cores, memory and disk as a share of their totals, with the last 10 minutes under the first two), the breakdown of what is using the workspace with CPU and memory columns, and the recent events (programs the memory guard stopped, and busy stretches of CPU above 90% with the chats and programs that caused them). The CPU view (`/cpu`) has the number of processes running, a chart over 10 minutes, an hour or a day, the breakdown sorted by share, and the busy stretches; the Memory view (`/memory`) is the previous page's content with the guard's 90% mark drawn in; the Disk view (`/disk`) shows the disk, the state of the backups (from the backup service's events, with a link to its README), and measures what is on the disk only when asked, saying which rows it could not measure (or that the walk failed, with a way to try again).

The graphs now come from the `resource_sampler` program (`system/services/oom_priority`), so they stay whole across the app stopping between windows; the app no longer samples memory itself. New routes: `/api/history?span=1h|24h`, `/api/disk`, and `POST /api/disk/scan`; `/api/stats` carries `cpu`, `events`, both graphs' `history`, and a `cpu` share on every breakdown row.

The breakdown now adds up: a group's memory is its programs' anonymous memory (what stopping them frees), the Shared row is the shared memory segments they map, the System row holds the rest in both accounting modes, and its CPU is what the other rows fall short of the tile. The Workspace row lists the workspace's own programs (the chat app, the desktop, each service by a plain name, the boot-time environment setup as "Environment setup", and what no program started by its command), and rows with nothing under them are hidden. Every chat, code checker and user app has a Stop button (an "x" on hover, always on touch screens) that asks before it stops the chat through the chat app, the checkers by signal, or the app through supervisord (`POST /api/stop`; an app that quit on its own since the page last refreshed counts as quit); the workspace's own programs have none. The disk view says the figure is the machine's whole disk, puts what is using it above the backups, and its walk lists the workspace's folders (with hints for `.venv`, `.git` and the like), each package cache, and the system software behind "Everything else".

Inside the app, the agent records are read by one `programs.chats` reader (the separate `chat_names` and `chat_ids` readers are gone), a Stop request's kind is dispatched with `match`, and the API document's `usage_mode` description names the accounting as it now is (anonymous memory, a System row in both modes).

The Workspace row names the agent observer "Agent manager" and the owner-exec daemon "Web access", and splits what no program started into "SSH access" (sshd and its sessions), "Internal system" (tini, the bootstrap and its uv wrapper, supervisord, the services agent's tmux and shell) and "Other".
