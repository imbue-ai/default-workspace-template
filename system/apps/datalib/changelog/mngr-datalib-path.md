The Datalib app now serves `data/.skills/datalib/Default`: the skill's folder is a libraries folder laid out like the desktop app's `~/Datalib`, with one folder per library, and the app serves the `Default` one. The launcher moves a store that an earlier workspace wrote at `data/.skills/datalib` itself into `Default` before it reads the token, with two atomic renames through a staging sibling (`data/.skills/datalib.moving-to-Default`), and finishes the move on the next start if it was interrupted between them. It follows the desktop app's rules for moving a library: only a store at the real libraries folder is moved (the library is known by where it is on disk, whatever spelling of its path the launcher is given), a store a datalib process still holds is left for the next start, and a top-level `data_root` in the moved `config.toml` that names the old folder is dropped. A folder that holds a store of its own and a non-empty `Default` makes the launcher refuse to start, naming both. The token's path is now `data/.skills/datalib/Default/system/api-token`.
