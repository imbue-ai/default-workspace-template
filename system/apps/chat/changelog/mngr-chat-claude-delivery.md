When the chat cannot tell whether a message reached the agent, it sends it again once and says so under the message, and a message still unconfirmed after that gets a notice of its own; a message sent to a Claude chat while it is still starting is no longer reported as possibly unsent, or lost when its process exits.

- A message mngr could not confirm reaching the agent (`submission_unconfirmed`), or whose send failed in a way mngr could not classify (`unknown`), is sent again once, automatically, where the agent is. When that lands, the message shows as sent, with a small "Sent again" line under it and a "?" explaining that the chat could not confirm the first copy arrived, so the agent may see it twice; if the first copy did arrive too, its second copy folds into that line rather than showing as a second bubble. The message route answers such a send `{"status": "resent"}`. Only when the second send cannot be confirmed either does the chat stop and show "Couldn't confirm your message arrived": the agent may already have it, Cancel and Send again are offered without Force or mngr's diagnostic text, the message goes back in the composer, and it comes back out once the agent's turn for it shows up. A message whose send mngr reports typed nothing (`agent_not_found`) is looked up again and sent once more.

- A message sent to an agent not accepting messages yet (`not_ready`), or on a host too loaded to read (`state_unknown`), is tried again after 1, 2 and 4 seconds before it shows a failure, and one for an agent that was down and would not start (`agent_unreachable`) is tried once more. Nothing was typed, so these tries cannot double it. Each `not_ready` try includes mngr's 30-second wait for the input box, so those can take about two minutes.

- A message sent to a Claude chat while it is still starting is no longer reported as possibly unsent. Claude takes a message at once but writes it down only after its startup hooks finish; mngr now reads Claude's screen when it has waited out its window, so a message Claude holds counts as sent, and one Claude never took is cleared from its input box and sent again automatically, once, where the agent is (`not_submitted`). An unconfirmed send now remains only where the screen cannot settle one: pi and opencode chats, and the rare Claude screen that shows neither.

- A message a Claude chat showed but had not written down yet (while its startup hooks run) is no longer lost when the agent's process exits before it does, from a crash or a kill. The chat reads the agent's final transcript and sends again, once, each delivered message sent after the last message it wrote down, restarting the agent to do so. Nothing is sent again after a deliberate stop, after Stop takes the turn back, to a chat that is switching or has moved on, for a message older than half an hour, or for a message that was itself such a resend.
