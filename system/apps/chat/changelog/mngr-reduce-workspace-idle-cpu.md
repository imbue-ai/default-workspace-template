The statusline conformance tests now pin the trimmed `claude_status_line.sh`. The script prints nothing, spawns no command besides `jq` (and `mv` when the state changes), and leaves `model_state.json` untouched when a run reports the same model, effort and fast mode.

The chat app no longer launches `mngr autocompact run` while proactive compaction is off. It used to launch it once a minute for every running chat, although with the mode off (the default, and the setting on every workspace) the command can only do nothing. Each launch is a full mngr start costing about 2.4 seconds of CPU, so on a 4-vCPU workspace with three running chats that was about a fifth of a core. The sweep now reads `plugins.autocompact.mode` through the same in-process mngr config the app already loads, and skips the launch unless it is `proactive_timer`.

When it is on, one launch covers every running chat instead of one launch per chat. If mngr rejects that launch (a chat stopped since it was listed fails the whole command), each chat is retried on its own, so one stopped chat never keeps the rest from being checked. A launch that times out, crashes, or cannot start is not retried per chat, since it would fail the same way for each.

The chat app now carries the autocompact plugin, so with `plugins.autocompact.mode` set to `on_next_prompt`, a message sent from the chat compacts a stale agent before it is delivered, as `mngr message` already did. Before, that mode never applied to messages sent from the chat. With the mode off (the default) nothing changes.
