The Claude model picker's Opus entry now selects Claude Opus 5.5: the `opus[1m]` alias it switches with resolves to `claude-opus-5-5` on the new 2.1.280 pin, so the entry is labelled "Opus 5.5" and its `harness_reported_model_id` moves to `claude-opus-5-5`, which is what the live model-state read is matched against. Opus 5 (`claude-opus-5`) stays in the catalog as a hidden option so a chat created on the previous pin still shows its name instead of falling through to the shrug case; it is ordered after the offered Opus 5.5 key, because the prefix pass would otherwise let the shorter key claim the new id. Fast mode is declared on both, following the `fast_mode` capability the binary's own model table gives Opus 5.5, Opus 5 and Opus 4.8.

The catalog's three binary-derived facts -- what each alias resolves to, what each model is called, and which models can go fast -- are now pinned against a fixture lifted from Claude Code's own baked-in model catalog (`baked_model_catalog_v2_1_280.json`) rather than transcribed from release notes. A pin bump that repoints an alias, renames a model or changes its fast support now fails a test naming the specific disagreement, which is the failure this release would otherwise have shipped silently: the picker would have offered a switch labelled "Opus 5" that landed on Opus 5.5.
