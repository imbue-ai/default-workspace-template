Phase 9 of the chat-agent split (`docs/system/blueprint/chat-agent-split/`).

- A switch that keeps the agent on a new account (a rebind) can now change the model too. Before, a rebind refused a model pick, so changing account and model meant switching and then picking from the model bar, or interrupting the first turn. Pressing the account still arms the switch at once. The strip above the composer now offers Change, and the model bar's card a Model row, for a rebind as for a handoff. Both open the switch dialog, whose rebind variant ("Switch to Anthropic 2 (Claude Code)?") starts its picker on "Keep the current model". The strip and the model bar name the pick. Reopening the dialog from Change starts from the armed pick. The dialog offers no picker for Antigravity, whose model is changed from the agent's terminal, and says so there instead of pointing at the model bar, so no switch arms a pick that cannot be applied, and a new chat started from the dialog carries none either. The server rejects such a pick at once too, and its account model options route offers nothing for Antigravity.

- `POST /api/chats/<chat-id>/handoff` accepts `model` for a rebind. The pick is applied once the agent is back on the new account and before the message it was switched with. `mngr start` does not wait for the harness the way a create does, so a switch the harness refuses is tried again for up to 30 seconds while the agent comes up. A pick outside the agent's options fails at once, except while a codex agent's daemon has not answered with the new account's options yet: the pick is then tried again too. A pick that cannot land leaves the chat in the failed phase with `failed_step: model` ("Could not set the model on Claude Code"), and the retry reruns only the pick when the restart already landed.

- Each harness now has one account-binding class (`harnesses/<harness>/account_binding.py`), registered on `HarnessSpec` as `binding_class` like the watcher, tracker, and resolver classes. It owns what differs per harness when an agent is bound to an account: the scoping variable, the files a re-auth clears, the account files seeded at sign-in, the `mngr create` arguments, the workspace's create defaults, the rebind's edit, and the move of session files during a rebind. `harnesses/account_scope.py` is gone, `harnesses/binding.py` keeps only the account resolution and the rebind set, and the rebind runner no longer checks which harness it is rebinding. Behavior is unchanged.

- The model bar no longer flickers through other models while a switch is being carried out. Before, the chip gave up the picked model the moment the backend flipped the chat's identity -- a rebind relabels the agent with the new account partway through its restart, and a handoff's successor becomes the chat's agent before it has taken the pick -- and fell back to the pushed live choice, which shows the account the chat is leaving and then whatever model the new account last ran before settling on the pick. Rebinding twice in a row walked the chip through both. Now the chip reads the picked model from the moment it is armed until the harness reports it, and a page reloaded mid-switch reads the pick off the chat rather than the live choice: `handoff.model_pick` rides the chat snapshot. A switch that failed is the exception: it never applied the pick, so the chip drops back to the model the agent is really on while the failure notice stands.

- The rebind record's `claude_sessions_config_dir` is now the harness-neutral `sessions_dir`. A record written under the old name still reads.

- The switch dialog now offers a model for a Codex account the chat has not run on. Before, a Codex account's models were read off an existing agent of that account, so switching between two Codex accounts offered no choice at all when the destination had never run one: the dialog said the agent would keep its current model and left it there, while switching from Claude to Codex, or between two Claude accounts, did offer a picker. The account is now asked for its own models instead -- a short-lived `codex app-server` bound to the account folder, one `model/list`, no agent and no conversation. That also fixes a quieter half of the same bug: two accounts of one provider can be on different subscriptions and genuinely offer different models, so an answer borrowed from another account both hid models the destination has and offered ones it cannot run, which a rebind then failed on at its model step. A successful read is kept beside the account's credential, so the picker still has a set when Codex cannot be reached at all; an account with neither offers only the default.

- `HarnessCatalog.popups` is required in the frontend, like `label`.
