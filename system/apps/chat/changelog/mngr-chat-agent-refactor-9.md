Phase 9 of the chat-agent split (`docs/system/blueprint/chat-agent-split/`).

- A switch that keeps the agent on a new account (a rebind) can now change the model too. Before, a rebind refused a model pick, so changing account and model meant switching and then picking from the model bar, or interrupting the first turn. Pressing the account still arms the switch at once. The strip above the composer now offers Change, and the model bar's card a Model row, for a rebind as for a handoff. Both open the switch dialog, whose rebind variant ("Switch to Anthropic 2 (Claude Code)?") starts its picker on "Keep the current model". The strip and the model bar name the pick. Reopening the dialog from Change starts from the armed pick. The dialog offers no picker for Antigravity, whose model is changed from the agent's terminal, so no switch arms a pick that cannot be applied.

- `POST /api/chats/<chat-id>/handoff` accepts `model` for a rebind. The pick is applied once the agent is back on the new account and before the message it was switched with. `mngr start` does not wait for the harness the way a create does, so a switch the harness refuses is tried again for up to 30 seconds while the agent comes up. A pick outside the agent's options fails at once, except while a codex agent's daemon has not answered with the new account's options yet: the pick is then tried again too. A pick that cannot land leaves the chat in the failed phase with `failed_step: model` ("Could not set the model on Claude Code"), and the retry reruns only the pick when the restart already landed.

- Each harness now has one account-binding class (`harnesses/<harness>/account_binding.py`), registered on `HarnessSpec` as `binding_class` like the watcher, tracker, and resolver classes. It owns what differs per harness when an agent is bound to an account: the scoping variable, the account files seeded at sign-in, the `mngr create` arguments, the workspace's create defaults, the rebind's edit, and the move of session files during a rebind. `harnesses/account_scope.py` is gone, `harnesses/binding.py` keeps only the account resolution and the rebind set, and the rebind runner no longer checks which harness it is rebinding. Behavior is unchanged.

- The rebind record's `claude_sessions_config_dir` is now the harness-neutral `sessions_dir`. A record written under the old name still reads.

- `HarnessCatalog.popups` is required in the frontend, like `label`.
