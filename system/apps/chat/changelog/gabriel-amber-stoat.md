Claude Code failures now render as failures in the chat transcript.

Before, a failed turn was recognised by matching its wording for `API Error: <status>`, which most of Claude Code's failures never say. "You've hit your monthly spend limit", "You've hit your session limit", "You're out of usage credits", "Your computer went to sleep mid-response", "Can't reach the API server" and the rest arrived styled as ordinary assistant prose -- reading as if the agent had said them. Across the transcripts on one machine, 160 of 166 recorded failures rendered that way.

Now the chat reads the stamp Claude Code puts on the record itself (`isApiErrorMessage`, the HTTP status, and its own error kind), so the failure is shown in red whatever its wording. Two credential dead ends that the old prose matching also missed -- an OAuth session that expired and could not be refreshed, and `Login expired - Please run /login` -- now get the sign-in action under them. A failure Claude Code attributes to a server but that carries no 5xx status is shown without a cause: it uses that label for failures that never reached a server, so a sleeping laptop or a DNS failure is not blamed on the model provider.
