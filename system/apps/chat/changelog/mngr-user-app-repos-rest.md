The welcome chat's seed (`POST /api/chats/seed`) takes an optional `first_message`, which the chat sends as the user's own when its first agent launches: at once when a provider account is signed in, otherwise when the sign-in launches the chat. A workspace created from an app is seeded with `/install-app <url>` this way. The message is kept in a file beside the seed, so it survives a restart of the app, and is sent once; a first message the user types before the launch follows it. A message that waited while a seeded chat's agent was being created now carries the seeded conversation when the launch left it pending, as a message sent afterwards does. A seed without the field behaves as before, and chat records keep their shape, so an earlier chat app still reads every chat.

A new `real_claude` test, `test_claude_skill_discovery.py`, holds the pinned Claude Code to listing a skill whose entry under `.agents/skills/` is a symlink into an app's own directory, the form `app-install` generates, and to not listing a skill left in an app with no link. Like the other `real_claude` tests it does not run in CI.
