The welcome chat's seed (`POST /api/chats/seed`) takes an optional `first_message`, which the chat sends as the user's own when its first agent launches: at once when a provider account is signed in, otherwise when the sign-in launches the chat. A workspace created from an app is seeded with `/install-app <url>` this way. The message is kept on the chat's record, so it survives a restart of the app, and is sent once; a first message the user types before the launch follows it. A seed without the field behaves as before. The chat record's on-disk version is now 3.
