The welcome chat's seed (`POST /api/chats/seed`) takes an optional `first_message`, which the chat sends as the user's own when its first agent launches: at once when a provider account is signed in, otherwise when the sign-in launches the chat. A workspace created from an app is seeded with `/install-app <url>` this way. The message is kept in a file beside the seed, so it survives a restart of the app, and is sent once; a first message the user types before the launch follows it. A first message that is a slash command is sent as typed, and the seeded conversation goes with the next message instead. A seed without the field behaves as before, and chat records keep their shape, so an earlier chat app still reads every chat.

A first-run seed (`is_first_run`) may carry turns and a first message too, which is what the Imbue Studio app sends for a workspace it created with an app. The turns follow the first-run welcome instead of being ignored, with the start suggestions under the last of them. The first message is not sent by the seed while the provider page is owed: the launch made as the owner leaves that page sends it, or the sign-in's when they left with nothing connected. It moves the first conversation's tree as a message the user sent would, so `/install-app <url>` leaves the tree at its start.

A new `real_claude` test, `test_claude_skill_discovery.py`, holds the pinned Claude Code to listing a skill whose entry under `.agents/skills/` is a symlink into an app's own directory, the form `app-install` generates, and to not listing a skill left in an app with no link. Like the other `real_claude` tests it does not run in CI.
