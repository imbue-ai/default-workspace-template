The chat's `new` action takes an optional `message`: the first message the chat sends once it is running, delivered by `mngr create --message` after the harness signals readiness (the path `/welcome` takes). A chat minted while nothing is signed in keeps the message on its provisional record and sends it when the sign-in launches it; a launch that names a reserved `agent_id` and another `message` is refused, like one that renames or refiles it. A seeded chat does not claim the workspace's first chat, so `/welcome` still greets the first plain chat. `POST /api/agents/create-chat` takes the same optional `message`. The manifest declares `launcher_rank = 10`, which puts the chat tile first among the New Tab page's "Open new" tiles.

A tool call that one of the workspace's hooks refused (Claude Code reports it as the call's error, `PreToolUse:Bash hook error: ...`) no longer shows the hook's message in red under its collapsed row; the text still appears when the row is expanded.
