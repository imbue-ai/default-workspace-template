`POST /api/chats/create` no longer takes `is_installation_check_skipped`, and a provisional chat no longer carries it. The chat app used it to skip claude's version check for the update chat, because a claude that no longer matched its pin failed the create. The workspace's settings now set `version_mismatch = "WARN"` for claude and the other pinned harnesses, so a mismatch only logs a warning and every create goes ahead without the flag. A request that still sends the field is now refused as an unknown field. This needs an mngr that has the `version_mismatch` field.
