The onboarding conversation continues inside the workspace as its first chat, and every chat starts fast for a configurable number of turns.

- `POST /api/chats/seed` opens a chat on turns that happened before the workspace existed (`chat_seed.py`). The turns are written as the chat's first segment under `data/.apps/chat/chats/<chat-id>/seed.jsonl` and read through a `seed` pseudo-harness, the chat's record names the seed as its first member, and the chat is listed as a provisional chat in the new `awaiting_first_send` phase with its transcript on the page and a composer under it. The user's first message launches the chat's first real agent, which joins the record as the seed's successor (`chat_id` and `chat_seq` labels, like a handoff's); the provider chooser opens at that send if nothing is signed in. A later handoff's prompt lists the chat's agents as predecessors, not the seed. A restart of the app restores seeded chats still awaiting their first send from their records (and re-requests their tab if no client saw it); discarding one drops the record with it. A title with no usable characters answers 400 and one already taken 409, as a launch's requested name would.

- Every chat that starts with no message is greeted: the `welcome` create template replaces the one-time `first` template and its first-chat claim (`claim_first_chat` is gone from `accounts.py`), so `/welcome` runs each time and the skill varies what it says.

- Fast mode is a workspace setting: `GET`/`PUT /api/settings` (`chat_settings.py`, `data/.apps/chat/settings.json`) hold `fast_mode_turn_limit` (default 5; 0 launches chats at standard speed) and whether the one-time notice has been shown. Every chat launches with the `fast` create template when the limit is above zero, the page turns fast mode off once the user has taken that many turns (the seed's turns do not count), shows a short notice over the model bar the first time it does so in the workspace, and the model picker shows the number beside the fast toggle for editing (a settings load that fails is warned about and answered with the defaults, and asked again only after a short delay rather than on every redraw). The fast-mode prompt modal and `POST /api/chats/<id>/fast-mode-answered` are gone.
