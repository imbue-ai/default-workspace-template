The onboarding conversation continues inside the workspace as its first chat, and every chat starts fast for a configurable number of turns.

- `POST /api/chats/seed` opens a chat on turns that happened before the workspace existed (`chat_seed.py`). The turns are written as the chat's first segment under `data/.apps/chat/chats/<chat-id>/seed.jsonl` and read through a `seed` pseudo-harness, the chat's record names the seed as its first member, and the chat is listed as a provisional chat in the new `awaiting_first_send` phase with its transcript on the page and a composer under it. The user's first message launches the chat's first real agent, which is named on the record as the seed's successor before its create runs (`chat_id` and `chat_seq` labels, like a handoff's), so mngr's listing of it mid-create shows the chat under the seed's id and never a second chat beside it; a create that fails takes it back off the record and destroys the agent if mngr had already made it. The provider chooser opens at that send if nothing is signed in. A later handoff's prompt lists the chat's agents as predecessors, not the seed. A restart of the app restores seeded chats still awaiting their first send from their records (and re-requests their tab if no client saw it); discarding one drops the record with it. A title with no usable characters answers 400 and one already taken 409, as a launch's requested name would.

- Every chat that starts with no message is greeted: the `welcome` create template replaces the one-time `first` template and its first-chat claim (`claim_first_chat` is gone from `accounts.py`), so `/welcome` runs each time and the skill varies what it says.

- Fast mode is a per-chat setting with three modes, off, auto and on (`chat_fast_mode.py`, `GET`/`PUT /api/chats/<chat-id>/fast-mode`, kept in the chat's folder so it survives reloads and travels with the chat across handoffs, and removed with the chat). Auto, the default, runs the chat fast for the first `fast_mode_turn_limit` of the user's turns (default 5; the seed's turns do not count) and then switches it to standard speed, once, with a one-time notice over the model bar the first time this happens in a workspace; a user who turns fast mode back on afterwards keeps it. The workspace's default for new chats and the turn limit are `GET`/`PUT /api/settings` (`chat_settings.py`, `data/.apps/chat/settings.json`). The model picker's fast row now states the chat's mode ("Auto", "Auto (off now)", "On", "Off") instead of a switch and opens a small chooser where the mode is picked, auto's turn limit edited, and the mode made the default for new chats; `/fast on` and `/fast off` in the composer choose the mode too. A chat whose mode calls for it launches through the `fast` create template, a handoff's successor included. The old fast-mode prompt modal and `POST /api/chats/<id>/fast-mode-answered` are gone.
