A sent message no longer sits in a faded bubble under a "Sending…" caption while it is delivered. It shows at once as an ordinary sent message, solid and uncaptioned, the same way everywhere a not-yet-delivered message appears (a fresh send, a message held while the chat switches harness, a message re-sent by a shoulder tap). This makes the chat more optimistic than before: a message now looks sent before the chat app has confirmed it, and the message-lifecycle contract says so. A send the chat app refuses still leaves the transcript and returns to the composer with a notice.

When the delivery has to wait for the agent to come up -- the agent was stopped and the send starts it, or it has just launched and is not taking input yet -- "Connecting…" shows with a pulsing orange dot beside the model name until the message goes through. A message sent to a chat that is still being created reads the same way. The chat app decides this from the agent's lifecycle and the harness's own ready signal (claude's `session_started` marker, pi's `pi_session_started`, codex's live connection) and reports it as `active_agent.is_connecting` on each chat's snapshot. The message-lifecycle contract describes it as the Connecting sub-state of Sending.
