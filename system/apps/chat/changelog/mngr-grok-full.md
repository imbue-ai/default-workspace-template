Grok Build (mngr agent type `grok`) is a chat harness, labelled "Grok Build", built on `imbue.mngr_grok.api` and measured against grok 1.0.62 with a stub model.

- **Sign-in.** The provider chooser offers xAI: sign in with an xAI account through `grok login --device-auth`, whose page and one-time code the chooser shows while grok waits (a terminal sign-in can now declare a device code, which gives it the show-the-code-and-wait shape and hands the CLI the browser shim), or paste an xAI API key from console.x.ai. A pasted key is checked with xAI (`GET https://api.x.ai/v1/api-key`) before anything is written; an accepted key replaces the account's `auth.json` with grok's `xai::api_key` scope, 0600 by temp file and rename under grok's own `auth.json.lock`, since grok uses a session login over a stored key. A device sign-in removes a key scope left from a paste. The xAI row shows a neutral glyph.

- **Accounts.** A grok chat binds to its account by `GROK_AUTH_PATH=<account>/auth.json` in its env file, so every agent on the account shares one credential and refresh lock while `GROK_HOME` stays mngr's per-agent home. Sign-in, probe and listing runs use the account folder as grok's home on mngr_grok's pinned environment, and re-pinning it keeps the consent answers recorded there. A same-lane account switch hands off to a new agent rather than rebinding, because mngr_grok merges consent answers only at provision. The signed-in check asks xAI about a key-only account and reads `grok models`' banner otherwise, without the server's own `XAI_API_KEY` and `GROK_*` variables.

- **Transcript.** `harnesses/grok/session_parser.py` turns grok's `updates.jsonl` records into the shared payload-free events: user turns, assistant text, thinking, tool calls labelled in claude's vocabulary (`tool_labels.py`) with their results, and turn markers (a top-level turn's start and end, a subagent's turn end). A cancelled turn, or one closed as `interrupted` after a resume, answers each killed tool with "Interrupted."; a failed turn shows grok's error; a shell that exits non-zero reads as failed with its `exit:` line; a guard refusal (`Hook denied:`) reads as failed with no error line; turns grok starts for finished background work read as notices, and Stop-hook feedback as a chip. The watcher tails every top-level session as one stream (a `/new` and a resumed session interleave by time) and each subagent's child session as its own lane behind a sub-agent card. Fixtures are grok's own captures.

- **Activity.** The dot is a turn latch per top-level session with no `active` marker, so a turn that ends while a background subagent runs reads `background`. grok's background-task markers (written by its hooks) and background work grok will wake for keep the chat busy until the wake turn starts (`set_wake_pending_tasks_callback`, `AgentManager.forget_finished_tasks(..., is_wake_turn_pending=True)`).

- **Sending and stopping.** A grok chat holds every message itself, and one flush worker types them as a block once no top-level turn is in flight, waking on mngr_grok's root-turn files so a held message goes out about a second after a turn ends; mngr's `busy_send_policy = "REFUSE"` keeps a send that races a turn start held. A slash command goes out alone and is never retyped, a message mngr confirmed is never typed again, and one mngr may have typed before it failed is typed again only when grok logs no turn holding it. A send to a stopped grok starts it; one that meets a gate screen fails with mngr's words. Stop presses one Ctrl+C through mngr (which presses only into a cancellable turn), waits for the turns it pressed into, and returns every undelivered message, also when the restart fails; the shoulder tap presses the same key and leaves delivery to the worker.

- **Model bar.** The bar offers grok 1.0.62's built-in models (Grok 4.6 and 4.5 and their efforts) that `grok models` lists for the chat's account, and reads `model_state.json`. `/model` and `/effort` go through a control lane the worker sends alone, ahead of held messages and never during a turn; one grok already runs is dropped unsent. A composer `/login` or `/logout` opens the sign-in, `/m`, like `/model` and `/effort`, gets the notice that points at the model picker, and the grok commands that take over the terminal get the send-it-from-the-terminal notice. So do the ones whose Enter, as mngr presses it, answers a picker or changes a setting (`/timestamps`, `/density`, `/theme`, `/t`, `/timeline`, `/vim-mode`, `/rename`, `/title`, `/jump`, `/session-info`, `/info`), `/minimal`, which replaces the composer mngr reads, and `/mem`, which grok completes to `/remember`.

- **Compaction.** A composer `/compact` asks mngr to compact the agent; grok's `compaction_checkpoint` is the "Context was compacted" status. A requested compaction shows before mngr is asked and is withdrawn when mngr declines it, for every harness compacted through mngr. Idle compaction passes grok over until `[plugins.autocompact] cache_ttl_minutes` is set, since xAI publishes no cache lifetime.

- **Every harness.** A chat send or key press (a stop or a shoulder tap) that reached the agent at its known location is no longer rediscovered and repeated: a send the agent refused (busy, blocked or not ready), may already have typed (mngr's `submission_unconfirmed`), or took before a dialog came up, and a press it refused. Only a location that reached no agent (mngr's `agent_not_found` or `agent_unreachable`) falls back to a fresh lookup. A watched directory that is deleted and recreated, as grok's root-turn directory is at every launch, is watched again rather than left to the one-second poll.

- **Policies and tests.** The tool-call policies' state-of-things page has a `grok` column (all of P1-P7 and P9-P10 live, P7 delivered on the first tool call of a turn) and grok's delivery channels, wiring and known bypasses; `tool-call-policies.md` lists grok's file tools. The conservation storm suite has a grok world that drives the real queue, worker, stop, tap and control lane through grok's measured semantics.
