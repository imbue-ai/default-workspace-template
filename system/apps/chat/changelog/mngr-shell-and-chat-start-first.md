The chat app, which owns the AI-provider chooser, can be routed to from the first moment of a boot instead of only after it has imported mngr and the harness plugins and then registered. Its program line binds port 8010 first (`listen_then_exec.py`), then registers and announces it (`forward_port.py --manifest system/apps/chat/app.toml --announce`). The server serves on the socket it inherits through `WERKZEUG_SERVER_FD`, so a request that arrives while the app is still importing waits and is answered as soon as it serves, instead of being refused. A socket on any other address than the configured one is refused with `InheritedSocketMismatchError`. The app still registers itself once it serves, which does nothing when the row is unchanged.
