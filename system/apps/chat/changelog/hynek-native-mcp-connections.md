A permission card can now offer the user's own cloud connections in place of the request. When a provider account signs in, the chat app asks once, in the background, which third-party connectors the account has on the provider's side (claude.ai connectors for a Claude subscription, ChatGPT apps for a ChatGPT sign-in) and keeps their names, and the addresses of their servers where the provider tells them, in the account's folder. A pending request for a service that one of those connectors is for then carries a quiet line under its button, "Your Anthropic account already has a Gmail connection. Alternatively, you could enable the existing connections associated with that account." A request for a built-in service is matched to a connector named after the service. A request for a custom service (one that pastes an API key, or signs in through the token-capture, cookie-capture or mcp flow) names only a domain, so it is matched to a connector served from the address the request names, and otherwise to one named like the domain ("ClickUp" for `api.clickup.com`). Opening it shows a warning that this circumvents Imbue Studio's permission guarantees and an "Enable existing cloud connections" button, which turns the connections on for the whole workspace, withdraws the permission request, restarts that chat's agent, and tells it what happened in a notice the page does not show; the card then reads "Cloud connections enabled instead". Every agent that starts afterwards, in a new chat, a restarted one, or the background, loads the connections of the account it runs on; a chat that was already running is still offered them, and taking the offer there only restarts it.

The offer is never made in a shared workspace, to a visitor, for a chat whose agent already loads its account's connections, or for an account whose connector list could not be read; an account signed in before this change has no list until it signs in again. Only claude and codex chats can get it.
