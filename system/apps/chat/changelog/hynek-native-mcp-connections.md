A permission card can now offer the user's own cloud connections in place of the request. When a provider account signs in, the chat app asks once, in the background, which third-party connectors the account has on the provider's side (claude.ai connectors for a Claude subscription, ChatGPT apps for a ChatGPT sign-in) and keeps their names in the account's folder. A pending request for a service that one of those connectors is named after then carries a quiet line under its button, "Alternatively, you could enable the existing connections associated with your Anthropic account." Opening it shows a warning that this circumvents Imbue Studio's permission guarantees and an "Enable existing cloud connections" button, which turns the connections on for that chat's agent alone, withdraws the permission request, restarts the agent, and tells it what happened in a notice the page does not show; the card then reads "Cloud connections enabled instead".

The offer is never made in a shared workspace, to a visitor, for a chat whose agent already loads its account's connections, for an account whose connector list could not be read, or to a claude chat in a workspace created before this change (its workspace-wide setting keeps the connections off for every chat); an account signed in before this change has no list until it signs in again. Only claude and codex chats can get it.
