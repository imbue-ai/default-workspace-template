Only an installation's first workspace starts the onboarding agent. `POST /api/chats/seed` takes an optional `is_onboarding` flag, which the Imbue Studio app sets only for the create that was granted its onboarding questions; the seeded chat's record keeps it, and `launch_role_templates(is_fast, is_onboarding)` stacks the `onboarding` role on the `chat` role for that chat's first agent, after `fast` when both apply. A seed without the flag (any later workspace's) starts a plain chat agent, and a handoff's successor never carries the role.

The chat page shows an "Is this you?" popup when the onboarding agent's background web look-up finds people who might be the user. A new `/api/identity-matches` store and routes take the look-up's candidates (each with the page it came from, which must be a web page), push them to the chat pages as an `identity_match_updated` WebSocket event (and send the pending ones to a page that connects later), and take the user's answer: "This is me" on one candidate, or "None of these". The answer reaches the agent as an ordinary message in the user's words ("That's me: <name>, <summary> (<link>)" or "None of those are me."). Escape or a press outside sets the popup aside on that page until a reload; a newer look-up for the same chat replaces a pending one; a preview chat refuses answers.

A new `POST /api/chats/<chat-id>/web-lookup` runs one web search on the chat's own provider, account and model, which the onboarding agent's look-up script asks for instead of naming a provider. Each harness can register a `WebLookup` on its spec (`harnesses/web_lookup.py`), the way it registers a one-shot completion: Claude's runs `claude -p` with only `WebSearch` and `WebFetch`, and Codex's runs `codex exec` read-only with web search switched on, each from an empty directory with no session kept, so a page's instructions reach no file or shell. The search uses the model the chat is set to (the alias the chat app switches to for a catalog model, else the id the harness reports), or the account's own default when none is known. A harness with no look-up (Pi, Antigravity, OpenCode so far) is refused with a 501, and the agent is told it could not look the user up.
