- The chat frontend's vitest run no longer fails with "EnvironmentTeardownError: Closing rpc while "onUserConsoleLog" was pending" while every test passes. Two `ModelProviderMenu` tests open the menu on a dynamic picker, which loads the chat's offerable models; the test file let that request go out to jsdom's `localhost:3000` unanswered, and its failure was logged after the file's environment had been torn down. The tests now answer the request themselves.

- A chat page's presence could be stuck as hidden (so not watching) while it was shown and focused, until its next heartbeat up to 30 seconds later. A page sends `hidden` when the shell's handshake lands and `visible` a moment later on `shell:shown`, each as its own request, and the threaded server could record them in the reverse order. Presence reports now carry a `sequence` number the page counts up from 1, and the chat app drops a report numbered at or below the page's standing one. A `closed` report is kept as the page's standing report until it expires (counting as neither open nor visible), so a report it overtook cannot reopen the page either. This was the cause of the flaky `test_a_chat_page_watches_its_chat_only_while_shown_and_focused` e2e test.
