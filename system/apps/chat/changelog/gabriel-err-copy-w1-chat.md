Chat's failures read as sentences for people, with the server's text, command output and ids behind a collapsed "See details", and native alerts replaced by styled notices. Where a sentence asks for a bug report, a "Report a bug" button asks the workspace's shell to open Imbue Studio's bug report with that sentence and its details attached; it shows only where the shell says Imbue Studio can open one. The chat app's own sentences that ask for a bug report carry `reportable: true` beside their `user_facing_message`, so the chat's pages and the desktop's launcher toasts offer the button for them. An exception no route expected answers 500 with no sentence of its own, so each page names what failed ("Couldn't stop the agent. Try again. If this persists, report a bug.").

- Sending: a refused send shows the chat app's sentence for its case (each of mngr's kinds, an agent whose start failed, a chat still waking up, a signed-out account, a chat that was deleted, with Start a new chat and no Retry or Restart); one it has no sentence for says "Your message wasn't delivered. Your text is back in the box, so nothing was lost." (with "Try again. If this persists, report a bug." when no reason came back). Every failed send keeps the agent tool's words behind See details. A send nothing answered is titled "Your message may not have been sent" with Send again only, which the chat app answers once for the same message; a repeat still under way counts as unconfirmed. An agent whose start failed for the send is a kind of its own (`agent_start_failed`) and offers Try again and Report a bug. A refusal whose kind the page doesn't know offers Retry only, a send to a chat that never became an agent (its create failed, or it was closed first) offers neither Retry nor Restart, and a first send whose launch failed gets Try again, which launches it again; a launch a gateway gave up on says the workspace didn't answer. The terminal advice became a "Turn on Source view" button, offered for a blocked input or an unconfirmed send. A message whose arrival never comes is captioned "This message may not have been delivered." A message sent to a chat from outside it (the launcher) that the chat refuses says why: chat still starting, a chat that is gone, a signed-out account, or else "Chat couldn't take this. Try again. If this persists, report a bug."

- Stop, switch, cancel and the queued-messages tap: each failure has its own sentence and a Try again; a switch that can't move the chat to that account offers Start a new chat; a cancel with nothing to cancel is a plain notice; a tap whose messages went through but whose nudge failed is titled "Queued messages sent" with Nudge the agent. The model menu's Stop agent and the chat list's Stop, Restart and Delete use styled notices; a delete nothing answered keeps the chat off the list until the list updates, and a half-done delete says so.

- Pages: a transcript or side conversation that won't load says so with Refresh or Try again; a stale side conversation offers Back to the chat; a chat the app no longer has says "This chat is no longer here." with Start a new chat; a stopped chat with nothing to show offers Start this chat; a failed create says "The agent for this chat couldn't be started..." with its output behind See details and a Remove this chat button (Delete now drops a chat that never became an agent); an address chat no longer serves gets a page with a way back. When the chat's frontend is missing, its page says "Chat isn't available in this workspace right now. Restart the workspace. If this persists, report a bug." with a Report a bug button (the chat app now serves the shell's app contract at `/_static/app_contract.js` for it); it offers no agent, since starting one would open this same page.

- Transcript: a failed turn leads with a plain line chosen by its kind, keeps a provider's prose and moves raw bodies behind See details. A conversation too long for the model (Claude's "prompt is too long", Codex's context window) is its own kind and reads "This conversation is too long for the model to take in. Start a new chat, or send /compact to shorten it."; other refused requests say what the provider refused, and "The model provider is having trouble. Try again in a moment." is kept for provider faults and unnamed failures. An ordinary 400 from the provider is no longer read as a dead account; a failed or killed background task gets a warning mark and "Background task failed"; a permission request that ended in an error says the agent didn't get permission, with Ask the agent to try again.

- Sign-in and providers: the provider list and sign-in failures say what happened instead of "[object Object]" or "null", and a failed provider list offers Try again and Report a bug whether or not providers were already listed; failure screens keep their buttons below the scrolling body; a provider tool's own failure line goes behind See details under "{Provider} didn't accept that sign-in."; sign-in start failures say Imbue Studio couldn't start the sign-in; the chip with no provider reads "Add a provider".

- Smaller copy: account lookups, create refusals, the switch's phase and retry refusals, Restart's failed restart, a model pick the chat app refused, the stopped terminal face, the model list that won't load, the declined slash command and the declined /compact, the /login notice, and the secret card's refusals (with a 2000-character limit on the decline note).
