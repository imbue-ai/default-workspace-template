Chat's failures read as sentences for people, with the server's text, command output and ids behind a collapsed "See details", and native alerts replaced by styled notices. A failure that owes the person help offers "Ask an agent to fix this": it sends the sentence and its details to an agent through the workspace's shell (to the chat about Chat, run through the workspace's assist flow), reads "Asking an agent…" until the chat opens, which closes a notice, and tells a refused ask beside the failure. Under an ask refused with a failure that owes help itself, "Draft it in a chat" leaves the same request unsent in a chat's message box, and "Report a bug" asks the shell to open Imbue Studio's bug report with the sentence, its details and the refused ask's attached; an ask nothing answered is only asked again. "Report a bug" stands in the agent's place, wherever the shell says Imbue Studio can open one, where the ask would go through what failed: a send refused because the chat app can't read its agent list, a message from outside a chat that the chat would not take or could not pick up (the ask takes the same intake route), and the provider chooser while nothing is signed in (an agent needs an account to run on). Each of the chat app's refusals says what it is where it is raised: its sentence owes help unless its answer says `routine: true`, which the chat app sets for ordinary operation the sentence fully explains (a workspace or chat still starting, an agent waiting on an answer in its terminal, a signed-out or unavailable account, a chat, side conversation or secret request that is gone or already answered, a chat in the middle of a switch, a declined /compact, a name or a note to change). An exception no route expected answers 500 with no sentence of its own, so each page names what failed ("Couldn't stop the agent. Try again.").

- Sending: a refused send shows the chat app's sentence for its case (each of mngr's kinds, an agent whose start failed, a chat still waking up, a signed-out account, a chat that was deleted, with Start a new chat and no Retry or Restart); one it has no sentence for says "Your message wasn't delivered. Your text is back in the box, so nothing was lost." (with "Try again." when no reason came back). Every failed send keeps the agent tool's words behind See details. A send nothing answered is titled "Your message may not have been sent" with Send again only, which the chat app answers once for the same message; a repeat still under way counts as unconfirmed. An agent whose start failed for the send is a kind of its own (`agent_start_failed`) and offers Try again and Ask an agent to fix this. A refusal whose kind the page doesn't know offers Retry only, a send to a chat that never became an agent (its create failed, or it was closed first) offers neither Retry nor Restart (a message the chat app was holding for a new chat deleted elsewhere before it landed comes back into the box with that notice too: the discard names the messages dropped with the chat, and is replayed to a page whose socket was down), and a first send whose launch failed gets Try again, which launches it again; a launch or a switch a gateway gave up on says the workspace didn't answer. The terminal advice became a "Turn on Source view" button, offered for a blocked input or an unconfirmed send. A message whose arrival never comes is captioned "This message may not have been delivered.", with "Check in Source view" beside it, which turns on the agent's terminal. A message sent to a chat from outside it (the launcher) that the chat refuses says why: chat still starting, a chat that is gone, a signed-out account, or else "Chat couldn't take this. Try again."

- Stop, switch, cancel and the queued-messages tap: each failure has its own sentence and a Try again; a switch that can't move the chat to that account offers Start a new chat; a cancel with nothing to cancel is a plain notice; a tap whose messages went through but whose nudge failed is titled "Queued messages sent" with Nudge the agent, whose message is written as Imbue Studio about the user's queued messages, not as the user. The model menu's Stop agent and the chat list's Stop, Restart and Delete use styled notices; a delete nothing answered keeps the chat off the list until the list updates, and a half-done delete says so.

- Pages: a transcript or side conversation that won't load says so with Refresh or Try again; a stale side conversation offers Back to the chat; a chat the app no longer has says "This chat is no longer here." with Start a new chat; a stopped chat with nothing to show offers Start this chat; a failed create says "The agent for this chat couldn't be started..." with its output behind See details and a Remove this chat button (Delete now drops a chat that never became an agent); an address chat no longer serves gets a page with a way back. When the chat's frontend is missing, its page says "Chat isn't available in this workspace right now. Restart the workspace." with a Report a bug button (the chat app now serves the shell's app contract at `/_static/app_contract.js` for it); it offers no agent, since starting one would open this same page.

- Transcript: a failed turn leads with a plain line chosen by its kind, keeps a provider's prose and moves raw bodies behind See details. A conversation too long for the model (Claude's "prompt is too long", Codex's context window) is its own kind and reads "This conversation is too long for the model to take in. Start a new chat, or send /compact to shorten it."; a request the provider refused shows the provider's own message on the line ("The model provider refused this request: max_tokens: too large."), or "The model provider refused this request." when the failure carried none, and "The model provider is having trouble. Try again in a moment." is kept for provider faults and unnamed failures. The chat app reads the provider's message, and whether a failed turn's text is a raw body, once as it parses the turn (`api_error_message` and `is_error_text_raw` on the event), so the page classifies no text. An ordinary 400 from the provider is no longer read as a dead account; a failed or killed background task gets a warning mark and "Background task failed", its exit code or signal still on the line; a permission request that ended in an error says the agent didn't get permission, with Ask the agent to try again.

- Sign-in and providers: the provider list and sign-in failures say what happened instead of "[object Object]" or "null", and a failed provider list offers Try again and an agent (Report a bug while nothing is signed in) whether or not providers were already listed; failure screens keep their buttons below the scrolling body; a provider tool's own failure line goes behind See details under "{Provider} didn't accept that sign-in."; sign-in start failures say Imbue Studio couldn't start the sign-in; the chip with no provider reads "Add a provider".

- Smaller copy: account lookups, create refusals, the switch's phase and retry refusals, Restart's failed restart, a model pick the chat app refused, the stopped terminal face, the model list that won't load, the declined slash command and the declined /compact, the /login notice, and the secret card's refusals (with a 2000-character limit on the decline note).
