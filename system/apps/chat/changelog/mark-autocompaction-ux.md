Turn on idle compaction for chats, with a per-chat and per-workspace toggle, and run its sweep in process.

- **Idle compaction on by default:** The template's `.mngr/settings.toml` sets `[plugins.autocompact] mode = "proactive_timer"`, so an opted-in, idle chat above the plugin's token threshold is compacted just before its prompt cache expires. The plugin's other keys stay at their defaults. One workspace can turn it off with `mngr config set --scope local plugins.autocompact.mode disabled`; the sweep re-reads the mode every tick.

- **Per-chat toggle:** Each chat keeps its setting in its folder (`autocompact.json`), copied from the workspace default (`autocompact_default` in `/api/settings`, initially on) at its first launch, so it travels across handoffs and rebinds like fast mode. A chat created before this change reads the workspace default until its toggle is changed. `GET` and `PUT /api/chats/<chat_id>/autocompact` read and replace it (`{"is_enabled": true}`), answering 404 for an unknown chat and 400 for a bad body.

- **`autocompact` agent label:** A chat's agents carry `autocompact=on|off`, stamped at create and handoff and rewritten by `mngr label` when the toggle changes (a stopped agent is relabeled too), so `mngr list` shows the setting. `autocompact` is now a label only the app sets.

- **In-process sweep:** The 60-second sweep calls the autocompact plugin's `compact_stale_agents_by_name` in process instead of launching `mngr autocompact run`, passing only the running chats that have the toggle on. With none opted in it does no work at all (no config read, no plugin call). A failed config read or plugin call is logged as a warning, an unexpected error is logged without stopping the sweep, and a slow sweep delays the next tick and logs a warning past 30 seconds. Each compaction request and toggle change writes one `autocompact: ...` line to the chat service log.

- **Settings and catalog for the UI:** `/api/settings` gains `autocompact_default` and `is_autocompact_notice_shown`. Each `/api/harnesses` entry gains `supports_compaction` (Claude, Codex, Pi) and `can_interrupt_compaction` (Claude only).

- **COMPACTING activity state:** A chat's `activity_state` reads `COMPACTING` while its context is being compacted, counting as working on the chat row. Claude's `compacting` marker wins over `THINKING` and `TOOL_RUNNING` (so Claude's own mid-turn auto-compaction shows too); a compaction the chat asked for shows only once the agent is idle, so a `/compact` queued behind a running turn keeps the turn's state until the turn ends. It comes from Claude's `compacting` marker (written by mngr's `PreCompact` hook, watched by a shared one-second poller beside the model-state one; an error in one agent's recompute is logged and stops neither poller nor the session sweep) and from the chat's own requests: the idle sweep's, and a `/compact` sent from a Claude chat's composer. Codex and Pi chats show it for the sweep's requests only, and a stopped agent still reads `IDLE`. The `autocompact: compaction pending`, `autocompact: compaction finished` and `autocompact: stale compacting marker ignored` lines record it in the chat service log.

- **Stale timeouts:** A compaction that never reports completion (a cancelled or failed one, or a crash) stops showing after 10 minutes, whether it came from a marker or a request; an ignored marker is logged once, and a marker dated in the future is aged by its file time. On a hooked Claude chat a request also ends when `last_compaction.json` records a finish after it; on any other chat nobody has open (Codex, Pi, or a Claude agent created before the hooks), where no compacted event can end it, a request stops showing after 3 minutes.

- **Cleared on interrupt:** On Claude, the stop button cancels a compaction even with no turn in flight, by pressing the cancel chord (`M-q`, `chat:cancel`, the action Escape takes). The stop button and the interrupt route remove the agent's `compacting` marker and the chat's pending request only when a chord or a restart was actually sent, since a cancelled compaction reports no completion; a stop that found nothing to interrupt leaves both alone. Clearing either writes an `autocompact: compaction cleared by interrupt` line to the chat service log.

- **`/compact` before the first reply is declined:** A `/compact` sent from a Claude chat's composer before the agent has replied once is not sent; the send answers 409 with the detail "Nothing to compact yet." and kind `nothing_to_compact`, and no "Compacting…" status is set. The composer shows it the way it shows a declined slash command: a "/compact wasn't sent" notice reading "Nothing to compact yet." with only an OK button, and the typed `/compact` stays in the composer. Claude Code refuses such a `/compact` ("Not enough messages to compact.") only after its `PreCompact` hook has written the `compacting` marker, which then showed "Compacting…" for the full 10-minute timeout. A `/compact` Claude Code refuses for any other reason still leaves the status up until that timeout or the stop button clears it.

- **`compaction_cause` on the compacted event:** The "Context was compacted" status event carries `compaction_cause`: `"idle"` (the idle sweep), `"manual"` (a `/compact`), `"native"` (Claude compacted on its own), or `null` when unknown. It is attached as the event is stored and streamed, so a reload sees the same value. Each compaction the chat asks for is also recorded in the agent's state dir as `compaction_request.json` (`{"cause": "idle"|"manual", "requested_at": "<utc iso>"}`), so a compaction the chat no longer remembers (a re-opened chat, a restarted chat app) takes the cause of a request made within the 10 minutes before it, and otherwise falls back to a recent `last_compaction.json`.

- **Auto-compact in the model menu:** A chat on a harness that supports compaction gets an Auto-compact row in its model menu, reading On or Off. Its submenu picks On or Off for this chat, explains "Saves ~50% by compacting right before the cache expires.", and ends with a "New chats start with" row whose On / Off segments show and set the workspace default, independent of the chat's own choice.

- **"New chats start with" in the Fast mode submenu:** The Fast mode submenu's "Use <mode> for new chats" switch, which could only make the chat's current mode the default and went inert once it was, is replaced by the same "New chats start with" row with Off / Auto / On segments. The workspace default is highlighted and any mode can be picked from any chat state; the segments are disabled only until the settings load. The row itself now reads "Fast mode" rather than "Fast Mode".

- **"Compacting…" status:** While a chat is compacting, the activity strip above the composer names who started it: "Compacting as requested…" (a `/compact`), "Compacting while idle…" (the idle sweep), "Compacting to free up context…" (Claude's own compaction), or "Compacting…" when the cause is unknown. Once a message is queued behind it, ", then replying…" takes the place of the ellipsis ("Compacting while idle, then replying…"). Each chat's `active_agent` in `chats_updated` and `/api/chats` carries the cause as `compaction_cause` (`"idle"`, `"manual"`, `"native"`, or `null`), set only while its `activity_state` is `COMPACTING`.

- **A typed `/compact` shows as the user's bubble, and a message sent during it shows once:** A `/compact` sent from a Claude chat's composer, which the transcript used to drop, now arrives as the user's own bubble reading `/compact` (`non_turn_tail: true`). Claude Code records it a second time, as the command's expansion, once the compaction ends; that copy arrives hidden (`display: "hidden"`, `non_turn_tail: true`), so the bubble shows once. The first record's arrival retires the composer's "Sending…" bubble, so a message queued behind the compaction no longer stands that bubble down in its place, which showed the queued message as a queued chip and a "Sending…" bubble at once.

- **A compaction shows as two chips:** The "Context was compacted" pill is gone. Each compaction now shows as two chips in the same chip rows the agent's tool calls use: a start chip (package-open glyph) named as the activity strip names the running compaction ("Compacting as requested…", "Compacting while idle…", "Compacting to free up context…", or "Compacting…" when the cause is unknown), and a finish chip (package glyph) reading "Compacted" whatever the cause, since the start chip beside it already names it. Claude's own mid-turn compaction joins the chip run at its place in the turn (or a chip row of its own when nothing chips beside it), a `/compact` puts the chips directly under its bubble, and an idle compaction puts them after the last turn's reply, or on its last chip run when it ended without one. While the chat is compacting, the start chip alone stands where the pair will land, and the pair replaces it once the compacted event arrives.

- **The compaction chips say why:** Either chip opens the tool chips' detail panel, headed with that chip's glyph and label. It shows a sentence saying why the compaction ran: "Compacted because you asked (`/compact`)." (manual, with `/compact` in the chat's inline-code style), "Compacted while idle to keep replies fast and cheap. Change this under Auto-compact in the model menu." (idle), "Your agent triggered compaction. You can ask it about its current setting, or tell it to change it." (native), and "Compacted to keep replies fast and cheap. Idle compaction is under Auto-compact in the model menu." (unknown). Under a dashed rule follows the summary, in an output pane clamped like a long tool output. The page composes the sentence from the cause, so it never reaches the transcript, the events API, or the agent. A compaction with no summary, or one still running, opens on the sentence alone.

- **One-time notice:** The chip row holding the latest idle compaction carries a dismissible notice, "Idle chats now compact automatically to keep replies fast and cheap. Turn this off per chat, or for new chats, under Auto-compact in the model menu.", until the user dismisses it once for the workspace (`is_autocompact_notice_shown`).

- **Stop button during compaction:** The stop button stays hidden while a chat compacts on a harness whose interrupt cannot cancel a compaction (`can_interrupt_compaction` false: Codex and Pi). On Claude it shows and cancels the compaction (see "Cleared on interrupt").

- **A stuck sweep is logged:** Each sweep now runs on its own thread while the sweep loop waits on it. One still in flight after 2 minutes, and again every 5 minutes after that, logs an `autocompact: sweep still running after <N>s` warning carrying the stack it is blocked in, so the chat service log shows where it hangs. No other sweep starts until it returns. A sweep that does return but takes over 30 seconds still gets the existing slow-sweep warning.
