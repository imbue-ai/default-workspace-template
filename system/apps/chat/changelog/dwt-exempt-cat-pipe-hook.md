The tool-call policy for piping into `tail`/`head` (P1) now states the rule the guard enforces: a pipe is blocked only when the output it truncates would have to be regenerated. Reads of files, directories and git history, `--help`/`--version` output, and pipes downstream of a `tee FILE`, are allowed, and each pipeline in a compound command is judged on its own.

`tool-call-policies-state-of-things.md` now records that pi reaches every command guard and the OOM/git-identity rewrite through this repo's `.pi/extensions/policy_guards.ts`, which runs the same scripts as the other harnesses. mngr's pi extension no longer carries any command policy. Until this repo pins an mngr with that change, `policy_guards.ts` still judges the command the older mngr records as `mngrOriginalCommand`, and replaces that mngr's prefix with its own.
