Model-choice tracking no longer spends a dedicated filesystem watcher on every agent. Each observed agent -- workers included, running or stopped -- used to get its own watchdog observer for its `model_state.json` (a poll thread, dispatcher, emitter, and inotify buffer: four OS threads and one kernel inotify instance per agent, held for the agent's whole life), so a host accumulating agents grew the chat app to hundreds of threads and eventually exhausted the inotify instance limit, at which point new agents' model watchers silently failed to schedule. Tracking is now one shared poller thread that stats every known agent's model-state file once a second and recomputes only the choices whose file stamp changed. The path set is re-resolved from ground truth on every pass, which also fixes a latent bug where a watcher built before the agent's harness was known kept watching the guessed path forever.
