The provider chooser offers xAI, which runs on Grok Build, so a chat can now start on grok. Sign in with an xAI account through `grok login --device-auth`, whose page and one-time code the chooser shows while grok waits for the code to be confirmed (a terminal sign-in can now declare a device code, giving it the show-the-code-and-wait shape), or paste an xAI API key, whose field hints `xai-...`. A pasted key is checked with xAI before anything is written; an accepted key replaces the account's `auth.json` with grok's `xai::api_key` scope, 0600 by temp file and rename under grok's own `auth.json.lock`. A device sign-in removes a key scope left from a paste. The xAI row shows a neutral glyph.

A grok chat binds to its account by `GROK_AUTH_PATH=<account>/auth.json` in its env file, also in the workspace's create defaults, while `GROK_HOME` stays mngr's per-agent home. Sign-in and probe runs use the account folder as grok's home on mngr's pinned grok environment, without the server's own `XAI_API_KEY` and `GROK_*` variables, and seeding the folder keeps the consent answers recorded there. The signed-in check asks xAI about a key-only account and reads the banner `grok models` prints otherwise. Switching a grok chat to another xAI account hands off to a new agent rather than rebinding.
