The chat server no longer grows by roughly 50-170 KB for every message sent, stop pressed, terminal opened and agent listing served, for as long as it runs. Each of those operations builds a fresh mngr context, and mngr caches every provider it builds against that context -- along with the context, its config, and the captured output of every process its concurrency group ran -- until something closes them; nothing in the chat did, so every operation's context stayed in memory for the life of the server.

All of them now go through one context manager, `agent_discovery.mngr_context()`, which closes the providers mngr cached for its context on exit, whether the operation succeeded or raised, and then exits the concurrency group. A new project ratchet (`test_project_ratchets.py`) keeps it the only way the chat package builds an mngr context: a direct call to mngr's `load_config`, or to the retired `_get_mngr_context`, anywhere else in the package fails it.
