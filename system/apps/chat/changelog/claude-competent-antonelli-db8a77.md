A Claude reply now shows in the chat while it is being written, instead of only once Claude finishes it. Claude writes a reply to its session file only when the whole text block is done, so a page used to show nothing for the several seconds the agent's terminal was already streaming the answer. While the chat is open in a window that is shown and focused, and a turn is in flight, the chat app reads the reply off the agent's terminal three times a second (with mngr's `stream_snapshot` converter), and the page shows it at the end of the transcript until the real reply replaces it. Background chats (in a hidden or unfocused window, kept loaded out of sight, or not open at all) and agents with no turn running are never read.

A page now recovers transcript events its live stream never delivered. When a chat's turn ends, and when the page is shown again, the page asks for whatever follows its last event: missing events at the end are added in place, and a missing event further up reloads the transcript. Before, such an event stayed missing until the page was reloaded.

Switching back to a chat the chat list already had open now puts the keyboard in its composer, as opening a chat for the first time already did. Before, the keyboard stayed on the list, so that chat neither took typing nor counted as the one being looked at, and its replies did not stream until it was clicked.
