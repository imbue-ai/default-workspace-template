Loading a Claude chat, and every live refresh of it, no longer scans the account's whole projects tree. The watcher looks for a session's file where Claude files it for the chat's work directory first (one or two file checks), and only falls back to a scan of the project directories directly under `projects/` when the file is not there. A session the history names but whose file never appears is scanned for at once, then after 1s, 2s, 4s and so on up to once a minute, instead of on every refresh forever; on one production workspace two such sessions made every refresh of every chat walk 841 project directories, and loads of those chats took 17-22 seconds.

A transcript watcher now refreshes at most once every 0.25 seconds. Every chat on an account watches the same projects tree, so one chat's writes woke every chat's watcher once per write; a burst of writes now costs each watcher one refresh.

A new chat started from the chat window's New chat no longer vanishes when the window's live connection is slow to catch up. The window created and showed the chat, then took the first chat list the connection delivered, which could predate the chat, as meaning it was gone, and closed it: the window went blank and stayed blank. It now keeps a chat it created until a list names it.
