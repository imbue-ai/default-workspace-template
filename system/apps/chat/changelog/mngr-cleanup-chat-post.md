Every text that enters a chat from outside a chat page arrives through one route, `POST /api/chats/intake`: the text, how the receiving chat is chosen (`target`: `new_chat`, `current_chat` from the window's path, `chat_selector`, or an explicit `chat`), whether it is sent or drafted (`is_draft`), an optional `account_id`, and `is_delivery_awaited` to wait for the harness to accept the send. The route answers the pure root path the shell opens a window at: `/?chat=<id>` when it finished the work, `/?chat=<id>&intake=<token>` or `/?intake=<token>` when the page has to finish it (a draft, a pick, or a first message with nothing signed in). Pending intakes are held in memory for fifteen minutes under `GET`, `POST .../apply`, and `DELETE /api/chats/intakes/<token>`.

The manifest declares `new`, `send`, and a new `draft` launch path as POSTs onto that route with presets; `GET /new` and `GET /send` are gone (a stale link answers 404), and the root takes no `draft` query parameter. Loading or reloading any chat page creates or sends nothing.

A new chat that cannot start at once (a draft into a new chat, or a first message with no account signed in) is minted as an unseeded provisional chat in the `awaiting_first_send` phase; its page shows an empty conversation over the composer and the first send launches it, through the provider chooser when nothing is signed in.
