The chat app's OOM prioritizer now re-tags chats one pass at a time on a background thread. Presence heartbeats, messages and lifecycle changes only mark a pass as wanted, and a pass reads the pid registry once for all chats instead of once per chat. Previously each of those events ran a full pass on its own request thread with no limit on how many ran at once, so a burst of heartbeats could pile up request threads and leave the chat service unresponsive. A chat's memory band is now written by the pass thread a moment after the request returns, and a pass that starts more than 5 seconds after it was wanted logs a warning.
