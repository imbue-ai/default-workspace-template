Every route of the chat is now in its route table, and the API document at `/api/schema` describes all 67 of them: a route that exchanges JSON names its request and response models (hand-built answers such as the lanes, the accounts, the health probe, the screen capture, the watchers, the sign-in callback relay, the secret requests and the focus-chat answer now have models, and `POST /api/chats/create` publishes `project_id` in its body), and a page, a file, a stream, the socket and the loosely shaped event routes are listed with the reason they carry no schema. Every modelled route reads its body through the shared `parse_request_body` and answers through `model_response`, which fail the request when they disagree with the table, so the document cannot drift from the routes; a body that is not a JSON object is refused with "the request body must be a JSON object" and a body of the wrong shape with "field '<name>': <reason>", and every refusal is the shared `{"detail": ...}` shape (a send failure adds `kind`, a converging refusal adds `phase`, as before). A body carrying a key its route's model does not name (on the accounts, the account flows, the secret requests and `POST /api/chats/create`) is now refused the same way, where it used to be ignored. The harness catalogs route answers a model too, and the richer failures (a send failure with its kind, the converging refusal with its phase) are listed on the routes that answer them, so the document shows them. The harness catalog answer models live in `imbue/chat/api_models.py`.
