A message is no longer lost or shown twice when the chat's sign-in fails or its delivery cannot be confirmed.

- When a chat's login expires and the user signs that account in again, the chat sends again, on its own, the message the expired login refused, once the sign-in has restarted the agent. Every live chat on that account whose last reply was the sign-in error does this, wherever the sign-in finished. While it happens, the failed turn reads "Signed in again. Sending your message again…". Nothing is sent again for a turn the agent had already started working on, when the user has written since, or while the chat is switching to another provider.

- When the chat cannot send it on its own (the chat was stopped, its restart or the resend failed), the failed turn reads "Signed in again." and offers "Send your message again" while it is still the chat's newest turn. When a resend of several refused messages stops partway, the ones it did not get to stay offered. The provider's original text stays under "See details". Each account now records when it last finished a sign-in, and `GET /api/accounts` carries it as `signed_in_at`.

- Once a refused message is sent again right after its sign-in error, by the chat, by the button, or typed again by hand before anything else, the original message and its sign-in error are hidden, so the message shows once, whichever order the agent wrote the error and the message in. The same words written after some other message are a new message, and hide nothing. This replaces the rule that hid every sign-in error from before the chat's first reply: such an error now stays when the user wrote something else next.

- A message sent to a Claude chat while it is still starting is no longer reported as possibly unsent. Claude takes a message at once but writes it down only after its startup hooks finish; mngr now reads Claude's screen when it has waited out its window, so a message Claude holds counts as sent, and one Claude never took is cleared from its input box and sent again automatically, once, where the agent is.

- A message the chat could not confirm reaching the agent is no longer typed into the agent a second time: the chat looks the agent up and sends again only when mngr reports nothing was typed (`agent_not_found`, or `not_submitted` as above). For an unconfirmed send, which remains only for the other harnesses or a screen that shows neither (`submission_unconfirmed`) the notice reads "Couldn't confirm your message arrived", says the agent may already have it, and offers Cancel and Send again, without Force or mngr's diagnostic text. The message goes back in the composer, and comes back out once the agent's turn for it shows up. "Send your message again" under a sign-in error does the same when its send cannot be confirmed: it says so and offers Send again in place of Try again.

- A message whose send got no answer from the chat app (the connection dropped, or a proxy gave up on a long send) is no longer reported as failed while it may have been delivered. The page sends it again under the same send-time id for about half a minute, and the chat app answers a repeat as it answered the first send, waiting for it while it is still under way, instead of delivering it twice. If it still gets no answer, its copy goes back in the composer and comes back out once the agent's turn for it shows up. Retry after a failed send goes under the failed send's id the same way.

- A message a Claude chat showed but had not written down yet (while its startup hooks run) is no longer lost when the agent's process exits before it does, from a crash or a kill. The chat reads the agent's final transcript and sends again, once, each delivered message sent after the last message it wrote down, restarting the agent to do so. Nothing is sent again after a deliberate stop, after Stop takes the turn back, to a chat that is switching or has moved on, for a message older than half an hour, or for a message that was itself such a resend.
