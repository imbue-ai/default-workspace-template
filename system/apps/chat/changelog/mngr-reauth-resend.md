A message is no longer lost or shown twice when the chat's sign-in fails or its delivery cannot be confirmed.

- When a chat's login expires and the user signs that account in again, the chat sends again, on its own, the message the expired login refused, once the sign-in has restarted the agent. Every live chat on that account whose last reply was the sign-in error does this, wherever the sign-in finished. While it happens, the failed turn reads "Signed in again. Sending your message again…". Nothing is sent again for a turn the agent had already started working on, when the user has written since, or while the chat is switching to another provider.

- When the chat cannot send it on its own (the chat was stopped, its restart or the resend failed), the failed turn reads "Signed in again." and offers "Send your message again" while it is still the chat's newest turn. The provider's original text stays under "See details". Each account now records when it last finished a sign-in, and `GET /api/accounts` carries it as `signed_in_at`.

- Once a copy of a refused message is in the chat, sent again by the chat, by the button, or typed again by hand, the original message and its sign-in error are hidden, so the message shows once. This works anywhere in a chat, and whichever order the agent wrote the error and the message in.

- A message the chat could not confirm reaching the agent is no longer typed into the agent a second time: the chat looks the agent up and sends again only when mngr reports nothing was typed (`agent_not_found`). For an unconfirmed send (`submission_unconfirmed`) the notice reads "Couldn't confirm your message arrived", says the agent may already have it, and offers Cancel and Send again, without Force or mngr's diagnostic text. The message goes back in the composer, and comes back out once the agent's turn for it shows up.
