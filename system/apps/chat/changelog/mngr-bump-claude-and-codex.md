The Claude model picker's Fable entry now selects Claude Fable 5.1: the `fable[1m]` alias it switches with resolves to `claude-fable-5-1` on the new 2.1.269 pin, so the entry is labelled "Fable 5.1" and its `harness_reported_model_id` moves to the suffix-free `claude-fable-5-1`, which is what the live model-state read is matched against. Fable 5 (`claude-fable-5`) stays in the catalog as a hidden option so a chat created on the previous pin still shows its name instead of falling through to the shrug case; it is ordered after the offered Fable 5.1 key, because the prefix pass would otherwise let the shorter key claim the new id.

The hidden set is re-derived from the 2.1.269 binary's model ids: Mythos 5.1 joins Mythos 5, the pre-4 ids the binary still resolves (`claude-sonnet-3-7`, `claude-haiku-3-5`) get their own entries so the family catch-alls do not mislabel them, and the dotted `claude-sonnet-4.6` spelling is dropped because the binary no longer carries it. The alias table documented in the module is updated to what 2.1.269 accepts (`best` is new, `mythos` and `opusplan[1m]` are gone); `best` stays out of the picker with `opusplan` since it names a policy, not a model. Fast mode is still scoped to Opus 5/4.8, so nothing changes there.
