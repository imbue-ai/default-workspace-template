A message is no longer delivered twice, or reported as failed while it may have arrived, when the chat cannot confirm its delivery.

- A message the chat could not confirm reaching the agent is no longer typed into the agent a second time: the chat looks the agent up and sends again only when mngr reports nothing was typed (`agent_not_found`). For an unconfirmed send (`submission_unconfirmed`) the notice reads "Couldn't confirm your message arrived", says the agent may already have it, and offers Cancel and Send again, without Force or mngr's diagnostic text. The message goes back in the composer, and comes back out once the agent's turn for it shows up.

- A message whose send got no answer from the chat app (the connection dropped, or a proxy gave up on a long send) is no longer reported as failed while it may have been delivered. The page sends it again under the same send-time id for about half a minute, and the chat app answers a repeat as it answered the first send, a refusal included, waiting for it while it is still under way, instead of delivering it twice. If it still gets no answer, it gets the unconfirmed notice above, and its copy goes back in the composer and comes back out once the agent's turn for it shows up. Retry after a failed send goes under the failed send's id the same way.
