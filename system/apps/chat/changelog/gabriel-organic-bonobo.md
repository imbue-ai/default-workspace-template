A workspace's first chat no longer loses its `/welcome` for good. Before, the greeting was typed into the chat but its submission was never witnessed, and because `/welcome` is a slash command the create still reported success -- so the workspace's one-per-workspace first-chat claim stayed spent and no later chat could be greeted either. A create that survives but whose greeting was never submitted now gives the claim back, so the next chat is greeted instead. The chat itself is untouched: this is not treated as a failed create. Handing the claim back means a later chat stacks the `first` template again, which also launches that chat in fast mode and shows the fast-mode prompt a second time.

Chats are also better protected from a memory shed while they are launching. A chat's protection is earned from live signals -- an open tab, a visible tab, a recent message -- and for the first seconds of its life it has none of them, which left a brand-new chat scored as the most expendable chat in the workspace at exactly the moment its unrepeatable opening message was in flight. A chat whose process is younger than the launch grace now holds the protected floor, and falls back to the ordinary engagement scoring once it is past it. This changes a launching chat's ordering against workers, agent subprocesses and other chats; it does not put a chat below the workspace's services, so on a freshly booted workspace with no other agents running a launching chat is still the first thing shed.
