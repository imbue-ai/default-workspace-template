A workspace's first chat no longer loses its `/welcome` for good. Before, the greeting was typed into the chat but its submission was never witnessed, and because `/welcome` is a slash command the create still reported success -- so the workspace's one-per-workspace first-chat claim stayed spent and no later chat could be greeted either. A create that survives but whose greeting was never submitted now gives the claim back, so the next chat is greeted instead. The chat itself is untouched: this is not treated as a failed create.

A chat is also no longer the first thing shed when the workspace runs low on memory during its own launch. A chat's protection is earned from live signals -- an open tab, a visible tab, a recent message -- and for the first seconds of its life it has none of them, which left a brand-new chat the most expendable chat in the workspace at exactly the moment its unrepeatable opening message was in flight. A chat whose process is younger than the launch grace now holds the protected floor, and falls back to the ordinary engagement scoring once it is past it.
