The welcome chat's agent starts as soon as the user signs in to a provider, rather than on their first message: the sign-in the chat's "Connect an AI provider" chooser produces launches a chat still awaiting its first send with no message, so the agent is up before the user has typed. The first message sent to it then carries the seeded onboarding conversation ahead of the user's words (as the launch used to), once it has gone through: a send the harness refused or could not take yet leaves the conversation for the next, and a slash command sent first goes as typed and leaves it for the next message too. The chat record carries `is_seed_pending` for this; a record written before it reads as delivered. One send carries the conversation at a time: a send that overlaps the carrying one goes as typed. A message sent while the sign-in's launch is still on its way waits for the chat and goes to it, rather than launching the chat a second time (which the chat app refuses).

A new chat starts with fast mode off unless the workspace's default was changed in the model picker; it used to start in auto (fast for the first two turns). Auto and on are still there to pick, and a workspace whose settings file already names a default keeps it.
