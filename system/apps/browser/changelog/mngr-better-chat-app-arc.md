The browser app gains an `app.toml` manifest (`instances = true`, `priority = "browser"`, a `new` action and a focus-mode default shortcut) and an `icon.svg` (the same globe the rail already draws), and its supervisord program registers through `forward_port.py --manifest system/apps/browser/app.toml` instead of `--name browser --no-icon --program browser`. Like every Python app it now runs from its own uv tool environment: `build_workspace.sh` installs it with `uv tool install -e system/apps/browser`, the program line runs the bare `browser-service` entry point rather than `uv run browser-service`, and the root `pyproject.toml` no longer lists `browser` as a dependency of the workspace venv (it stays a workspace member). Phase 1 of the workspace app model (`docs/system/blueprint/workspace-app-model/`).

Phase 5 of the workspace app model: the daemon serves the instances API (`GET /_instances`, `POST /_instances`, `DELETE /_instances/<key>`, `POST /_instances/<key>/rename`, `POST /_instances/<key>/location`) on its own Flask app, as an adapter over the fleet (`src/browser/instances.py` over `src/browser/bridged_fleet.py`). One instance per browser: key = the browser name, URL `/?session=<name>`, title `Browser N` or the legacy name, status `working` while an agent holds control, `idle` otherwise (a browser still launching included), `error` once it crashed; `explicit`, not renameable. `new` creates as `POST /browsers` does (a `409` with the reason while the fleet is full or Chromium is not installed), delete closes as `DELETE /browsers/<name>` does, and a location report carrying an absolute `http(s)` URL navigates the live browser's active tab (a new `CdpClient.navigate`; `409` while an agent holds the browser or while it is launching or crashed, `400` for a rooted path) and checkpoints the fleet manifest. Reads, delete, and location answer `503` until the saved fleet is restored. A failure of the daemon itself underneath a verb (its loop not answering in time, a startup error) is a `500` with a detail body, not Flask's bare 500. Every fleet event that changes the list or a status (a registration, a launch reaching `running`, a close, a launch failure, a crash, every ownership write) nudges the shell from a daemon thread. Nothing user-visible changes yet: the shell reads `/_instances` from phase 7, and the browser tab, the fleet CLI, and the shell's `/api/browsers` passthroughs behave as before.

The fleet manifest (which browsers exist and their tab URLs, restored on daemon start) moved from `data/.state/browser-fleet.json` to `data/.apps/browser/instances.json`, where contracts section 17 puts every app's instance records; a workspace upgraded across the move keeps its saved fleet because the daemon reads the old path until its first write to the new one (marked `CLEANUP`).

Phase 7 of the workspace app model (the shell core): the fleet manager's lookup (`get`) raises the typed `UnknownBrowserError` instead of `KeyError`, and the daemon's `/browsers/<name>` routes catch that; the fleet CLI addresses a browser's tab as `app:browser?instance=<name>` and targets views with `--view`; the shell's `/api/browsers` passthroughs of phase 5 are gone with the shell's other per-kind routes, so the browser tab is reached through the instances API and the relay alone.


Phase 8 of the workspace app model: the `new` action takes an optional `url` param (an absolute `http(s)` URL; any other param, or a URL that is not one, is a `400`), the page the new browser opens on, so `layout.py open https://example.com` is one create. The start page rides the launch as its tab list and the manifest entry written at registration carries it, so a daemon crash before Chromium is up still restores the browser to that page. `POST /browsers` accepts the same optional `url`, and the fleet CLI's `new` gains `--url`.

A browser's saved tabs survive a stop and start of the browser app and of the workspace. Each browser keeps the tab list its last successful query returned (seeded from the page a create or a restore opened it on) and reports that list whenever Chromium cannot be asked, so a checkpoint taken while Chromium is launching, dying, or crashed keeps the previous tabs instead of recording none; before, a restart came back on `about:blank` because the final checkpoint ran after Chromium had already received supervisord's group SIGTERM and wrote an empty list over the good one. The daemon's shutdown also runs while Chromium is alive now (see the `system/` changelog for the supervisord change).

A browser can be stopped and started on its own: every browser lists as `stoppable`, `POST /_instances/<name>/stop` ends its Chromium (after refreshing its tab list) while keeping the browser, its profile, and its tabs, and `.../start` relaunches it on those tabs from the same profile (`409` while it is still launching or when the fleet is full). A stopped browser has the new `stopped` lifecycle: it does not count toward the fleet cap, its manifest entry carries `stopped` so a daemon restart brings it back stopped rather than relaunched, the fleet CLI's verbs refuse it with status `stopped` and a hint naming `layout.py start app:browser?instance=<name>`, `ls` says so, and the viewer shows a "stopped" overlay with a Start button (the daemon's own `POST /browsers/<name>/start`; `.../stop` is its counterpart) while keeping its socket, so a start from anywhere swaps the live view back in.
