The browser app gains an `app.toml` manifest (`instances = true`, `priority = "browser"`, a `new` action and a focus-mode default shortcut) and an `icon.svg` (the same globe the rail already draws), and its supervisord program registers through `forward_port.py --manifest system/apps/browser/app.toml` instead of `--name browser --no-icon --program browser`. Like every Python app it now runs from its own uv tool environment: `build_workspace.sh` installs it with `uv tool install -e system/apps/browser`, the program line runs the bare `browser-service` entry point rather than `uv run browser-service`, and the root `pyproject.toml` no longer lists `browser` as a dependency of the workspace venv (it stays a workspace member). Phase 1 of the workspace app model (`docs/system/blueprint/workspace-app-model/`).

Phase 5 of the workspace app model: the daemon serves the instances API (`GET /_instances`, `POST /_instances`, `DELETE /_instances/<key>`, `POST /_instances/<key>/rename`, `POST /_instances/<key>/location`) on its own Flask app, as an adapter over the fleet (`src/browser/instances.py` over `src/browser/bridged_fleet.py`). One instance per browser: key = the browser name, URL `/?session=<name>`, title `Browser N` or the legacy name, status `working` while an agent holds control, `idle` otherwise (a browser still launching included), `error` once it crashed; `explicit`, not renameable. `new` creates as `POST /browsers` does (a `409` with the reason while the fleet is full or Chromium is not installed), delete closes as `DELETE /browsers/<name>` does, and a location report carrying an absolute `http(s)` URL navigates the live browser's active tab (a new `CdpClient.navigate`; `409` while an agent holds the browser or while it is launching or crashed, `400` for a rooted path) and checkpoints the fleet manifest. Reads, delete, and location answer `503` until the saved fleet is restored. Every fleet event that changes the list or a status (a registration, a launch reaching `running`, a close, a launch failure, a crash, every ownership write) nudges the shell from a daemon thread. Nothing user-visible changes yet: the shell reads `/_instances` from phase 7, and the browser tab, the fleet CLI, and the shell's `/api/browsers` passthroughs behave as before.

The fleet manifest (which browsers exist and their tab URLs, restored on daemon start) moved from `data/.state/browser-fleet.json` to `data/.apps/browser/instances.json`, where contracts section 17 puts every app's instance records; a workspace upgraded across the move keeps its saved fleet because the daemon reads the old path until its first write to the new one (marked `CLEANUP`).
