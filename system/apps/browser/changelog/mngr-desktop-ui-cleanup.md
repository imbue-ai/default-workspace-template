The browser daemon serves the shell's app contract module from its own origin (`GET /_static/app_contract.js`, the file the shell's frontend build writes), and the viewer page imports it by that same-origin path instead of from the shell's origin, whose cookie-less cross-origin module import the desktop client's forwarder refused with a 403 (so the viewer never reported its path and title to the shell). The `workspace-shell-label` meta tag the daemon stamped into the page for that import is gone. A workspace whose shell frontend is not built gets a 404 naming the missing file.
