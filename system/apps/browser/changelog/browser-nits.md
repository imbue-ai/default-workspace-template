A browser closed by an agent now says so. The pane covers itself with a terminal "This browser has been terminated by an agent." screen -- the same near-opaque overlay the crash/OOM screen uses -- instead of flashing "Loading browser view…" or looping forever on "Starting browser…". A pane you are watching when the browser closes gets told immediately, and a tab you reopen (or that a restored layout brings back) shows the same screen rather than retrying a browser that is never coming back. That holds even across a daemon restart, where the memory of the close was lost: once the fleet has finished restoring, a browser name that resolves to nothing is treated as gone for good, not as one still starting up.

The browser's tips card now leads with "Browser works in the background." -- closing the workspace tab doesn't stop the browser, and agents keep working in it.

The live stream now costs about half the CPU under continuous motion. The frame-rate ceiling defaults to 30 instead of 60, which roughly halves worst-case software-H.264 encode CPU (about one full core down to a bit over half of one) at the cost of a slightly less smooth picture while things are actually moving; an idle screen costs the same as before either way. Motion frames are also encoded more softly, while the paint-over pass that re-encodes the settled screen is unchanged -- so text is still crisp whenever you could actually read it -- and the congestion controller keeps room to soften further when a viewer's connection struggles. The knob is now `BROWSER_VIDEO_FPS_CAP` (was `BROWSER_VIDEO_FPS`), and raising it past the delivery window's limit is refused outright at startup, since a too-high cap is what made the capture rate sawtooth in the first place.
