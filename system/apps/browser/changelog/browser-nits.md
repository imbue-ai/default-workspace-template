A browser you closed no longer gets stuck showing "Starting browser…" when you come back to its pane. Closing a browser is meant to leave the pane on a clear "This browser has been terminated by an agent." screen, but a viewer that reconnected after the close -- for example when you left the workspace and returned, or the tab was restored -- kept spinning on the loading screen forever instead. The signal telling the viewer the browser is gone was carried only by the connection's close code, and the browser's own web server corrupts that code in transit (it writes a stray HTTP reply onto the just-upgraded socket, so the real browser reports a generic "connection lost" and never the specific "terminated" reason). The daemon now also sends the terminated (and failed-to-start) notice as a normal message just before closing, which arrives intact, so the pane reliably lands on the terminated screen instead of retrying. The live-video connection now acts on that notice on its own too, so it stops reconnecting to a gone browser even if the control connection is slow or unavailable.
