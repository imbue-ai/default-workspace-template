The agentic browser fleet now streams through the hardened streamed-browser display stack instead of the old CDP screencast with rebuilt HTML tabs and address bar: each browser is a full Chromium -- its own tabs, omnibox, and native menus -- streamed as damage-driven H.264 (pixelflux stripes, CPU-only) with display-level XTEST input, on its own private virtual display. browser-use is now the single connection driving each browser, so switching tabs switches the real tab and the pane follows whatever tab an agent acts on; a crashed browser is detected and reported instead of freezing. Copy and paste work both ways for text and images, videos play with sound (per-browser Opus audio, only while a tab actually makes sound), and a "View tips" card explains the controls. A browser pane that isn't being shown -- the workspace tab backgrounded, or the browser not the active tab -- throttles to about 1 FPS so it stops burning CPU while nobody is watching, and returns to full rate when shown again. The starting screen now shows a progress bar and reflects the real stage: "Starting browser…" while Chromium is coming up, then "Loading browser view…" once the browser is up and drivable and only the pixel view is still loading.

Only one browser view streams at a time across the whole app and every device -- the pane you are actually looking at. Every other view (another browser, a split pane, another device) fully pauses: its encoder stops, so it costs no CPU and no bandwidth, and it resumes in a fraction of a second when you look at it again. A paused pane shows a "Livestream paused" card that also notes when an agent is still working in the browser, making clear the browser keeps running while only the live view is paused. When the machine crosses three-quarters of its memory a red warning bar appears above the view suggesting you close some tabs, and hides itself when memory recovers. Each browser is now held to a single window: opening a second window (Ctrl+N or dragging a tab out) is not supported, so the extra window is closed with a short explanation and the main window is kept pinned to fill the pane, and the default limit is two simultaneous browsers. The browser now resizes to fill the pane reliably as it opens: a real pane size is always reported (only a genuinely collapsed, hidden pane is skipped), and the true size is re-reported the moment the pane becomes visible, so a stale early measurement can't leave the browser stuck small in a larger pane.

A round of hardening tightens the daemon's edges: the debug-telemetry endpoints now only accept a known, registered browser and coerce uploaded timing records to their expected numeric fields, so a bad client can't pin large data in memory or watch a made-up browser; the copy-out clipboard can be read only while you hold control (so an idle agent can't lift a password a person just copied); oversized control messages and clipboard pastes are rejected; and the control channel gets the same per-browser connection limit the video channel already had.

The live frame rate no longer sags and stutters behind interaction. The capture-rate controller was collapsing to a crawl and sawtoothing back up: the in-flight credit window was sized for only 30fps, so at a typical viewer round trip it pinned to its floor and throttled delivery below the frame rate the encoder was producing, and a single burst of dropped frames then slammed the rate all the way down before it climbed and crashed again. The window is now sized to carry the full frame rate, and a single drop interval is treated as ordinary overshoot -- the rate shaves off a little and holds near the top instead of collapsing, dropping in earnest only when frames keep being lost across several seconds (a genuine capacity limit). Measured under continuous full-screen motion the stream now holds ~60fps instead of sawtoothing 8-32, and under ordinary interaction the round trip sits on the network floor -- the remaining delay is the network, not the encoder.

A browser reopened after a long disconnect no longer comes up stuck in a small, upscaled window. The viewer measured its pane off the canvas element, whose box can read small before the pane has laid out; that early measurement locked the capture at the wrong size, and nothing re-checked it afterward, so it stayed wrong until a manual resize or a close-and-reopen nudged it. The viewer now measures the stable pane container instead, and re-asserts the true pane size on a short cadence, so it self-corrects within a couple of seconds instead of waiting for a manual resize.

Streamed browser sound now actually plays for the ordinary viewer. Per-browser Opus audio was only ever started when a paused view was resumed, but a view you open and immediately watch is never paused first, so its audio was never started and the browser stayed silent, even though the video and the whole capture pipeline were healthy. Audio now follows whether you are watching the view directly, independent of that pause-and-resume moment, so sound plays as soon as a tab makes noise. (You still click into the view once to let the browser start audio, the same one-time interaction every site needs.)
