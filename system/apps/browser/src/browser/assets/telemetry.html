Distance vs loss — round-trip time

Server-clock round trip (send → ack). Includes the viewer's decode+paint (no client taps in Rung 1), so this is transport plus client render, not pure network. Verdict logic: a low, steady floor with a thin tail = distance; a fat tail (p99≫p50) = loss / head-of-line stalls. Trust the percentiles only when the sample count is healthy.

Cross-row round trip

One line per stripe row (this host runs 2). All rows spiking together = the shared TCP socket stalled (network / head-of-line). One row alone = that row's decoder, not the network.

Server-side mailbox wait

Time a finished stripe sat waiting for a flow-control credit (mailbox → sent). This is the largest latency the server itself controls. Capture+encode before it is engine-internal and not measurable.

Mortality — drops & unacked

Application drops (deliberate staleness-bounding), not network loss. "Unacked" = sent stripes with no ack after 2s — candidate wire loss.

Local hop (TCP_INFO)

The daemon's socket peers with a local forwarder, so this sees the loopback hop only — it rules out local buffering, it does not see WAN loss.
