The Screen no longer re-grants control to a session that has just returned it. neko reports the host changes the service itself makes (give, reset, locking) on the same event socket as a human taking an uncontrolled Screen, and the service read every one as the latter, so a late echo of its own `give` put the previous controller back in charge and the next person's first input was dropped as a non-host's; the service now tells its own changes apart by neko's API session as the event's initiator and only keeps its host record from them. Found by the staging smoke run's template suites, where the drop test's take-and-return left the touch test's first touch on the floor. The human take and return verbs now also answer only once the lease has reached neko, so a session that sends its first input right after another returned control is a request neko grants rather than a non-host's input it drops.
