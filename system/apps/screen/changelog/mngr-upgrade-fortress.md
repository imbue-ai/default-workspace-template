The Screen service now registers the saved browsers from the tab manifest (or, with no manifest, the profiles on disk) when it starts, before any stack runs. Previously the fleet learned of them only when the stack came up, so a `browser` launch or an agent's `new` arriving while the stack was still down minted a fresh name beside the saved browser; that browser's first checkpoint dropped the saved entry from the manifest, and the next restore swept the saved profile -- deleting an upgraded (or merely restarted) workspace's tabs and logins. What relaunches when the stack comes up stays the restore's decision. Found by the pre-Screen -> Screen upgrade end-to-end test, where the first browser launch after the update destroyed the migrated `browser-1`.
