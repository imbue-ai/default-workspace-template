The watcher now writes a `service_registered` event only for an app whose registry row actually changed, instead of re-announcing every app in the registry whenever the file's mtime moves. It remembers each app's registered fields (URL, label, icon) rather than only its name, so a relabelled or re-pointed app is still announced, a new one is announced once, and a removed one still deregisters. The first pass after startup announces everything, as consumers reading from the start of the stream need the whole set.

`forward_port.py` replaces the registry file in full every time any app registers, so an mtime change said nothing about which apps changed -- and a program that restarts in a loop turned into a permanent flood. On one production workspace an app restarted every 1.86 seconds for four days; each restart re-registered it, and the watcher fanned each rewrite out to one event per app in the file. That came to 46,371 rewrites and 602,823 events in a single day, and grew the workspace's service event log to 1.1 GB. The registry's contents never changed across the whole flood -- every label was identical from the first event to the last.

The sibling change in `forward_port.py` stops the rewrite itself when nothing changed, so the two together mean an app restarting in a loop produces no service events at all after its first start.
