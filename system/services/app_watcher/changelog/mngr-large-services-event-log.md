At startup, a services log over 5 MiB is archived out of the replay. Consumers (the minds desktop forward, through `mngr event --follow`) replay the whole `events/services/events.jsonl` each time they attach, and an older watcher that re-announced every app on each registry rewrite grew some of these logs past a gigabyte: one production workspace's reached 1.16 GB, about 341,000 repeated registrations. The watcher now renames such a log aside before its first pass, so that pass starts a fresh log holding only the current apps, then gzips the old one to `events.jsonl.<timestamp>.gz`, a name mngr does not replay. It keeps the newest three archives. A log under the threshold is untouched. If compression fails, the watcher logs a warning and keeps running rather than restarting into the same failure.
