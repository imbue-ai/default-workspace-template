Shared workspaces now work when opened directly on a phone. The share gateway used to set its session cookie with the CHIPS `Partitioned` attribute only (needed for the hosted chrome's cross-site iframe), which Safari 18.5 through 26.1 rejects outright (WebKit bug 292975). On a phone that meant the page's own scripts and styles were denied with 401 after a successful sign-in (a blank system_interface, an app rendered as bare HTML), and every refresh went back to accounts.imbue.com.

The login callback now sets the same signed value as two cookies: a plain `imbue_machine_session` (`SameSite=Lax; Secure; HttpOnly`) for top-level visits and `imbue_machine_session_partitioned` (`SameSite=None; Secure; HttpOnly; Partitioned`) for the iframe case. Verification accepts whichever copy the browser sends, and both are stripped before a request reaches a service. The plain copy is Lax rather than None so that a foreign site cannot make a visitor's browser attach the session to subresource requests or fetches aimed at a workspace origin (plain GETs are exempt from the gateway's Origin policy); Lax still covers the phone flow, since the post-login callback is a top-level navigation and everything the page then loads is same-site.
