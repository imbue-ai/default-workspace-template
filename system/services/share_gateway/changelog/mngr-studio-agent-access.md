Visiting agents: a coding agent running outside the workspace can be invited in with a one-time code and then works through the workspace with the workspace's own authority. The gateway gains the `/_agent/*` surface on the auth origin (join, me, primer, skills, changes, invites, grants) and admits a bearer admission token beside the session cookie, resolving it against a new agent grant kind kept in `data/.secrets/agent_access/grants.toml` and scoped to the whole workspace (every origin, exec authority through owner-exec via a reconciled `authorized_keys` line) or to named apps. A served single-file Node helper (`wsvisit`) joins, signs owner-exec requests, verifies responses, refreshes the skills index daily, and heals moved coordinates. The `agent-access` CLI exposes invite, list, revoke, primer, skills, changes, and reconcile for the desktop and the terminal; with `--json` its refusals are JSON on stderr, and its events record whether the gateway or the CLI asserted the granter. Every writer of `~/.ssh/authorized_keys` (the gateway's reconcile and the desktop's SSH grant) now holds `authorized_keys.lock` around its read-and-write. Caddy routes `/_agent/*` on the auth origin and strips `Authorization` before every backend. Design: `specs/studio-agent-access/spec.md` in the mngr repo. The CLI refuses a non-positive `--expires-in-days` the way the invite route does; the helper refuses a state directory that is not private when it reads from it, tells an app-scope agent that inviting needs the whole workspace instead of calling it revoked, and names the clock skew behind a signature refusal. The helper no longer runs a command a second time when the run's stream trailer fails verification: it refreshes the workspace's addresses for the next command and reports the failure after the output. The helper drains its stdout and stderr before exiting, so a large answer read through a pipe (where Node writes asynchronously on macOS) keeps its tail. The join route bounds the body it reads rather than the body it has already read, and the grants and invites files escape every control character a stored string carries, so a trusted caller's odd input can no longer leave the files unreadable. The marker lines that bound the exec-only passages of the primer and the instruction block are removed from the rendered text for workspace scope, not only (with the passages) for an app scope. The helper refuses a `--timeout` that is not a positive number of seconds (one given without a value used to run the command with a one-second timeout). The gateway replaces `last_seen.json` atomically, so a listing that reads it mid-write no longer blanks every agent's last-seen time.

The helper refuses an `--expires-in-days` on `wsvisit invite` that is not a positive number of days (a bare flag used to mint a one-day grant, and a word a grant with no expiry at all), the way it already refuses such a `--timeout`.

When the helper cannot reach the workspace, it says the workspace may not be published right now and that its owner publishes it from the Share panel, since an unpublished workspace is the usual reason the share's addresses stop answering.

A workspace record the gateway cannot read (a truncated host `data.json`, an unreadable host public key) is logged rather than silently read as empty, so a join answer with no host id or host key can be traced to its cause; an absent record still reads as empty quietly.

A join or a revoke that drops an expired grant records the `expired` event for it, as the gateway's start-up reconcile already did, so a grant's event trail always ends with its expiry or its revocation.

The auth-origin label is created atomically: the gateway starting the stack and the `agent-access` CLI minting an invite can both create it on a workspace's first publish, and the one that loses now answers the label the other stored, instead of a second label the running gateway would not serve.

The orientation renderers log what they fall back from: a git invocation that fails or times out, a skill file that cannot be read, a skills-index cache that cannot be parsed, and a missing primer or instruction-block reference file each leave a line in the gateway's log beside the degraded answer they still render.

The helper an invite installs is pinned to a published source: the instruction block fetches it from the template repository at the workspace's exact ref (`raw.githubusercontent.com/imbue-ai/default-workspace-template/<tag or commit>/...`) and checks the SHA-256 the block carries, with the workspace's own `/_agent/helper` as the fallback for an unpublished commit; `/_agent/helper` answers an `X-Helper-SHA256` header, the join and `me` answers carry a `helper` object (`version`, `source_url`, `sha256`), and the helper warns on stderr when its own hash is not the one the workspace publishes, naming where to reinstall it from.

The helper's published address, the `X-Helper-Version` header, and the `template_ref` the orientation routes report now name the workspace's template commit (the one it was created from, or the upstream commit its last `update-self:` merge brought in) rather than the workspace's own HEAD, which bootstrap's initial commit puts past anything GitHub has, so the pinned download no longer 404s. The helper gains `wsvisit get <app>/<path>` (or a URL on one of the workspace's origins): the admission token goes with the request as a bearer and to those origins only, and an app that answers 503 with `Retry-After` while it starts is waited out.
