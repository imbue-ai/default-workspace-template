Visitors to a shared workspace now stay signed in for 30 days instead of 24 hours. The workspace session cookie the login callback sets was fixed at 24 hours and nothing renews it on use, so anyone using a share link -- the owner included -- was sent back through accounts.imbue.com roughly once a day. Where the accounts sign-in is still alive that costs a "Continue as ..." click; where it is not, a full sign-in. A browser that rejects the CHIPS `Partitioned` attribute is in the second case, because the connector sends its accounts session cookie with that attribute and no plain copy; Safari 18.5 through 26.1 is such a browser (WebKit bug 292975), which is the same lone-`Partitioned` pattern already fixed for this gateway's own cookie.

The session is still fixed rather than sliding, so 30 days is an absolute cap from the moment of login, not an idle timeout. Revoking someone's grant still cuts them off immediately -- the gateway re-reads the grants file on every request -- but an account revoked at the broker (sign-out, suspension) is not re-checked by the gateway, so that now takes up to 30 days to be felt on an already-issued session.
