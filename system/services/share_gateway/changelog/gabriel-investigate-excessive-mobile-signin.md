The share gateway now logs every sign-in it asks for and every sign-in it completes, so a visitor who keeps being asked to sign in (an iOS home-screen web app, for one) can be diagnosed from the log. A `Sign-in required` line names, for each copy of the session cookie, whether the browser sent it and, if so, why it opened no session (expired, signed with another key, issued for another domain, malformed) along with when it was issued and expires, plus the names of the request's other cookies, its `Sec-Fetch-Dest`/`Sec-Fetch-Site`, and the browser's user agent. A `Signed in` line records the new session's issue time and the user agent. A request denied for having no session now carries the same per-copy detail. Cookie and token values never reach the log.
