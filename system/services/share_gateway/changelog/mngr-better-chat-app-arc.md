The README describes sharing under the workspace app model: the `[services.<name>]` grant key is the app's registered name and the file keeps that key; the chat app's pages are served at their own registered origin, so a workspace-level grant admits the chat origin directly and a `[services.chat]` grant narrows a visitor to it; a visitor holding only a per-app grant reaches that app's origin and nothing else (not the shell, so not the tabs the shell arranges), and a `[services.files]` grant admits only the file viewer. The grants example gains a `[services.chat]` block. No code changes: caddy already re-renders its routes from the registry, so the chat origin is claimed and routed as soon as the app registers.
