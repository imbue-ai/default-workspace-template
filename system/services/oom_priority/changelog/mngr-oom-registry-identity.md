- The agent-pid registry now records each agent process's start time and boot id, and a reader counts an entry only while its pid is still that process: not a thread of another process, and started at the recorded time in the same boot. Under gVisor pids are reused within hours, `/proc/<id>` also resolves for a thread, and the registry outlives a container restart. So a leftover entry could point the chat app's prioritizer at an unrelated process. That is the likely way one workspace's chat app ended up marked as an abandoned chat (`oom_score_adj` 800) and was shed during an update. An entry written before this change, which has no start time, counts while its pid is a process whose environment carries the agent id the entry records, so chats that are already running keep being re-tagged until they next start. The earlyoom kill hook, which reads an entry after its process is gone, no longer names an agent from an entry recorded in an earlier boot.

- `lookup_pids_by_agent_id` returns every live process of an agent, so both of a codex chat's processes (its TUI and its app-server) get re-tagged rather than only one.

- The memory candidates command reports each candidate's anonymous memory (from `smaps_rollup`, or `smaps` under gVisor) instead of summed `VmRSS`. Under gVisor `VmRSS` counts every mapped binary in full and read about two times too high for a claude chat, three for a codex TUI and ten for codex's helper. The JSON field is now `anonymous_kib`. A new `--free-memory` flag prints only the free memory line, reading nothing but the meminfo files.
