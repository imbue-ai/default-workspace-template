The OOM band-coverage checks now read the supervisord config the way supervisord does, following the `[include]` globs into `system/supervisord.conf.d/`.

Those checks parse the config with `configparser`, which does not follow supervisord's `[include]`. Once programs moved into per-program drop-in files, a bare read of the main config returned a single program, so `test_every_service_key_in_supervisord_conf_has_a_band` and `test_every_built_in_supervisord_program_has_an_explicit_band` were asserting over one program out of thirteen -- and still passing, because their guards were satisfied by that one program. That is precisely the silent gap they were written to close, after `xvfb` and `env-converge` sat mis-banded for months. Both now see all thirteen programs, and both still pass.
