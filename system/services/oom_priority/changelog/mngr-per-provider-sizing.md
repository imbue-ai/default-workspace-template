A local docker workspace under runc now feeds earlyoom its own memory cap. The new `publish_cgroup_meminfo` program (`bin/publish_cgroup_meminfo.py`, over the new `cgroup_meminfo` module) reads the container's cgroup v2 memory controller four times a second and writes its limit and headroom to the file earlyoom reads with `--host-meminfo`, with the same formula the gen-2 slice VM uses; before, the container's `/proc/meminfo` reported the whole machine, so earlyoom never acted before the cgroup OOM killer. It exits under gVisor, removes the file while the container is uncapped, and touches nothing where it has no answer (no cgroup v2 memory controller, as on lima, or an unreadable counter). The program is PROTECTED, like earlyoom and the backstop listener.
