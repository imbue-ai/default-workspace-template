New `SPARE_AGENT` band (1000, the ceiling) for a spare chat agent: one the chat app starts ahead of the next new chat and that no one uses yet. The launch wrapper puts an agent labelled `chat_spare=true` (`agent_identity.is_spare_agent`) in it, so the spare and every process it spawns are shed before anything else under memory pressure, after a restart too. Once a chat takes a spare, or a chat awaiting its first send holds a reserved spare that is up, the chat band policy holds that chat at the engaged floor for its first minute (`CHAT_JUST_STARTED_GRACE_SECONDS`) before scoring it like any chat.

The browser band now tops out at 990 (`SHARED_BROWSER`, down from 1000; the floor stays 910), so renderers still sit at the top of their band but below a spare, which holds no one's work where a renderer costs a tab.

`memory_candidates.py` leaves agents labelled `chat_spare=true` out of its idle chats, since no chat list shows a spare until a chat takes it.

The registry no longer has `lookup_pid_by_agent_id`: the chat app, its only caller, now reads every live pid of an agent through `live_pids_by_agent_id`.

The revival-notice hook (`claude_shed_notice_hook.py`) no longer tells a new agent about an earlier agent's shed. The chat app destroys a shed spare and mints the next agent under the same name ("Chat N", or the name of the empty chat it is reserved for): the spare's replacement, or an ordinary new chat created before the replacement starts. That agent used to find the earlier spare's shed record and carry the notice into a chat that had just begun. A record older than the agent's own `create_time` (`agent_identity.agent_created_at`), and any record while the agent is still labelled `chat_spare=true`, is now marked delivered without the notice; a shed of the agent itself, once a chat has it, is reported as before.
