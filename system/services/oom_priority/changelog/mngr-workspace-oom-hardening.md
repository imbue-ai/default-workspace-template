The `publish_cgroup_meminfo` program (local docker workspaces under runc) now publishes MemAvailable as the cgroup limit minus usage plus only the inactive file cache, the same signal the kubelet evicts on and the same change as the gen-2 VM's publisher in mngr. It used to add the active file cache and reclaimable slab too. Near the limit those are what the kernel thrashes rather than frees, so the figure could not fall far enough for earlyoom's SIGKILL threshold to fire before the cgroup OOM killer did.

earlyoom's log now says when each line was written. earlyoom runs through `run_with_timestamped_output.sh`, which execs it (supervisord still signals earlyoom itself) with both of its output streams going through `earlyoom-stamp` into `/var/log/supervisor/earlyoom-stderr.log`, each line prefixed with its UTC time to the millisecond. `earlyoom-stamp` is in earlyoom's `--avoid` list, since earlyoom's own output goes through it. Without timestamps, a workspace's OOM kill could not be lined up against what earlyoom was doing at the time.
