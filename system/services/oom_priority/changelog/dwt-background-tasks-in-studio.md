`memory_candidates.py` no longer offers an agent whose chat is waiting on a background task as safe to stop. Such an agent has ended its turn, so mngr lists it as `WAITING`, but the task's completion will start its next turn, and stopping it would lose the work in flight. A candidate must now be `WAITING` and in a chat that is not busy: no live marker under the chats' background task directory, read through `system/scripts/background_tasks.py` for the agent's `chat_id` label, else its own id. The table's heading says so ("waiting, not on a background task"), and the README's "Memory candidates" section describes the rule. A tree without that script has no busy chats.
