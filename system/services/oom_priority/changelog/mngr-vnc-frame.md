`SERVICE_BANDS` gains `screen = 72` (between `cron` and `files`) for the Screen service, and loses `xvfb`, whose program is gone; the Screen's stack members (`screen-xorg`, `screen-session`, `screen-pulse`, `screen-neko`) and its `screen-watch` listener resolve to the Screen's band by program name through `_NON_SERVICE_PROGRAM_BANDS`, so the backstop never pushes them to the user band.

With the browser's migration onto the Screen (the Screen spec, section 16), `SERVICE_BANDS` loses the `browser` key: the browser app and its coordinator program are gone, and the Screen service (`screen`, 72) is what launches Chromium now. The shared-browser band stays for Chromium's processes, remapped into it by the Screen service's raise-only band sweep (`system/apps/screen/src/screen/band_sweep.py`), which also raises every other program started from the Screen to `AGENT_SUBPROCESS`; the README's band table and "The Chromium exception" say so.

`memory_candidates.py` reads the fleet from the Screen service (`MINDS_SCREEN_SERVICE_URL`, the `screen` registry row, else `http://127.0.0.1:8090`) and lists a running browser as a candidate while no window of the Screen exists on any desktop (the browser's windows are on the Screen, which never stops for emptiness); a candidate's `controller` reads `human` for any human in control of the Screen.
