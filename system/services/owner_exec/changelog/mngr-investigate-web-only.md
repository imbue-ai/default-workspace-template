New `owner-exec` service: an owner-authenticated in-workspace exec surface (run a command with streamed output, read a file, write a file, read/replace the sharing grants) that the hosted minds web client drives instead of an SSH session. Every request is authenticated by an Ed25519 signature over the request envelope, verified against the workspace's `~/.ssh/authorized_keys` and bound to the workspace's share domain, timestamp, and a single-use nonce -- so authorization equals possession of a key the workspace trusts. Exec is unavailable while the workspace is not shared. Runs behind the share gateway's owner-session forward_auth as defense in depth.

Note: the `[program:owner-exec]` supervisord entry is temporarily commented out — `uv run owner-exec` spawn-errors under supervisord in a built workspace (cause undiagnosed; it broke `supervisorctl restart all` during restore). The package and its tests remain; re-enable once the spawn error is understood.
