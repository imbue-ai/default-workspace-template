The grants endpoints are now compare-and-swap capable, so two clients (web chrome and desktop) editing sharing grants concurrently lose cleanly instead of silently overwriting each other. `GET /grants` returns a `revision` alongside the document (a digest of the file bytes; `""` while no grants file exists), and `PUT /grants` accepts an optional `base_revision`: when given and stale, the write is refused with `409 {"error", "revision", "grants_toml"}` carrying the current document so the caller can merge and retry. Omitting `base_revision` keeps the old blind-replace behavior. Successful writes return the new revision, and the read-compare-write runs under a server-side lock.
