Backup retention now actually thins old snapshots. `restic forget` applies its keep-hourly/daily/weekly/monthly policy once per *group*, and restic's default grouping is host plus paths -- but every tick reads from its own uniquely-named snapshot path (`<mount>/snapshots/<timestamp>/home`), so each snapshot landed in a group of its own and "keep 1 hourly" kept all of them. Retention had never removed anything: one workspace measured here was holding 987 snapshots, every hourly backup since it was created. The forget now runs with grouping disabled, so the whole repository is thinned as one unit; the same workspace keeps 56.

The first forget after this lands removes the whole backlog on an affected workspace, and the daily `restic prune` that follows will take much longer than usual that one time while it reclaims the space.

A snapshot that does not contain the subtree the backup reads now fails the tick with an error naming what the snapshot does contain. Previously the path was handed to restic unchecked, and the tick died a step later on restic's own "…/home does not exist, skipping" followed by "Fatal: all source directories/files do not exist" -- a complaint about restic's arguments that never mentioned the snapshot they came from, which made a workspace whose volume has an older layout look like a broken restic rather than a mismatched snapshot.
