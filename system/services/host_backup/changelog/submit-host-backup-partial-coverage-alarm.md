A backup that quietly leaves out most of what you care about now says so. On hosts where only the mngr host dir sits on persistent storage, your workspace is not on it -- it lives on the container's own disk, which does not survive the container. A backup of that storage therefore covers agent state, chat history and logs, and none of your actual work. Nothing about it looked wrong: the backup succeeded and reported success, so anyone asking "am I backed up?" got a confident yes over an unrecoverable workspace.

The service now checks at startup whether the whole backup root is on the same persistent storage as the mngr host dir, by comparing the filesystem each is on. When they differ it logs an error and writes a durable `BACKUP_COVERAGE_IS_PARTIAL` event naming what is excluded. The check is deliberately conservative: when either side cannot be read it reports full coverage rather than raising a false alarm, and the `direct` method -- which takes no snapshot and reads the backup root live -- never reports a gap, because it does not have one.

This does not widen the coverage, which cannot be done from inside the container; the layout is chosen by whatever provisioned the host. It makes an invisible gap visible.
