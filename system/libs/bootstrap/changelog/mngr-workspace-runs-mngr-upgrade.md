Each boot runs `mngr upgrade` with the workspace's own mngr on every stopped local agent before anything starts one, so chats and workers an older mngr created get the current mngr-generated hooks and scripts and stay stopped. Agents already running are left out. The new step (`upgrade_agents`) is skipped while an update apply is in flight and when the boot's venv sync failed; it is bounded, logs each agent's outcome, and never stops the boot.

Once a pass leaves every agent current, it records the mngr it ran (the commit each of its installed packages came from) in `data/.state/agent_upgrade/coverage.json`, and later boots start no mngr process until the venv's mngr changes. The pass is also a command, `upgrade-stopped-agents`, which update-self runs after an update lands or is rolled back.
