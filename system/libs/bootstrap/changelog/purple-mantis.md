The container keeps the user's timezone when the boot-time fetch fails. Before, a boot that could not reach the minds app on the user's computer (it was asleep, offline, or its tunnel to the workspace was still coming up) left a freshly created container on UTC, so cron schedules ran in UTC until some later boot's fetch succeeded. The bootstrap now records each zone it applies in `data/.state/user_timezone` and re-applies that zone whenever the fetch fails.
