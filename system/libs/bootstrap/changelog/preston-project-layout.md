The bootstrap still files "Chat 1" into the machine-wide member-title store, because nothing yet lifts the `display_name` label into the serialized agent state the frontend draws tabs from; that write goes away once the label is plumbed through.

The create names only the agent: the host is implicit, since the bootstrap runs inside it. Passing `Chat-1@<host>` instead asked mngr to look up a host by that name and failed with "Could not find host", leaving a booted workspace with no chat at all -- the same shape of failure this naming work set out to end.
