Bootstrap checks for an interrupted update apply at container start (the marker under `data/.state/update-apply/`) and rolls it back before the venv converge and before any service or agent starts, via `update_self.py recover --if-stale --no-restart`. The rollback is git restores plus plain copies of the pre-apply snapshots -- no network, no package manager and no working mngr -- with one exception: an apply that had reached its provisioner step is rolled back by re-running `setup_system.sh`, which does reach the network for the pinned toolchain. Once the venv is converged, bootstrap wakes and messages the DRI agent the marker names, best-effort, so someone verifies state and talks to the user about retrying; the wake is held until after the converge so the woken agent's `uv run` calls cannot race it.
