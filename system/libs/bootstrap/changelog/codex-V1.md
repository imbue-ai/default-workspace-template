Bootstrap now converges the workspace venv (`uv sync --all-packages --frozen`) at boot, before the initial chat agent is created and before supervisord starts. The venv is a bake-time artifact while the working tree is a landing-time artifact; on docker and pool-lease hosts nothing re-ran the sync at create, so a bake older than the landed branch left the first implicit `uv run` to reconcile them lazily -- mid-boot, concurrently with the services and the first agent, and with root-closure scope rather than `--all-packages`. Processes importing during that rewrite window failed intermittently (`ModuleNotFoundError: imbue_common` and friends), which codex agents hit hardest (exec-per-tool-call from the first prompt). Best-effort with a 600s bound: a sync failure is logged loudly and boot continues (the implicit per-`uv run` syncs remain the fallback).

The initial `/welcome` chat agent is now created with a stacked harness and role template (`-t claude -t chat`) rather than the single `chat` template, following mngr's split of create templates into harness and role. `--transfer none` is no longer passed explicitly -- the `chat` role template owns it, which keeps the value in one place instead of two that could drift. The welcome agent stays claude-only.
