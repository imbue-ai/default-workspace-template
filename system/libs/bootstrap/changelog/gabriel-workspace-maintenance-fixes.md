The every-5-minutes update-apply recovery guard runs again on containers whose `/run` is a tmpfs, which is every gen-2 imbue_cloud slice and every desktop docker workspace. Its cron entry took its `flock` lock at `/var/lock/update-apply-recover.lock`. In this image `/var/lock` is a symlink to `/run/lock`, and a tmpfs `/run` starts out empty, so `flock` failed with "No such file or directory" on every tick and the guard never ran. An interrupted update apply was then never recovered unless the container restarted. The lock is now `/run/update-apply-recover.lock`, directly under `/run`, which exists on every container.
