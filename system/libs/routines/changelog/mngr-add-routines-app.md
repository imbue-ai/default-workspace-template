New: the routines library, everything in the workspace that runs on a schedule. One TOML definition per routine under `system/routines/`, a scheduler (interval or one-off, time of day, weekdays, day of the month, catch-up after downtime, retry after a failed run), one runner for command runs and skill runs (which wake the routine's own chat and wait for the agent's turn through the chat app), per-routine state, an append-only run ledger with a log per run, notifications to the Imbue Studio feed (headed by the routine's title) after repeated failures, on recovery and when an agent waits on the user, whether the agent was woken by a skill routine or by `routines wake` from a command routine's run, the `routines` command for agents, the cron env wrapper, and `routines migrate-cron`, which converts the cron entries a workspace wrote before. The listing names the apps routines belong to (`app_names`, from the app registry), a run in flight is told from a reused pid by the process's start time, and a spawned run's own output goes to its run log.

`routines wake` names the chat after the routine and waits as long as the routine's `timeout` says when the routine is defined (`--title` and `--timeout` still override), so a command routine that wakes its agent is recorded as a skill run is.

`routines migrate-cron` also converts a plain cron line's weekday lists and ranges (`1-5`, `1,3,5`) and a runner job id with capitals or underscores, leaves an entry whose routine already exists in place, and points every entry it leaves with cron at the env wrapper's new path. The command refuses a `--days` or `--once` it cannot read, a mistyped `--run-id`, and a `routines log` for a run the routine never had, each in one line; an empty `--at`, `--days` or `--app` clears the field on `edit`; a wake inside a run never waits past the run's own time. The Fix brief quotes the last finished run's output. A skill run reads a turn longer than one transcript page to its end, so its summary is the agent's last message and a long turn is never mistaken for one that is still going. A skill run whose agent worked and went idle without answering ends failed a minute later, instead of waiting out the routine's timeout and interrupting an idle chat. A state file that cannot be opened is an error rather than a fresh start, and one whose content does not parse is kept beside the fresh one (`state.json.bad`) when the next write replaces it. `routines add` and `edit` refuse `--every` beside `--once`, and `--skill` beside a command, instead of keeping whichever came last. `routines migrate-cron` converts an entry file whole or not at all, leaves a reversed weekday range with cron, and skips a line whose duration or time of day it cannot read instead of stopping the whole pass. A routine may not be called `events`, the run ledger's directory beside the routines' own state. A skill run the chat app refuses to interrupt at its deadline is still recorded as timed out, and a run spawned by the Routines app is collected once it exits.

A manual start (`routines run <id>`, the app's Run now) answers its receipt once the run has taken hold, so a page read right after it shows the run; a run record a dead runner left behind no longer counts as a run in flight for a start or a removal. A skill run waits out a chat app that is unreachable mid-turn for two minutes (a restart, a bounce) instead of failing at the first poll. `routines wake` inside a command run leaves how it ended (a timed-out wake is a timed-out run) and its warnings in the run's `result.json`, which the runner records. A definition commit is retried only when another writer holds the index or a merge is in progress.

A run the tick closes off as interrupted counts as a failed attempt (the streak grows and the feed is told at the threshold), and the tick first stops the command a dead runner left running, whose process group the state records. A run records itself in the state before the ledger, so a runner that dies between the two is reaped. The ledger's appends and rotation share a lock. A run tries its lock a few times before it counts as refused, nothing probes the lock to ask whether a run is going, and a manual start that loses the routine to a run arriving at that moment is refused rather than handed a receipt. A message the chat app holds for a handoff is waited out: a held clear settles before the transcript cursor is read, and a held skill command gets two minutes to start.
