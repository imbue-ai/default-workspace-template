Routines an app owns now live inside the app, at `system/apps/<package>/routines/<id>.toml`, and are listed and run beside the ones under `system/routines/`; `routines add --app <name>` writes there when `<name>` is a user app (its directory and its record `system/config/apps/<name>.toml` both exist). The library never rewrites or deletes a file inside an app: rescheduling such a routine keeps the new schedule in its state (`schedule_override` in `state.json`) with no commit, and the routine runs on it until it is rescheduled back to the file's own schedule, while `routines edit` of any other field and `routines remove` are refused with a message naming the app's directory. A routine id that more than one file has is listed once, as broken, naming each file. Routines under `system/routines/` behave as before.
