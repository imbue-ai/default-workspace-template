`run_automation.sh` no longer stacks a `claude` create template (which stopped existing when harnesses moved to `--type`) or resolves an account through `system/scripts/default_account_args.py`. The automation agent runs on the workspace's default provider account and its harness, which the chat app keeps in `.mngr/settings.local.toml` for every unqualified `mngr create`; a new `--type <harness>` option names a harness explicitly. With no account signed in the create is refused with a message that says to sign in.
