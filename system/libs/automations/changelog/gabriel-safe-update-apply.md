`with_agent_env.sh`'s "every cron job should be prefixed with it" rule now names its one exception: the built-in `update-apply-recover` guard the bootstrap writes at each boot carries its own `PATH` line and `cd` instead. The wrapper rebuilds the agent environment from `/home/user/.mngr/env` (with `jq`) and exits non-zero when that is missing, which is exactly the state a workspace left mid-update can be in -- so the one entry whose job is to repair that state cannot depend on it.
