`app-install link <name>` gives an app its own history and its private dev repository. For an app the workspace built it makes the first `git subtree split` with a join marker, in a clone bounded by the app's age (falling back to the whole history when the bounded clone would read the app's history differently), and moves the primary branch to the marker without touching a file; `--refresh` makes a new marker once the app has changed since its last, from a split cut at that last marker the way the sync service cuts its own, so the marker joins the history the service has been pushing whatever was merged in between. With GitHub sync enabled, or with `--create-dev-repo`, it creates the private repository `<name>-dev`, writes its URL to the app's record and commits that one file. A modified installed app gets only the repository; an unchanged one is refused, and so is a run in a worktree that is not the primary checkout, and an app whose directory was removed and made again, whose own history would carry the workspace's. The result says whether a repository was created and what remains.

`app-install list` reports `modified` for an installed app whose committed directory differs from what was installed in any path outside the regenerable set (`uv.lock`), and whether each app is linked (`is_linked`).

`install`, `update` and `link` are refused with a message naming the command when git has no `git subtree`.

`app-install publish` holds the steps of publishing an app that need no judgement, which the new `publish-app` skill runs in order: `compare <name>` says which files differ from the version last published; `set-version <name> <version>` writes the version into `app.toml` and, for a Python app, `pyproject.toml` and its lock, with the workspace's template release as `verified_template`; `assemble <name> [--commit <rev>]` builds the app's directory at one commit, less what `[publish] exclude` names, in a directory under `/var/tmp`, and refuses it when the secret scan finds anything (`secrets_found`, with each file) or a Python app's lock does not hold outside the workspace (`lock_check_failed`); `push <name> [--repo-name <repository>]` creates the public repository on the first publish (closed to outside contributions, topic `imbue-studio-app`; a taken name is `name_taken`), makes one commit whose parent is the last published one, with a `Derived-From` trailer on the first publish of an app that was installed and changed here, and pushes it fast-forward-only to `main` with the tag `v<version>`, never forced; `record <name>` writes `published_repo_url`, `published_commit`, `published_version` and `verified_template` to the app's record and commits that one file. An interrupted step is finished by running it again.

`app-install reference add <name> <path> [--note <text>]` and `app-install reference remove <name> <path>` change what an app's record lists as using the app, holding a reference to the rules the footprint code reads it by, and commit that one file.

`app-install uninstall` now also removes an update or a publish of the app that was waiting and the sync service's state for it, and its result names what a later app of the same name takes over (`kept_share_grants`, `kept_routine_state`), the repositories on GitHub it leaves alone (`kept_repositories`), and the apps that list the uninstalled one under `[[dependencies]]` (`dependents`).

`app-install verify <name> [--template <version>]` runs an app's own checks and, when they pass, records the template version they passed on as the record's `verified_template`; the update pass runs it for each app it converted or regenerated.

A commit the installer makes on the primary checkout (an uninstall, a record change) is authored `app-install` even when the shell it runs in exports another git identity, as an agent's does.
