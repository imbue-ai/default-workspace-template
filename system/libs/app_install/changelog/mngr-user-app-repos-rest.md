`app-install link <name>` gives an app its own history and its private dev repository. For an app the workspace built it makes the first `git subtree split` with a join marker, in a clone bounded by the app's age (falling back to the whole history when the bounded clone would read the app's history differently), and moves the primary branch to the marker without touching a file; `--refresh` makes a new marker once the app has changed since its last. With GitHub sync enabled, or with `--create-dev-repo`, it creates the private repository `<name>-dev`, writes its URL to the app's record and commits that one file. A modified installed app gets only the repository; an unchanged one is refused, and so is a run in a worktree that is not the primary checkout. The result says whether a repository was created and what remains.

`app-install list` reports `modified` for an installed app whose committed directory differs from what was installed in any path outside the regenerable set (`uv.lock`), and whether each app is linked (`is_linked`).

`install`, `update` and `link` are refused with a message naming the command when git has no `git subtree`.
