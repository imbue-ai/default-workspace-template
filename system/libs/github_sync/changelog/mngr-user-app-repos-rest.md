The `github-sync` service now keeps each user app's private dev repository current. On every tick it splits the history of each linked app (`git subtree split`, never `--rejoin`, never a commit) and pushes it fast-forward-only to the app's `<name>-dev` repository, recording what it pushed in `data/.state/app_sync/<name>.json`; a lost state file only costs a split and a push. Each split is made in a scratch clone under `/var/tmp` cut at the app's newest join marker, or at its install for an installed app, so it reads only the commits made since and writes nothing to the workspace repository. A merge that brings in older commits (an update of the workspace, a worker's branch that left before the marker) is read there as following only the newer ones, which `git subtree` alone cannot get across; a change to the app from such a branch is in the app's history as part of the merge. A split whose history holds the workspace's own commits (an app directory that was removed and made again) is never pushed, and one that runs out of time says how many commits it had to read. Each dev repository's visibility is checked on its own, and one that is public stops only its own pushes. The status file and `github-sync status` name every app with its state (`pushed`, `up_to_date`, `no_dev_repository`, `not_linked`, `unmodified`, `not_private`, `visibility_unknown`, `push_refused`, `failed`).

`github-sync sync-app <name>` runs that for one app on request, whether or not sync is enabled for the workspace.

New for callers: `github_sync.repositories` (create and lock down a GitHub repository through latchkey, which the publish-template script now calls), `github_sync.app_history` (whether an app is linked or modified, its split, and the cut of a clone that `app-install link --refresh` shares), and `git_environment_through_gateway`. The library now depends on `app-manifest`.

`github_sync.repositories` also gains `set_repository_topics` and `hint_for_push_failure` (what a refused push most likely means), which moved here from the publish-template scripts so that the app publish uses the same two.

`github_sync.repositories` gains `read_repository_is_private(repository)` and `make_repository_public(repository)`, which `app-install publish visibility` uses, and `request_github` sends no body when given none, so a read is a plain GET.

`create_repository` raises unless GitHub's answer says the new repository has the visibility that was asked for, so a repository that was to be private is never used unconfirmed. This holds for a published template's repository and an app's dev repository too.
