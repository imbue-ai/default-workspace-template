- A workspace fetches its template's release tags itself when its checkout names no version, which a workspace made from a published copy of the template does not: it holds the template's history and none of its tags, so it showed no version and never found itself behind its release channel. The dispatcher fetches them in the minute it reads the channel's version, from the `upstream` remote or, where the checkout has none yet, from the address `system/config/parent.toml` names, which is where the update-self skill fetches from. It tries again a day later at the earliest while the checkout still names no version, and never while an update is running. A checkout with no `parent.toml`, or a shallow one, is left alone.

- A workspace moved to another release channel is no longer updated to the channel it left: a schedule it armed for that channel's version is cancelled at the dispatcher's next minute, or by a request that reads the new channel's version before then, so the dispatcher never starts it, also while the new channel's version cannot be read.
