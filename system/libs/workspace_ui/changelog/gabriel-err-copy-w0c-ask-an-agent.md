A failure can offer "Ask an agent to fix this", which sends the failure to an agent as its task.

- `askAgentToFix(connection, {whatFailed, details, instruction?})` in the app contract sends an agent a message, written as Imbue Studio about the user ("Imbue Studio showed the user this failure: ..."), that says what the person was shown, quotes the details as they are, and says what to do: find and fix the fault and tell the user what changed, or the `instruction` the request names. It goes through the new `shell:ask-agent` (the connection's `askAgent(text, options?, delivery?)`), to the chat about the app the page belongs to, which opens beside the page's window, or to the main chat when the app is internal, no app takes an ask, or the delivery is `main-chat`; the `draft` delivery leaves it unsent in a chat's message box. Plain-HTML pages use it from `/_static/app_contract.js`.

- It answers a promise of `StartOutcome` that settles on the shell's `shell:ask-agent-result` (the window opened, or the failure to show), or as not answered when a handshake from a shell that started again comes first (the handshake now carries the shell's `shellId`, the same across its re-sent greetings) or the page disconnects; a caller that shows the outcome itself passes `{showsOutcome: true, onLateAnswer?}`, so the shell toasts no failure of its own for it and an answer that still arrives goes to `onLateAnswer`; without it the shell toasts a failure.

- `AskAgentToFixButton` renders nothing without a shell. It reads "Asking an agent…", disabled, until the ask settles, then shows a failure under itself, with "Draft it in a chat" and "Report a bug" for a failure that owes help, and takes a late answer in place of a not-answered one. A page with its own "Report a bug" passes `pageReportBug: {onFailureChange}`: the button then offers no second "Report a bug" under a refused ask, and the page's report files both failures through `withAskFailure` (the ask's sentence and details added under the page's details, labelled).

- The connection's `startWithText(text, options?)` (`shell:start-with-text`, the main chat) now answers the same way, through `shell:start-with-text-result`, so its button can show it pending too.

- A toast button marked `keepsToast` (one that hands the failure on, such as "Ask an agent to ...") leaves its toast up once pressed, after which the toast's other buttons still apply. An action may say it is `pending`: while its `isPending()` holds, its button is drawn disabled under its pending label ("Asking an agent…").

- Every ask runs the workspace's assist flow (`/assist`, which also reports a fault in built-in code to Imbue). `assistRequest(text, origin?)` writes the message an agent reads: the command first, then the app and the window the ask was pressed in. The shell calls it for every ask that passes through it, so a page never does.

- A failure that owes help offers an agent by default, and "Report a bug" only where no agent can be asked or the ask was refused. `FailureRemedies` draws "Ask an agent to fix this" for such a failure, "Report a bug" in its place without a shell or under `isAgentWithheld` (the ask would go through what failed), and nothing for a failure that owes none; under an ask refused with a failure that owes help it shows the draft and a "Report a bug" that files both failures. `Toasts` draws "Ask an agent to fix this" on a lasting toast that owes help while the page passes `onAskAgent` (`askAgentFromToasts(connection)` for a framed page), reading "Asking an agent…" until the ask settles (the ask is the toast's `agentRequest`: its message and details, or what the caller named in their place, such as an instruction), and "Report a bug" in its place while it passes only `onReportBug` or the toast was shown with `isAgentWithheld`.
