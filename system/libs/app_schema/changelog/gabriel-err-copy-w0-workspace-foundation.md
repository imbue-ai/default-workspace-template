`ErrorResponse` carries two optional fields beside `detail`: `user_facing_message`, a sentence written for the person using the workspace that its frontends show as written, and `reportable`, whether that sentence asks for a bug report. `error_response` takes both. Each is left out of the JSON when unset, so a route that sends neither answers exactly `{"detail": ...}` as before, and every route may send them without listing a richer failure model.
