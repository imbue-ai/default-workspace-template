`ErrorResponse` carries three optional fields beside `detail`: `user_facing_message`, a sentence written for the person using the workspace that its frontends show as written; `reportable`, whether that sentence asks for a bug report; and `kind`, which case of refusal it was, for a frontend that offers different controls per case. `error_response` takes all three. Each is left out of the JSON when unset, so a route that sends none answers exactly `{"detail": ...}` as before, and every route may send them without listing a richer failure model.
