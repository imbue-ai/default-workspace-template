The library now owns how a route exchanges JSON, so an app's API document cannot drift from its routes. Every app keeps a route table: a `RouteModels` entry (request model, response model, status, alternate successes) for each route that exchanges JSON and a `SchemalessRoute` entry, with its reason, for each that serves a page, a file, a stream or a socket. `parse_request_body` validates a body with the model the table names (a body off the shape is a 400 `ErrorResponse`, the one error shape every route now answers, logged with the method, path and problem) and `model_response` answers the model the table names; either disagreeing with the table fails the request with `RouteModelsMismatchError`. The document shows every table entry (an alternate answer under a failure status, such as a relay's 502, is described as a failure rather than a success), `x-no-schema` with the reason for a schemaless route, and `ErrorResponse` as every operation's default response. `assert_api_schema_describes_app` now also requires every operation to be in the table, the table to name no route the app lacks, and no modelled view to read its body around the helper. A HEAD request is checked as the GET operation that serves it, so a probe's HEAD of a modelled route answers as before. A check on every answer fails a modelled route that answered JSON around `model_response` or succeeded without reading its body through `parse_request_body`; a failure richer than `ErrorResponse` must be listed as one of its route's answers; `merge_route_tables` joins an app's module tables and refuses a route two of them name; the 400 handler and the answer check are installed app-wide even when the document is registered on a blueprint.
