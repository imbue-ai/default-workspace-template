`run_sidecar_app` takes `is_registered` (default true): a throwaway boot of a sidecar app (a preview on free ports) serves its instances API and its wrapped server without registering, so the live app's registry row is left alone. Such a boot is not held to the manifest's `instances_url` either: that URL is where the registered app's API is, and an unregistered boot serves wherever it was told to (the terminal's preview could not boot before this, since its manifest names the live sidecar port).
