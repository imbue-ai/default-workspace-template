New library: the shared implementation of the instances API every multi-instance workspace app serves (phase 2 of the workspace app model, `docs/system/blueprint/workspace-app-model/`; nothing mounts it yet, so nothing user-visible changes). `build_instances_blueprint(source, nudger)` serves `GET /_instances`, `POST /_instances`, `DELETE /_instances/<key>`, `POST /_instances/<key>/rename`, and `POST /_instances/<key>/location` over a pluggable `InstanceSourceInterface`, mapping the library's typed errors to the contract's status codes with `{"detail"}` bodies and nudging the shell after every mutation. `JsonStoreInstanceSource` keeps instances with no other backing state in an atomically written `instances.json` (lowest-free `<prefix>-<N>` keys, `params.path` as the URL, location reports recorded). `ShellNudger` posts `/api/apps/<name>/changed` to the shell (resolved as `layout.py` does) and swallows an unreachable shell at debug level. `run_sidecar` serves the blueprint beside a wrapped third-party server: it listens first, registers through `forward_port.py --manifest`, spawns the child, forwards `SIGTERM` and `SIGINT`, and exits with the child's status. `app_instances.testing` carries the stub source and scratch servers later phases' tests use.
