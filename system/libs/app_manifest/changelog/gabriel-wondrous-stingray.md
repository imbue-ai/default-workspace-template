An app's supervisord wiring is found again. `find_wiring_sections` read only `system/supervisord.conf`, but every program now lives in a `supervisord.conf.d/` drop-in, so the app footprint silently lost its wiring -- and the browser app, which declares an `xvfb` sidecar, failed outright with "supervisord.conf does not define program:xvfb". It now reads the main config and its drop-ins, and attributes each block to the file it is actually written in, so a footprint names the file a change would have to edit.
