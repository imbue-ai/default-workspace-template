New library and CLI, `workspace-themes`, for workspace themes (`docs/system/blueprint/workspace-themes/plan-workspace-themes.md`).

- Reads theme folders from `system/themes/` (built in) and `themes/` (made in the workspace), resolves each theme's base chain, chrome, and icons, and validates every theme against contract 1: only contract tokens and parts, metrics within range, no classes, ids, imports, or remote URLs (including through a namespace prefix, any selector function, a backslash, or a URL put in with `var()` or `if()`), and only allowed file types and sizes (a hidden file, or a file in a hidden folder, that a theme never serves, such as a `.DS_Store`, an editor's swap file, or a `.git` folder, is ignored); each selector of an app's overlay (`apps/<app>.css`) names one of that app's parts, and an overlay defines no `@keyframes` or `@font-face`, since every overlay is in every app's bundle. `validate <id>` reports every folder with that id.

- Serves a theme's bundle and files from any app's own origin (`register_workspace_theme_route`), with `X-Content-Type-Options: nosniff` on every answer and a script-free `Content-Security-Policy` on an svg (`theme_file_security_headers`). A theme folder, an icon, or an icons folder that is a link is never read or served, and a style file may not be named `theme.css`, the bundle's name. A relative `url()` inside a custom property's value (a wallpaper token such as `--desk-default-wallpaper: url("assets/bubbles.svg")`) is sent rewritten to `/_static/themes/<id>/<path>`, since the browser resolves it where `var()` puts it rather than against the style file.

- Icon tools that work with any image model or none: `icon spec` (what to draw, and which apps lack an icon), `icon fit` (trim, scale, and quantize any drawing onto the theme's limits; one already at the theme's size keeps its pixels one for one), `icon grid` (draw from a text pixel grid), `icon check` (an svg icon may hold no script, event handler, `foreignObject`, or reference outside itself), and `icon install` (which, for a built-in theme, fills only an icon the theme does not ship); `fit` and `grid` take `--preview` for an enlarged copy.

- `new` lays out a theme folder, `validate` checks themes, `bundle` prints a bundle, `list` lists themes, and `lint-app` finds literal colors, fonts, and shadows in a tokens-mode app.

- `scripts/vendor-css-library.mjs` adapts a CSS library (system.css, win95.css, ...) onto the contract's parts from a pinned, digest-checked source; it refuses two library assets with one file name, and never reads text inside an attribute selector or string as a class.

- `workspace-themes icon missing [<id>...]` lists, for every theme with icons of its own, the apps it has no icon for (naming the folder too when two folders share an id), and exits 1 when there are any. A theme that keeps the standard icons has none to draw.

- When it sends a theme's style file, the server gives each rule for the `button`, `field`, or `select` part a second selector for the bare `<button>`, text `<input>`, `<textarea>`, or `<select>` of a page built on the page kit (`:root[data-page-kit]`), at the element's own weight, so such a page wears the theme without marking its controls and an app's own class rules still win.
