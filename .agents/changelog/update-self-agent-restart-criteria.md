- update-self now restarts the workspace's agents when an update changes what their harness processes loaded at start. Before, the apply restarted only the services, so after a Claude Code upgrade (or a change to pi's extensions, as in the pi guards change) every open chat and background agent kept running the old version until something else restarted it.

- Whether a restart is needed is decided by rule and reported (worker guide §4d, a new **Agent restarts** report field the lead's audit requires). The new `update_self.py agent-restart-verdict` reads the mechanical part off the diff: a harness version pin in `setup_system.sh` or `[agent_types.*] version`, the Antigravity installer, and `.pi/extensions/`. The worker judges only harness config the command cannot place, counting it as loaded at start when its live reload cannot be established. `.claude/settings.json` (Claude Code reloads it live), the scripts hooks run, and an agent's launch config (recorded when the agent is created, so a restart would not pick it up anyway) do not need one.

- After a successful apply the lead runs the new `update_self.py restart-agents`, which asks the chat app to restart every chat and background agent that has ended its turn. The chat app checks each one at the moment of its restart. Conversations carry over. Agents that are working, waiting on a dialog, mid-handoff, receiving a message, holding queued messages, or in a state the chat app cannot read are left running and named in the results message, which asks whether to interrupt them. A restart does end a background command an idle chat was waiting on, and the chat gets that command's report saying so.

- As its last command the lead runs `update_self.py restart-self`, which restarts the update's own chat once its final turn ends and sends it a note, shown to the user as a one-line notice, asking it to confirm the restart and to repeat the offer for the chats not restarted; when the restart does not happen, the note says so instead.
