- update-self now restarts the workspace's agents when an update changes what their harness processes loaded at start. Before, the apply restarted only the services, so after a Claude Code upgrade (or a change to pi's extensions, as in the pi guards change) every open chat and background agent kept running the old version until something else restarted it.

- The worker decides by rule and reports it (worker guide §4d, a new **Agent restarts** report field the lead's audit requires): a harness version pin, `.pi/extensions/`, or harness config whose live reload cannot be established means a restart; `.claude/settings.json` (Claude Code reloads it live), the scripts hooks run, and an agent's launch config (recorded when the agent is created, so a restart would not pick it up anyway) do not.

- After a successful apply the lead runs the new `update_self.py restart-agents`, which restarts every idle chat and background agent through the chat app. Conversations carry over. Agents that are mid-turn, waiting on a dialog, or mid-handoff are left running and named in the results message, which asks whether to interrupt them. As its last command the lead runs `update_self.py restart-self`, which restarts the update's own chat once its final turn ends and sends it a note, shown to the user as a one-line notice, asking it to confirm the restart and to repeat that offer; when the restart does not happen, the note says so instead.
