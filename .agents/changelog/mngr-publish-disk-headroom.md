`serve_isolated_instance.py --copy` now checks a copy against what the workspace can actually still write (the `disk_headroom` library, which also reads a cloud machine's published disk quota) and keeps 2 GiB of that free. Where no quota is published it still holds back the 4 GiB a cloud machine's quota may keep from `statfs`'s free space, as before. On a cloud machine that publishes its quota, app previews no longer fail when its disk shows 4-6 GB free with room to spare, and still refuse when the quota is what is nearly full.

The caretaker and update-app skills check disk space with `uv run --no-sync disk-headroom` instead of `df`.
