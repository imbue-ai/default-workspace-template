`service-processes.md` no longer carves `system_interface` out of "supervisord only manages the programs declared under `system/supervisord.conf.d/`". That program now lives in a drop-in like every other, so the rule holds without an exception: every supervisord program in this workspace is declared in exactly one file under `system/supervisord.conf.d/`, named after it.

Every boot smoke-check now checks that the drop-ins are actually there, not just that the config parses. An `[include]` glob that matches nothing yields a config that realizes cleanly and runs no services at all, which is newly reachable now that the main config declares no programs of its own. So the check requires at least one realized program everywhere it is performed: `publish-template`'s assembly (exit 4), `use-template` and `update-installed-template` before they fast-forward the workspace onto a merged tree, and `update-published-template`'s re-cut. `publish-template`'s assembly additionally refuses a `--base-ref` whose tree does not name `system/supervisord.conf.d` (exit 5, alongside the existing `pyproject.toml` and `system/supervisord.conf` requirements).
