Two references for visiting agents (coding agents invited into the workspace from outside): `visiting-agents.md`, the primer the share gateway renders for an agent at every connect (how to work through the helper, the skills index to re-read daily, the connected accounts and latchkey rules, the apps, recent changes, what not to do), and `visiting-agents-invite.md`, the instruction block an inviter copies. Both are templates the gateway fills in with the workspace's live state, so they track the template version the workspace runs.

The instruction block installs the helper from the template repository on GitHub at the exact version the workspace runs (a tag, else the commit) and checks its SHA-256, naming the workspace's own `/_agent/helper` only as the fallback for an unpublished commit; both references say a visiting agent does not create agents inside the workspace unless instructed to, where they used to forbid it outright.

The primer's apps section says how to reach an app from outside (`wsvisit get <app>/<path>`, which sends the admission token as a bearer and keeps it on the agent's machine) and that an app the shell stopped answers 503 with `Retry-After` for a second or two while it starts, which `wsvisit get` waits out; the instruction block lists the verb.
