New `free-workspace-memory` skill for when the workspace runs low on memory, the memory guard sheds something, or the user asks what is using memory. It is one flow around `workspace_memory.py`: list what could be stopped (idle chats and workers, apps no window shows, the browser nobody is looking at, and, offered last, apps a window shows), offer it to the user, stop only what they approve, and answer whoever reported the shed. It replaces `.agents/shared/references/freeing-memory.md`; `lead-proxy.md`, `dead-worker-recovery.md` and `update-self` point at the skill instead. Caretaker and the harden worker read free memory from the guard's own figure (`workspace_memory.py free`) rather than `free -h`.

update-self lists what it could stop with `update_self.py memory`, which runs whichever memory tool the workspace's own tree has and reports what that version does not list as unknown. Its prose used to run `memory_candidates.py` by path, a script that is absent before minds-v0.8.2 and lists no apps before minds-v0.9.2. `handoff-contract.md` now says which code travels with the skill and which is asked of the workspace's tree.
