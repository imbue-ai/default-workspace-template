New `workspace-memory` skill for any question about the workspace's memory: how much something uses, what is using it, what could be stopped, or a shed an agent reports. It measures first, with the memory candidates command, the System Monitor's breakdown, or one process's `Anonymous` lines, and says why `ps` RSS, PSS and `free` read several times wrong under gVisor (an agent once summed 2.7 GB of RSS for a browser holding well under 1 GB). It then frees memory with the user exactly as `.agents/shared/references/freeing-memory.md` did; that reference moves into the skill, and `lead-proxy.md`, `dead-worker-recovery.md` and `update-self` point at the skill instead. Caretaker reads memory from the guard's own free-memory line rather than `free -h`.
