An app's crystallize pass now checks how the app works from a phone and when it is shared, right after the worker's first milestone, so the hardened core reaches the user first. The worker drives the app at phone sizes with touch (viewport tag, no sideways scroll, nothing reachable only on hover, tappable controls), fixes what it finds without changing the desktop layout the user confirmed, and commits a phone-sized browser test. It then reviews every route in the app's API document for what a visiting person or agent could do with it: the app gains the request guard the built-in apps already have, a route that hands a visitor a secret or credential becomes owner-only, changes are attributed to the requester's participant key (a person's user id or a visiting agent's grant), and an app visitors can change keeps a bounded access log. Whether visitors may see the owner's data beyond what the pages show, change, delete, spend, or run commands is left to the user: the worker names those routes on a new `Sharing:` line of its `done` report, and the lead asks the user after go-live. `web-frontend-testing.md` now points browser tests in the repo-root suite at its `module_browser` and `phone_context` fixtures rather than pytest-playwright's `page`, `context` and `browser`, which that conftest refuses, and a user-built app's own suite adds Playwright to its dev group and launches Fortress by its path.
