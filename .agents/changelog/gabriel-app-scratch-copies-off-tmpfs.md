- `serve_isolated_instance.py up --copy` (which app previews use for their copy of an app's data) now checks that the copy fits before making it. A copy that would leave less than 6 GiB free on its disk (above the space a cloud workspace's disk quota holds back) is refused before anything is written, failing the boot with a message saying what to do instead, and a copy that fails part way is removed rather than left holding the space.

- The `update-app` skill no longer tells an agent to copy an app's data into `/tmp`, which is now a RAM disk capped at about 1 GiB. The copy an agent tests a change against is made with `serve_isolated_instance.py up --copy`, which puts it on disk and deletes it on `down`, and a snapshot before an in-place change goes to `/var/tmp` after a fit check. The `file-sharing` and `minds-api` skills send large files and backup exports to `/var/tmp` as well.
