`update-self` no longer tells the user about template releases newer than their Mind app.

A workspace capped at its app's version used to hear that a newer release "is available upstream but needs a newer app", with a suggestion to update the app or pass `--override` to go past it. It said so even while the user's release channel had not rolled that app version out to them, when the app itself reported it was up to date. Releases above the app's version are now treated as if they do not exist: the already-on-this-release refusal and the post-update message never name one, the refusal for an app older than every release no longer suggests `--override`, and a workspace whose own update flow predates the cap is moved to the capped release without being asked about the newer one it picked. `resolve-target` drops the `latest_available` and `held_back_by_ceiling` output fields. The Mind app announces its own updates on the user's channel.
