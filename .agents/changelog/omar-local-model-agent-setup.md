- A new `set-up-local-model` skill lets an agent get a model running on the user's own computer when they ask for AI work to "run locally", with one approval and no visit to Settings or to a chat's provider menu. The agent asks Imbue Studio for the local-model permission; once the user approves, Imbue Studio installs Ollama if the computer runs no model server and downloads a model that suits its memory. The skill's script (`check`, `start`, `wait`, `verify`) reads the progress with sizes, checks that the model answers from the workspace with a 16,384-token window, times one answer, and records where refresh code reaches the model in `data/.state/local_model/endpoint.json`. The same skill brings a model back when one that was set up stops answering, without asking the user to install or start anything.

- The copyable `local_model.py` helper in `use-ai-integration` reads that record before a chat's Local model connection, so a refresh needs no chat signed in to a local model. Before its long call it checks that the server answers; when a recorded model does not, it asks Imbue Studio once to connect the workspace again before raising the unreachable error. Its error messages name the new skill, not the provider menu.

- `use-ai-integration`, `build-app`, `update-app` and `run-on-users-computer` point at the new skill: a refresh that cannot reach the computer skips the run and says so, and a model runner is never installed by running commands on the user's computer.
