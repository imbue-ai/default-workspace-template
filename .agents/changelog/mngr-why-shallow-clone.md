The update-self flow now heals shallow-history workspaces in place. Workspaces created from pool hosts baked before the full-history bake fix (mngr PR pairing this change) carry a `--depth 1` clone whose history dead-ends at a parentless graft commit, breaking `git log` archaeology and making upstream comparisons hard to reason about. Both the lead's fetch (SKILL.md Step 2) and the worker's fetch (worker guide Step 1) now run a guarded `git fetch --unshallow upstream` when the repo-wide shallow marker is present; the guard makes it a no-op on healthy repos. Because the worker guide runs from the target release's copy of the skill, the heal applies on the first update into a release that ships it; the worker's worktree shares the main repo's object database and shallow marker, so healing there heals the whole workspace.
