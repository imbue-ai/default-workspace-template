- The careful flow for critical apps takes one lease per critical app it touches (`editing critical app <name>`, a `workspace_ui` or npm-file change counting as both the shell and the chat), rather than one `editing critical apps` lease for all of them, so a chat edit and an unrelated shell edit no longer block each other. A pass takes its leases all or none, so two passes that need the same apps at entry never hold one each, and a pass that later grows to a held app surfaces it along with the leases it already holds. The go-live freshness check now also fails when any file the pass changes moved on the served branch, and the lead re-checks for another pass's "recently updated" notice before applying. `update-self` takes the per-app leases, all or none, for the critical apps an update touches (and its release step no longer names the stale `editing service system_interface` lease), and `harden-contention.md` tells a merging pass to wait out a critical app's lease too.

- `update-app`'s `preview_app.py` has an integration test (`test_preview_app_lifecycle.py`) that boots a fixture app from its manifest's `[preview]` table through the real `serve_isolated_instance.py` and `forward_port.py`, refreshes a rebuild in place, and tears it down. The existing tests stub the shared script and hand-write its state file, so a renamed flag or state key there used to pass both suites.
