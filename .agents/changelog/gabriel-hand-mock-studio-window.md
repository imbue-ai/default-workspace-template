- `serve_isolated_instance.py down` refuses while a window on the user's desktops still shows the instance, since tearing it down would leave that window on a dead server, and changes nothing. `--close-windows` closes those windows first, through the shell's own close route, which closes a window for every client without moving anyone's view to its desktop. A window that cannot be closed (a pinned one) refuses the same way. When the desktops cannot be read, the teardown goes ahead with a warning.

- `preview_app.py down` takes the same `--close-windows`, which reaches the siblings it booted, and the careful-flow and update-self teardowns use it in place of a separate `workspace-layout close`. `mock_frame.py down` closes its window through it.

- The interactive-delivery reference gives the command for showing a hand-built page (a detached prototype, such as an HTML mock) as a framed window, `serve_isolated_instance.py up` over `python3 -m http.server` then `workspace-layout open`, in place of a server and link of the agent's own. A localhost link to such a page opens in the workspace's browser rather than as a window. `serve_isolated_instance.py up` takes `--preview-kind mock` and `--preview-note`, so the hand-built page's frame carries the "UI Sketch" banner `build-app`'s mocks use; previews of real changes keep the "Preview" banner.
