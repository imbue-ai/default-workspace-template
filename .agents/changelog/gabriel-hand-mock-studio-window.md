- `serve_isolated_instance.py down` refuses while a window on the user's desktops still shows the instance, since tearing it down would leave that window on a dead server, and changes nothing. `--close-windows` closes those windows first, each through a client already on its desktop so nobody's view moves. A window that cannot be closed refuses the same way. When the desktops cannot be read, the teardown goes ahead with a warning.

- `preview_app.py down` takes the same `--close-windows`, which reaches the siblings it booted, and the careful-flow and update-self teardowns use it in place of a separate `workspace-layout close`. `mock_frame.py down` closes its window through it.

- The interactive-delivery reference gives the command for showing a hand-built page (a detached prototype, such as an HTML mock) as a framed window, `serve_isolated_instance.py up` over `python3 -m http.server` then `workspace-layout open`, in place of a server and link of the agent's own. A localhost link to such a page opens in the workspace's browser rather than as a window.
