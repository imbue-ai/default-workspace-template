- `publish-template` is restructured for progressive disclosure. `SKILL.md` is the lead's checklist (about 400 lines, down from 1,445); the worker's assembly instructions moved to `references/assembly-worker.md`, and every failure and what to do about it to `references/failures.md`. The task file the lead writes now carries only the template's parameters.

- The deterministic steps are scripts, shared with `update-published-template`: `github_access.py` probes and waits for the GitHub grants, and reports UNKNOWN rather than "not permitted" when the gateway cannot reach the user's Imbue Studio app, so the user is asked to open the app instead of being sent requests for access they may already have granted (the permission requests stay inline, since the chat builds its approval card from them), `github_repo.py` creates the repo, locks it down, points the README's Open in Imbue Studio button at it and sets its topic, `push_snapshot.py` runs the pre-push gate and pushes one snapshot commit as a fast-forward (with an optional version tag), refusing to publish from the live workspace or any other main checkout, and `record_publish.py` writes the `docs/VERSION_HISTORY.md` entry. `update-published-template`'s `references/ledger-entry.md` is gone.

- The pre-push gate is one command, where it was a validator run plus three greps: every `validate_template.py` run now checks that the thumbnail is inert (no script, embedded HTML or event handlers), and `--pre-push` adds the check that the README's repo-URL placeholder was replaced.

- The worker and the lead run the publish tools from the publishing workspace's copy rather than the copy inside the assembled tree, which is the base's and can be older. A workspace whose base predates a tool fix no longer fails at the worker's or the lead's validation.

- Fixed stale instructions: renaming after assembly edits the title in both manifest files (the old step renamed slug-named files that no longer exist, and then failed validation); the README is reviewed by pasting it into chat (the preview-tab step was removed in August); the published-page check after the push is now a step; the generated manifest points adopters at `connect-external-service` instead of the retired `latchkey` skill; and `update-installed-template` names `update_ledger.py` as where the ledger starter lives. `update-self`'s ledger helpers (`VERSION_HISTORY_STARTER`, `origin_line`, `insert_under_workspace`, and `pad_note`, the note-padding rule both ledger sections use) are public, for `record_publish.py`.
