`update-self`'s results message no longer tells the user that parts of an update "only take effect when this workspace is rebuilt" when a rebuild would change nothing. The worker now marks each image-level `Dockerfile` hunk *covered live* or *pending recreate*. A hunk is covered live when its effect already reaches the running workspace through the merged tree or the apply's `setup_system.sh` re-run, or when it only shapes the image build (a layer-cache `COPY`). A hunk is pending recreate when the running workspace lacks something until a recreate. The lead's §5c and the results message's Caveats section now mention only pending-recreate items, and say what the workspace lacks until then. Before this, §5c said to call out every image-level hunk, while the Language rules said a consequence-free item was "one line at most, or nothing". The lead followed §5c and told the user about COPY lines for manifests and an installer that the apply had already made live.
