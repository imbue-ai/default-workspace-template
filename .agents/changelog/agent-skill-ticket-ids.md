`heal-creation`, `update-creation`, `crystallize-creation`, `update-app` and `update-self` no longer keep a ticket or lease id in a shell variable. Each tool call gets a fresh shell, so the variable was empty by the time a later call ran `tk start` or `tk close`, and `tk` resolves an empty id to whatever single regular ticket it finds -- possibly another agent's lease. The create-and-start blocks of the first three were also refused outright by the `agent_tk_standalone.sh` hook. The skills now have the agent pass the printed id literally, and the three harden leads save it to the task directory's `ticket_id.txt` for the close at merge time. A new test, `.agents/shared/scripts/skill_tk_commands_test.py`, runs every documented `tk start` / `tk close` block past the hook and rejects any id passed through a shell variable.
