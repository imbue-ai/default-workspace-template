`update_self.py run-status start` records the lead's chat id (`MINDS_CHAT_ID`, else `MNGR_AGENT_ID`) in the run record as `chat_id`. Renaming a chat renames its agent, so the Imbue Studio app and the workspace's update watchdog, which found the lead only by the recorded chat name, read a renamed chat's update as gone: the app reported it as not finished and the watchdog could record it stuck and stop its worker while it was still working. With the id on the record they find the lead under its new name. The run's later `run-status` writes find its record by the same id, so a renamed lead that restarts mid-update, and so runs under its new name, still records its verdict on its own run rather than on a fresh record the app is not watching.
