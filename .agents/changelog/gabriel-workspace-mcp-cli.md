MCP servers are now reached through `mcpc`, one MCP client the whole workspace shares, instead of each harness's own MCP config. `connect-external-service`'s `references/mcp.md` lists servers in `mcp-servers.json` at the repo root, opens a session per server with `mcpc connect`, and calls tools with `mcpc @<name> tools-call`, so a newly connected server works in the same turn, from any chat on any harness, from an app, and from a scheduled job, with no chat restart. A hosted server's OAuth sign-in runs through `mcpc login`, held open in the background while its consent page is handed to the user in a workspace browser; a hosted server that takes a key names it as `${VAR}` in its header, records the secret file it needs as `secretsFile`, and is connected under `with_secrets.py`, which replaces the `mcp-remote` bridge. The routing table's cheap test now runs `mcpc` beside `latchkey services list` to find connections that already exist. `publish-template` no longer renames the MCP config (nothing in `mcp-servers.json` connects on its own) and reads the secret files it runs under from that file; `use-template` connects each server once the file it runs under is stored, the user has signed in, or at once when it needs neither.
