The `update-self` skill's pre-flight backup step now reads `host-backup-now`'s exit code instead of relying on the printed event: exit 0 is a captured restore point, exit 3 means backups are not configured (so there is no restore point and the user has to be asked before proceeding), and any other non-zero exit is a failed backup attempt. Previously the step could also stall for the command's full 30-minute timeout when backups were not configured; `host-backup-now` now returns as soon as the tick resolves.
