Added a `migrate-workspace` skill: bring everything from another (older, broken, or replaced) workspace into this one -- apps, skills, documents, data, scheduled automations, and every past chat. An old workspace cannot update itself across the tree reorganization and the Debian 12 -> 13 base-image change, so the guidance becomes "create a fresh workspace and have its agent pull the old one in"; this skill is that pull. It is reached by description match alone, worded for how users actually phrase the request, and it has an escape hatch for being asked from the *old* side (it creates the new workspace, then hands off to that workspace's agent).

The flow runs over a live SSH session brokered through the minds API, so the old workspace has to be startable; a source that will not start is handled in prose via a backup export instead. The lead agent gets access with one batched permission request, takes a fresh backup on both sides, checks that this workspace is genuinely fresh, and resolves what the user actually authored by diffing the source against *its own* template base -- which excludes template-version drift by construction. It then surfaces the whole inventory and every question it can up front (collisions, unmerged branches, billing-relevant AI decisions) before dispatching a worker for the transfer, path rewriting, app/job re-registration, and chat recreation.

Everything under the source's data tree comes over, including `anthropic.env` so migrated integrations keep working; only the app-minted `restic.env` and `cloudflare_tunnel.env` are excluded, since each points at the *old* workspace's own resources. Every old agent except the source's primary is recreated dormant via `mngr create --template chat --adopt <session.jsonl>`, keeping its old name and its original creation label, so its full history renders in a tab and a message revives it. Agent-name collisions auto-suffix and are reported; app, skill, and port collisions stop and ask, because that wiring collides for real.

Supporting material: `references/pre-declutter-layout.md` (the old->new path map for `minds-v0.3.9` and earlier, the substrate deltas, the per-old-skill replacement table, and a tour of the capabilities that did not exist then), `references/agent-recreation.md` (the session-adoption mechanics), and `scripts/migrate_workspace.py` (layout detection, baseline diff, agent/branch/port/job enumeration, the latchkey and AI-integration audits, path mapping and reference rewriting, and agent recreation -- each reporting what it could *not* settle, so a partial result never reads as "nothing there").

The `minds-api` skill's headline workflow now points at this skill instead of carrying a thinner version of the same flow, and its description no longer claims migration as its own job.
