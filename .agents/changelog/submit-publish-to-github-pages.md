New `publish-to-github-pages` skill: publishes one of the user's apps as a public static site on their own GitHub Pages (`<user>.github.io/<app>/`). It first decides whether the app can run with no server (as-is, rewritten into a static copy with frozen data or browser storage, or not at all -- anything needing a secret such as an AI key, shared data, or background work is refused with a plain reason), builds the copy outside the live app, blocks the publish on any leak (both secret scanners from `publish-template`, emails, references back into the workspace, calls to the app's server), checks every page in a real browser locally under the repo subpath and again live, then creates the public repo, pushes and turns Pages on through latchkey. Users without a GitHub account get a short sign-up guide; the user is asked only before something goes public or when visitors would notice a difference. Includes takedown (turn off or delete) and a per-app record so republishing updates the same site. Ships with tests for every tool against a stand-in app, latchkey and a local bare repo in place of GitHub, plus browser tests of the page check and one end-to-end run.
