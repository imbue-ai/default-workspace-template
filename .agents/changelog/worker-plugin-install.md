Launched workers (the crystallize / update / heal hardening passes) now get the code-guardian plugin installed for their worktree before their claude starts, so `/autofix` and `/verify-architecture` exist in the one session a worker gets. Claude Code resolves its plugin set at session startup, so the SessionStart-hook install landed too late for a worker: it started with `Unknown skill: imbue-code-guardian:autofix` and skipped its mandated review gates. The worker create template runs `system/scripts/claude_update_plugin.sh` as a provision command; an install failure there is a warning in the provision output rather than a failed launch, so a plugin outage never makes a worker undeployable.

The plugin script itself no longer wipes the shared plugin cache on every session start: every claude in the workspace shares one config dir, so the wipe stripped plugin skills from sessions that were already running, and a session whose reinstall then failed (offline, git auth) started with no plugin at all. Install and update failures are reported instead of being silently swallowed.
