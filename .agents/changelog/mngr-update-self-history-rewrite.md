update-self now updates a workspace created before the template's history was rewritten to drop the vendored mngr directories. Such a workspace shares no commit with a newer release, so the update's merge had no base and could not run. The lead's new `rewrite-history` step (end of Step 3a) rewrites the workspace's own branches and tags with the same pinned filter upstream used, which reproduces upstream's rewritten commits exactly and restores the merge base; shallow workspaces from old pool bakes are grafted onto the matching release first. Only refs and indexes move: the vendored files stay on disk, untracked and excluded, so the running workspace keeps working until the update lands. Every other workspace sees a no-op.
