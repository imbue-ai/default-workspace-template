Workers are cleaned up at every level of a dispatch: a lead destroys a worker after merging it (or after `no-update-needed`), stops it after a failure, and never leaves a process running for a worker it is done with. The old rule for intermediate leads ("stop, never destroy") existed only so the eval capture could read a sub-worker's reports out of its lead's work dir; mngr already preserves every destroyed agent's transcript, so destroying loses nothing the capture reads.

The launcher carries the whole lifecycle. `launch` labels each worker `runtime_dir=<repo-relative dir>` beside `lead_agent`, syncs the runtime dir from the repo root so the label and the sync agree wherever the launch runs from, and refuses a taken name up front, naming the holder's state and lead and the destroy that frees it. `destroy` is recursive by default: it resolves the subtree from one `mngr list`, and before each agent goes (deepest first) pulls the runtime dirs of the workers it dispatched out of its worktree into the caller's tree at the same paths, so even a sub-worker its lead had already destroyed is carried up. Unmerged commits and dirty worktrees are warned about, not refused; `--delete-branches` adds `-b`; `--no-recursive` names the descendants left behind; one outcome line per agent and a non-zero exit report partial failure. A new `stop` subcommand stops a subtree with `mngr stop --archive`, so `archived_at` marks a worker stopped on purpose. `launch-sync` reports `destroy_failed` and exits non-zero when its destroy left something behind.

Prose follows: `lead-proxy.md` ends `done` and `no-update-needed` with the destroy and `stuck` with the stop, and the intermediate-lead rule reads "destroy after merge, stop on failure"; `worker-failure.md` stops the worker as its step 3; `dead-worker-recovery.md` scopes the restart path to unarchived workers and salvages through the launcher's destroy; `harden-contention.md` supersedes with one `destroy --delete-branches` line; `harden-creation.md` names sibling sub-workers with the worker's own name as prefix; the crystallize, update, heal, and update-system-interface skills place the destroy between the merge and go-live.

Tests: `create_worker_test.py` covers the launcher's new behavior, `dispatch_contract_test.py` parses every `stop`/`destroy` line in prose (indented fences included), and `test_nested_dispatch_live.py` (release) proves destroy, transcript preservation, and relocation against real workers, pinning its clone to the installed claude.
