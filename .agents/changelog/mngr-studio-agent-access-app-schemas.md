The visiting-agent primer's apps table says what each app is for and where it describes its API (the manifest's `description` and `api_schema_path`), and tells an agent to fetch that OpenAPI document before reading an app's code. The `build-app` skill's scaffolder registers the schema route, writes both manifest keys and generates the test that keeps the document honest in every new app; the scaffolded views carry docstrings, and the skill explains what an app owes the document (a docstring per view, which the generated test requires; models for validated routes) and that `--description` is the manifest's one-line description of at most 200 characters, which the scaffolder refuses otherwise. The scaffolder writes a `--description` with characters outside the basic plane (or quotes) into the manifest and the app's `pyproject.toml` as TOML accepts them, rather than as escapes the manifest refuses or a raw quote the pyproject cannot hold. The `update-app` skill's change step says what a route change in an existing app owes that document (a docstring on the view, a route-models entry for a validated route, the manifest's `description` when the app's purpose moves).
