`update-self`'s apply, once an update that re-synced the workspace venv has landed, rewrites the mngr-written files of every chat and background agent stopped at that moment (the ones the lead paused included) with the new mngr, so they resume on files that match it; `rollback-last` does the same with the mngr it puts back. It is best-effort: a failure there is a warning, never a rollback or a failed update.

The worker guide says mngr-written agent files reach the agents stopped when the update lands, and every other agent at the workspace's next boot. An agent's launch command, arguments and environment still reach only agents created after the update.
