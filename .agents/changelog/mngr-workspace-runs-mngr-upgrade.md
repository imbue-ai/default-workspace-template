`update-self`'s apply, once an update that re-synced the workspace venv has landed, rewrites the mngr-written files of every chat and background agent stopped at that moment (the ones the lead paused included) with the new mngr, so they resume on files that match it; `rollback-last` does the same with the mngr it puts back, its notice reading "Bringing your chats up to date" meanwhile. A chat that something starts while that runs can be restarted by it. It is best-effort: a failure there is a warning, never a rollback or a failed update. Each of those runs first removes the record of the mngr that last left every agent current, even onto an older release without the upgrade, since an older release's own update can change the agents without removing it. An apply of such an update that rolls back, or that `recover` rolls back, removes that record too, so the next boot's upgrade runs with the restored mngr.

The worker guide says mngr-written agent files reach the agents stopped when the update lands, and every other agent at the workspace's next boot. An agent's launch command, arguments and environment still reach only agents created after the update.
