- An update (or a critical app's change) that a workspace restart interrupted, and that the boot-time recovery rolled back, is no longer retried by the agent on its own: the update itself may be what restarted the workspace, so an unattended retry could loop. The agent checks the workspace is healthy, winds the pass down with a `REFUSED` verdict, and retries only when the user asks ("After a restart rolled it back" in the update-self skill's `apply-outcomes.md`, and the matching paragraph in the update-app skill's critical-app reference).

- When that rollback could not put every pre-apply copy back (a full disk, a permission fault), `emergency.json` now lists each copy with the path it belongs at, and the new `update_self.py finish-restore` puts them back once the cause is fixed, using the same restore `recover` attempted. The agent finishes that restore without waiting to be asked.
