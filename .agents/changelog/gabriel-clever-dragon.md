- `update-self` now runs the *target* version's own copy of the skill instead of the local one. Once the target ref is resolved, a new `bootstrap-skill` step (`update_self.py`) `git archive`s that ref's skill dir to a fixed staged path (`runtime/update-self/skill-at-target/...`) and the rest of the pass -- lead and worker -- runs from there, so fixes to the update flow itself ship on the way in. The staged path is addressed by literal rather than a shell env var (which didn't survive Claude's fresh-shell-per-command Bash tool and silently fell back to the stale local copy); a ref that predates the skill stages the local copy instead.

- The reveal step for a `service` / `supervisord.conf` / `bootstrap` change now prescribes a full services-agent restart (`mngr start --restart system-services`) and forbids the surgical `supervisorctl reread && update`, which doesn't re-run `bootstrap` and so misses `libs/bootstrap` changes.

- Fixed the "what's new" collector (`update_self.py changelog-entries`): it scanned only the top-level `changelog/` dir, so it missed every entry under the current bucketed layout (`.agents/changelog/`, `dev/changelog/`, `libs/*/changelog/`, ...). It now gathers newly-added entries from every project bucket (excluding the vendored subtree).
