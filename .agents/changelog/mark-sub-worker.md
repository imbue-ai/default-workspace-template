Worker dispatch is level-agnostic: any agent that runs `create_worker.py launch` and polls for a report is a lead, including a worker, so a worker dispatches a sub-worker with exactly the commands a chat agent uses.

`launch` stamps the task file's own repo-root-relative `task_file` path into its frontmatter next to `lead_agent`, and labels the worker `lead_agent=<lead>`. `parse_task_frontmatter.py` takes that exact path (no glob) and emits `TASK_FILE`. Runtime-dir syncs use `--uncommitted-changes=clobber`, since the destination is gitignored `data/` and `merge` would touch the git stash every worktree of the repo shares. Nothing is installed into a worker's skill tree any more: `install_worker_skills.sh` is gone and a harden task file tells the worker to follow `.agents/shared/worker/SKILL.md` from its own checkout.

Workers report with a new `create_worker.py report` subcommand, which writes the report beside `finish_report_path`, pushes it to the lead, and falls back to the lead's work dir resolved through the worker's own `lead_agent` label; it fails loudly when it can deliver nowhere. `await` archives every report it prints under `consumed/` (timestamped, named by kind), so leads never move reports by hand. Its idle detection treats a worker with a live child (labelled `lead_agent=<worker>`, RUNNING or WAITING, not shed) as busy, so a worker waiting on its own sub-worker is never mistaken for a stalled one. The `question` gate is valid on every operation, and `lead-proxy.md` carries the rules for a worker that is itself a lead (answer or re-raise a question, merge one level with `--no-ff`, stop rather than destroy, 60m sub-worker timeouts). The harden contract lets a worker split its pass across sibling sub-workers: the worker decides the split, siblings run scoped tests only, and the lead runs the full suite and ratchets once on the merged result.

Tests: `create_worker_test.py` covers the stamps, the label, the report push and fallback, archiving, and child-aware idle detection; `dispatch_contract_test.py` executes every dispatching skill's real task-file block and launch command and parses every `create_worker.py` invocation in prose against the real parser; `test_nested_dispatch_live.py` (release) dispatches a real worker that dispatches its own sub-worker, answers its `question`, merges, and reports, and skips wherever a live claude worker cannot start.
