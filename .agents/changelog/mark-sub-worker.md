Worker dispatch now has contract tests across the three hands it crosses -- the lead skill's prose, the launcher script, and the worker-side task-file parser -- as the baseline for decoupling `launch-task` from the harden worker.

`dispatch_contract_test.py` (under `launch-task/scripts/`) discovers every skill that writes a task file and launches a worker, runs each skill's real fenced task-file block under bash, and checks that the result parses through `parse_task_frontmatter.py`, names a report path inside the runtime dir the launch syncs, and sits where the worker's glob will find it; it then runs the skill's real launch invocation against a recording runner and confirms the lead's poll target, the synced dir, the messaged file, and the stamped lead address all agree. Every `create_worker.py` invocation in skill and shared prose is also parsed against the script's real argument parser (`build_parser`, split out of `main` for this). `install_worker_skills_test.py` runs the provisioning script for real and pins the installed `harden-worker` layout, its overwrite semantics, and its failure modes.

Worker dispatch is now level-agnostic: "lead" and "worker" are roles in one dispatch rather than fixed rungs, so a worker launches a sub-worker with exactly the commands a chat agent uses. `create_worker.py launch` stamps the task file's own repo-root-relative path into its frontmatter as `task_file` (resolved through `git rev-parse --show-toplevel`, so launching from a subdirectory is correct) and attaches the resolved lead to the worker's agent as `--label lead_agent=<lead>` -- the same value it stamps, resolved once. `parse_task_frontmatter.py` takes an exact path instead of a glob (no `resolve()`, no searching) and emits `TASK_FILE` alongside `LEAD_AGENT` and `FINISH_REPORT_PATH`; exact paths are what keep two levels of dispatch, or two siblings, from resolving each other's task files. The runtime-dir sync moved to `--uncommitted-changes=clobber`: the destination is a gitignored runtime dir, so nothing tracked is at risk, and `merge`'s stash/pop would touch the git stash stack that every worktree of the repo shares -- which two concurrent dispatches corrupt. Nothing is installed into a worker's skill tree any more: `install_worker_skills.sh` and its test are deleted, and a lead's task file names `.agents/shared/worker/SKILL.md` in the checkout the worker already has. The contract tests moved with it -- dispatchers are discovered only among skill `SKILL.md` files, and the glob assertions are replaced by "the task file parses at the exact path the launch names, and the stamped `task_file` and `lead_agent` match what the launch used".
