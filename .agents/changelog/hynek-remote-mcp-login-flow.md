The `connect-external-service` skill now routes a hosted MCP server through latchkey instead of through the workspace's own MCP client or a harness's MCP config.

A hosted server is a custom latchkey service: its OAuth sign-in goes through latchkey's new `mcp` login flow (sent as the `login` object of a `custom-service` permission request: the authorization endpoint as the login URL, and the MCP endpoint plus the token and registration endpoints its `/.well-known/oauth-authorization-server` publishes as the parameters), and a server that takes a key in a header is an ordinary custom service on the endpoint's domain. Either way the credential stays in Imbue Studio's credential store, the gateway attaches it and refreshes the token, and the connection is there for every chat, app and scheduled job. The server is then called as a JSON-RPC API through `latchkey curl`, the way latchkey's builtin `*-mcp` services already are; `mcpc` can hold a session to it through the gateway for a long run of calls. `mcpc login` and the `${VAR}`-header entry for a hosted server are gone from the guidance (an older entry with a `secretsFile` still connects under the wrapper). A server that runs here as a package still goes through `mcpc` with its key from the secret card, since the gateway cannot inject into a local process.
