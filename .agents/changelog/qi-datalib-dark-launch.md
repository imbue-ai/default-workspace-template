New skill: `datalib`, which searches and mirrors the user's own data (Slack, email, GitHub, Notion, chat history) with the datalib binaries. datalib is not announced to users yet, so the skill's description tells the agent to use it only when the user's own message says "datalib", and never to suggest or mention it otherwise. Nothing of datalib is installed at boot: on first use the skill runs its `scripts/install_datalib.sh`, which downloads the pinned release (v0.42.0, the static musl build, about 80 MB) into `~/.local/share/datalib/<version>/`, links every binary into `~/.local/bin`, and fetches datalib's Node runtime (about 115 MB). It also saves datalib's agent guide at that tag beside the binaries, so the skill reads a local copy and a chat that uses datalib does not fetch github.com for it. The skill then starts the Datalib app (`supervisorctl start datalib`), which is stopped by default.

A sync does not hold the agent's turn. The skill's `scripts/sync_request.py open <step>` files the sync with the running Datalib app, which runs it independently of any chat, and `sync_request.py wait <request-id>...` run through `system/scripts/run_in_background.py` wakes the agent with each request's outcome when it ends. Stopping or handing off the chat stops only the wait, not the sync.
