`update-app` now has the chat agent size each requested change before touching code (how much it changes what the user sees, and how long it takes to build), build short changes itself through the live loop, and hand longer ones to a background worker through `launch-task`, so it stays free to answer new messages. The worker and the chat may edit the same files; conflicts are resolved when the chat merges the worker's work, and a launched worker is exempt from the service edit lease.

A new build-worker guide, `.agents/shared/build-worker/SKILL.md`, gives launch-task build workers their standing rules (what to read, how to build, check and report), so the chat's brief only carries the task. `worker-reporting.md` says reports reach the user through the lead and marks the no-update-needed report as harden-update only; `harden-creation.md` says nothing should touch the live, user-facing state.
