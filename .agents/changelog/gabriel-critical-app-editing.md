`service-processes.md` describes the `agent-observer` program: the workspace's one `mngr observe`, a manifest-less supervised service with no app directory, which every chat instance follows and which a chat never starts on its own.

The build-app scaffold writes the `[preview]` table into every new app's `app.toml`: the library's default for the name spelled out (`<PACKAGE_UPPER>_PORT`, `_HOST`, `_DATA_DIR` over a copy of `data/.apps/<name>`), so an edit to the runner's env names has the table to keep in step beside it.

`update-app` boots any app's preview from its manifest: `preview_app.py up --app <name> --worktree <dir> [--with <sibling>]... [--instance-key <key>]` reads the worktree's `app.toml`, resolves its `[preview]` table, boots the siblings first, writes the shell's registry copy with each sibling's row pointing at its preview, and surfaces the app as the labeled `<name>-preview` tab; `refresh` re-boots the inner process in place after a rebuild and `down` tears the preview and its siblings down. One preview per app at a time: a different worktree's live preview is refused rather than hijacked. The skill's isolated-instance section points at it for any app with a manifest and keeps the raw `serve_isolated_instance.py` invocation for manifest-less services.

`serve_isolated_instance.py` carries the old live-editing branch's work forward and gains what the preview table needs. Carried: `refresh --name` re-boots the inner server on its existing port after waiting for the old process to release it, recording the new pid before the health wait; `down` escalates SIGTERM to SIGKILL and removes the state directory only once every recorded process group is gone, keeping the state and exiting non-zero for a survivor (`up` refuses to boot over a stale instance it could not clear); a failed boot quotes the log since the last boot marker and the health probe's response body, and copies the log to `data/.state/isolated-instances/<name>-failed.log`; both the inner server and the wrapper launch through `oom_tag_service.py user`. New: `--port-env NAME=ENVVAR` and `--port NAME` for named free ports, `--copy KEY=SOURCE` for a directory copied into the instance's scratch space, `{port:...}`, `{copy:...}`, `{scratch}`, and `{host}` filled in the launch argv and `--env` values, and `--inner-path` for the page the preview frame opens (`preview_wrapper_server.py --inner-path`). The state file records ports, copies, and the inner path, so `refresh` and `down` need nothing but the name.
