Added the `notify-user` skill for chat agents: at the end of every turn in which it actually did work, a chat posts a one-sentence summary into the Mind app's notification feed (bell, badge, toast card, and a system banner when the user is looking elsewhere). Clicking the notification lands the user in that chat. "Did work" is the line `AGENTS.md` already draws for step records, so chitchat, clarifying questions and single quick reads stay silent; a Stop hook reminds an agent that forgot, and the agent can still decline. The skill is for chats only, not launch-task workers, whose results reach the user through their parent chat.

Its script posts to the app's existing per-agent notifications route through the latchkey gateway's minds API proxy, addressing it with `MNGR_AGENT_ID` rather than `MINDS_CHAT_ID` -- Latchkey authorizes the runtime agent, and the app derives the stable conversation destination from that agent's `chat_id` label, so the notification is not refused when the conversation and runtime agent ids differ. It exits non-zero with the reason on stderr when the app cannot be reached, so the agent can say in its reply that the notification did not go out.
