Added the `notify-user` skill for chat agents: at the end of every turn in which it did work, a chat posts a one-sentence summary into the Mind app's notification feed (bell, badge, toast card, and a system banner when the user is looking elsewhere). Clicking the notification lands the user in that chat. A Stop hook asks for one at the end of every turn; it is a suggestion, and a turn that does not warrant a notification declines by replying with nothing at all. The skill is for chats only, not launch-task workers, whose results reach the user through their parent chat.

Its script posts to the app's existing per-agent notifications route through the latchkey gateway's minds API proxy, addressing it with `MNGR_AGENT_ID` rather than `MINDS_CHAT_ID` -- Latchkey authorizes the runtime agent, and the app derives the stable conversation destination from that agent's `chat_id` label, so the notification is not refused when the conversation and runtime agent ids differ. It exits non-zero with the reason on stderr when the app cannot be reached, so the agent can say in its reply that the notification did not go out.
