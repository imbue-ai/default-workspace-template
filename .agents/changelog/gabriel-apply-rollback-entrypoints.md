A rolled-back update apply no longer leaves behind what the forward apply added outside its snapshots, which left the workspace unable to take any later update. The restore of a tool environment now puts its bin-directory entrypoints back to the restored receipt's set: it removes a link the apply added (a dangling `terminal-pty`, over which every later `uv tool install --reinstall` refused with "Executable already exists") and relinks one the failed reinstall had removed. A reinstall also clears a link into its own tool that the receipt does not list, so a workspace an earlier rollback already left in that state recovers on its next apply. Recovery no longer demands a bundle the restored tree has no frontend for (getting_started's, on a tree from before that app), which had turned a clean rollback into an emergency. The rollback also removes the fetched `system/vendor/mngr-assets` from a restored tree that has no fetch script, where it was an untracked directory that refused the next apply. The user-requested rollback of a kept rollback point gets the same cleanup.
