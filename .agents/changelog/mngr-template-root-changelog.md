update-self's "what's new" reads the release sections of the root `CHANGELOG.md`. `changelog-entries` lists the target's `## [minds-v<version>]` sections the workspace's base does not have (and `[Unreleased]` when it holds something) beside the changelog entry files the update adds. Once the template names the last release that kept its entries as files, a base with no release section also gets, under `added_before_consolidation`, the entries of the releases it skipped, read at that release. `--out` writes the sections and then each entry's text to one file, which the worker digests (Step 5 of the worker guide).

An entry is a `changelog/<file>.md` other than `README.md`, listed with `--no-renames`, so an entry is not dropped for resembling one the update deletes. A changelog or entry that cannot be read, a `CHANGELOG.md` heading that is not a `## [<label>]` one, and a repeated label are named under `unlisted`, and the command still exits 0.

The worker's merge triage takes the target's side for the two root changelogs (saving a workspace's own copy to another path first) and for an entry file the target deletes. Converting a user package to a standalone project leaves the root changelogs as written.
