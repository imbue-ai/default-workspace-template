The `submit-upstream-changes` mngr-changes reference now names the real recipe (`just dwt-mngr-pin`, not the nonexistent `just pin-template-mngr`) and describes how a developer with both checkouts iterates on a paired change: pin a template branch to an unmerged mngr commit on the private mngr-internal repo (`just dwt-mngr-pin-internal`), then move the pin to a public export of that branch before merging (`just dwt-mngr-pin-export`). Neither is something an agent in a workspace does.
