The update-self apply now removes a stale second install of the mngr tool that shadows the one it refreshes. Before, a workspace that had applied an update with pre-minds-v0.4.3 scripts could carry a copy under `/home/user/.local` alongside the image's copy under `/root/.local`; every later apply refreshed only the `/root` copy (the one on the worker's PATH) while login shells, including the terminal app and the desktop app's `mngr exec`, resolved the stale one first. The first release that added a dependency to mngr then broke every command those shells ran, with the update still reporting success. Now each apply deletes any mngr tool environment and console script under `$HOME/.local` or `/root/.local` that is not the installation behind `mngr` on its own PATH.
