update-self's apply now refuses to land an update (`--target-ref`) without `--ff-only`. Landing with an ordinary merge puts the worker's `update-self: merge upstream template (<ref>)` commit on a second parent, which the version read and `resolve_template_base.py` never look at because they follow only the first-parent line. After such a landing, the Mind app kept reporting the previous version and offering the same update again. An update that also asks for `--keep-rollback-point` is now refused with a message that says to drop `--keep-rollback-point`, not `--ff-only`. The old message led one update run to drop `--ff-only` and land with an ordinary merge.
