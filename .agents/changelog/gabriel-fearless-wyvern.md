Fixes for issues surfaced by migrating a real pre-declutter workspace.

`migrate-workspace`'s `detect-layout` now resolves its roots through any symlink before returning them. On a pre-declutter source `/mngr` is a symlink, and `find` will not descend a symlinked start path -- so the session scan matched nothing and exited 0, reporting a workspace full of agents as having none. `list-agents` resolves its own `--host-dir` too, so it is correct when run on its own, and an empty scan now says so explicitly rather than passing for "this source has no agents."

`migrate-workspace` reads `host-backup-now`'s exit code instead of matching its printed text, so a tick that prints nothing is no longer mistaken for a successful backup. It also distinguishes the two sides: the destination is the side the migration writes to, so a missing restore point there now stops and asks, where previously only the source was checked.

Every command `migrate-workspace` sends to the source over SSH now goes through `with_agent_env.sh` -- the backup, and the optional `mngr stop` that quiesces the source's agents. sshd builds a fresh environment per session, so a bare `ssh <host> 'uv run host-backup-now'` had neither `MNGR_AGENT_STATE_DIR` nor `MNGR_HOST_DIR`, could not locate the events log to wait on, and exited 2 immediately having printed nothing -- which reads exactly like a broken source; a bare `mngr stop` likewise has neither `mngr` on its PATH nor a host dir to act on. The wrapper rebuilds the agent environment and execs from the repo root.

Those commands run on the *source*, so they probe a candidate list rather than naming one path: the wrapper has lived at the repo root's `scripts/`, then `system/scripts/`, then `system/libs/automations/`, then `system/scripts/` again, and a source carries whichever its generation shipped. Exit 127 means the source predates the wrapper entirely, and the skill falls back to the explicit events-log paths; that reference's own example of reading the log was written as `$MNGR_HOST_DIR/...`, which expands to nothing over SSH, and now spells the path out.

Hardening workers are now told that their worktree isolates code but not data. `data/` is gitignored, so a worker starts with an empty one while the user's records stay in the live tree -- and a test whose result depends on ambient on-disk state passes trivially against an empty store without ever running the code path it covers. This had already produced a green hand-off from a worker whose suite failed the moment it ran against the real data. The worker references now point at the isolation contract and tooling that `update-app` already owns, require that a service's tests resolve their data path injectably rather than reading whatever is on disk, and tell `migrate-workspace`'s worker to mirror the migrated data into its worktree and exercise each app against it.
