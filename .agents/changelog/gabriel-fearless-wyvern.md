Fixes for issues surfaced by migrating a real pre-declutter workspace.

`migrate-workspace`'s `detect-layout` now resolves its roots through any symlink before returning them. On a pre-declutter source `/mngr` is a symlink, and `find` will not descend a symlinked start path -- so the session scan matched nothing and exited 0, and every agent came back with no transcript to adopt (the `ls` that enumerates the agents follows the symlink fine; only the transcript scan is rooted at it). `list-agents` resolves its own `--host-dir` too, so it is correct when run on its own, and an empty scan now says so explicitly rather than passing for "this source has no agents."

`migrate-workspace` reads `host-backup-now`'s exit code instead of matching its printed text, so a tick that prints nothing is no longer mistaken for a successful backup. It also distinguishes the two sides: the destination is the side the migration writes to, so a missing restore point there now stops and asks, where previously only the source was checked.

Every command `migrate-workspace` sends to the source over SSH now goes through `with_agent_env.sh` -- the backup, and the optional `mngr stop` that quiesces the source's agents. sshd builds a fresh environment per session, so a bare `ssh <host> 'uv run host-backup-now'` had neither `MNGR_AGENT_STATE_DIR` nor `MNGR_HOST_DIR`, could not locate the events log to wait on, and exited 2 at once -- saying so on stderr and leaving stdout empty, so there was no printed outcome to read; a bare `mngr stop` likewise has neither `mngr` on its PATH nor a host dir to act on. The wrapper rebuilds the agent environment and execs from the repo root.

Those commands run on the *source*, so they probe a candidate list rather than naming one path: the wrapper shipped at `system/scripts/`, moved to `system/libs/automations/` two days later, and has now moved back, so a source carries whichever its generation shipped. A pre-declutter source has none at all -- the wrapper postdates the declutter by a release -- so the probe says so with its own exit code (66, rather than 127, which the wrapped command can return on its own) and the skill falls back to the explicit events-log paths. That reference's own example of reading the log was written as `$MNGR_HOST_DIR/...`, which expands to nothing over SSH, and now spells the path out; it also no longer reads an immediate exit 2 from `host-backup-now` as evidence of an old backup service, since without the agent environment every pre-declutter source fails that way whatever it runs.

The data-isolation contract now has its own shared reference at `.agents/shared/references/data-isolation.md`, instead of living inside the `update-app` skill and being pointed at from the worker references. It covers protecting the user's live store while verifying a change, and the `DATA_DIR` override that makes a creation pointable somewhere else in the first place; `update-app` keeps only the invocation for surfacing a throwaway instance to the user as a preview tab. It also states the half the worker references needed: a worktree isolates code, not data, so a check that reads `data/` passes vacuously against the empty one a fresh worktree starts with. Before believing a green run, check whether anything under test reads `data/`, and give it real data if so -- `migrate-workspace`'s worker is told to mirror the migrated data into its worktree and exercise each app against it.
