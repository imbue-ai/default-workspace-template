Three build-app scaffolder tests no longer fail when run inside a live workspace. They asserted which port the scaffolder would pick automatically, but it skips any port something on the machine is already listening on, and a live workspace has apps across that range, so it picked 8091 instead of the 8081 or 8082 the tests expected. The scaffolder now takes that listening-port check as an argument, and the tests pass one that reports nothing listening. The two tests that a requested port held by another app is refused now use the same check, so they can no longer pass just because the machine happened to be listening on that port. A new test runs the real scaffolder and confirms the port it picks is the one written into both the app's program file and its runner.
