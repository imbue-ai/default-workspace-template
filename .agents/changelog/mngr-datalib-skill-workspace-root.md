The `datalib` skill, its install script and the Datalib app's launcher name the workspace's home, `/home/user`, instead of following `$HOME`. An agent's shell has `HOME=/root`, so a config written at `$HOME/workspace/data/.skills/datalib/Default` landed where the Datalib app does not read (the sync request was refused with 409, no config), and the install script run from that shell installed a second copy of the binaries under `/root/.local`. The skill's preamble now spells `/home/user/workspace` and `/home/user/.local/bin`, the install script installs under the workspace's parent directory wherever it is run from, and the launcher looks for `datalib-http` under the same directory rather than under the home of whatever started it.
