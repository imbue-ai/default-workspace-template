An update no longer tries to pause the main chat. The chat app starts the main chat again as soon as it stops, so pausing it never held: the update recorded it as paused while it was already back, and a run freeing memory could keep stopping it without gaining anything. Pausing the busy chats before applying the update now leaves the main chat running, `run-status stop-chats --agent` refuses to pause it by name and says why, and the update and memory guides say it cannot be stopped.
