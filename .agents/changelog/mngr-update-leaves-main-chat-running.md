An update no longer treats the main chat as something it can pause or stop for memory. The chat app starts the main chat again as soon as it stops, so pausing it never held: the update recorded it as paused while it was already back, and a run freeing memory could keep stopping it without gaining anything. `run-status stop-chats --agent` now refuses the main chat and says why. Before the apply, a busy main chat is still stopped, which interrupts its work, but it is recorded as interrupted: the resume sends it the note without trying to start it. The update and memory guides say the main chat cannot be stopped for memory.
