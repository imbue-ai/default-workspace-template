New `manage-projects` skill, documenting the project/view layer for agents: what a project is (a filter over the machine's objects plus its own saved arrangement, not a container), the member-ref grammar (`chat:<agent-id>`, `terminal:<tmux-session-name>`, `service:<name>`, `service:browser?session=<id>`, with `url:<hash>` now legacy-only since ad-hoc pages are no longer filed as members), how to query membership and per-view open state with `layout.py views` / `list --view` / `inspect --view`, and that `layout.py` has no explicit add-member/remove-member/create/delete-project verb -- filing happens only as a side effect of `open`/`split`.

It also documents the ref-resolution trap verified against `layout.py`'s parser: a bare word only ever expands to `service:<word>`, so a renamed app's chosen display title is never an addressable name -- and the corresponding rule that renaming stays chat-only in the UI (a chat's ref is a stable agent id `mngr rename` moves everywhere, where a terminal/browser/app's registered identity can never change), while `layout.py rename` can still set a display-only title on any kind.
