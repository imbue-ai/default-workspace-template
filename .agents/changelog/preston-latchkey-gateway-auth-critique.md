Restore the `X-Latchkey-Gateway-Permissions-Override` header on every git command the skills run through the latchkey gateway (`latchkey`, `publish-inspiration`, `use-inspiration`, `update-published-inspiration`, `update-installed-inspiration`), guarded with `${LATCHKEY_GATEWAY_PERMISSIONS_OVERRIDE:+...}` so it is sent only when the env var exists. The `latchkey` skill's "Git operations on GitHub" section is now the canonical form of the command; the other skills mirror it.

Timeline: the skills sent both headers from the start (5cf163f5, 2026-07-07). Commit 58e2f55c (2026-07-31, "Drop LATCHKEY_GATEWAY_PERMISSIONS_OVERRIDE (gone with the secondary gateway)") removed the header everywhere while retiring the remote-VPS secondary-gateway fallback -- but the override serves a second, unrelated purpose on desktop-hosted gateways (Docker/Lima/Modal workspaces): it is the per-agent authorization JWT, and the gateway evaluates requests without it against a deny-all default. That broke every gateway git push/fetch in desktop workspaces with a 403 despite approved grants. The `${VAR:+...}` guard keeps the command working on VPS gateways, which omit the env var.

Also fix `publish-inspiration` §7's permission probe: approved grants are stored under account-scoped keys (`github-git:<account>`), never bare `github-git`, so the probe's exact-key match could never see a real grant and reported "NOT permitted" forever. It now matches the `^github-git(:|$)` scope prefix.
