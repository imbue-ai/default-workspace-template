update-self now works out which earlier updates' rollbacks still need undoing with a new `update_self.py pending-rollbacks` command, which the worker runs before it merges, and the apply refuses a merge that leaves one in place by the same rule. Before, the worker guide reverted the newest rollback it found. That could be an earlier release's rollback that its own retry had already undone, and the worker then stopped on an empty revert. Now each rollback nothing has undone is reverted, newest first, whether the pass retries that release or moves to a newer one. A user's rollback of an app change is left alone. Before, the apply caught a skipped revert only on a retry of the same release; now it catches it on any pass.

The build-app scaffolder's port picker now takes the "is this port in use on this machine" check as an argument, and its tests pass a stand-in, so they no longer fail in a workspace whose own apps already listen on the low 8080s.
