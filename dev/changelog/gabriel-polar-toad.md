`.mngr/settings.toml` no longer defaults `commands.create.type` to `claude`: the type an unqualified `mngr create` resolves to, and the provider account it runs on, come from the git-ignored `.mngr/settings.local.toml` the chat app writes from its account store, so a create with no account signed in fails instead of launching a claude that cannot take a turn. A new `[pre_command_scripts] create` entry runs `system/scripts/require_create_account.py`, which refuses such a create with "No provider account is signed in on this machine. Sign in from a chat tab, then try again." in place of mngr's "No agent type provided" and its config-set hint; it gates itself to creates run inside the workspace, so the create of the workspace itself from a checkout of this template is never refused. `[work_dir_extra_paths]` shares the local file into worker worktrees by symlink, so a create run from inside one resolves the same account. `system/scripts/default_account_args.py` is removed.

`system/vendor/mngr` is refreshed to the mngr branch of the same name, whose one change over the minds-v0.5.2 vendor is that a `[commands.<name>]` table in a higher-precedence settings layer adds to the parameters lower layers set instead of replacing them, which the local file depends on.
